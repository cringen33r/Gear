## 1. Как работают область видимости, hoisting и TDZ в JavaScript? Объясните различия между var, let и const на примерах

**Область видимости**
- Участок кода, где идентификатор доступен
- **Лексическая**: определяется местом объявления, а не местом вызова
- Виды: глобальная, функциональная, блочная (`{}`), модульная
- Scope chain: поиск от текущей области к внешним, не нашёл → `ReferenceError`

**Hoisting**
- Не перемещение кода: перед выполнением создаётся лексическое окружение, в нём регистрируются все объявления области

| Объявление | Поднимается | Инициализируется | Доступ до объявления |
|---|---|---|---|
| `var x` | да | `undefined` | `undefined` |
| `let`/`const`/`class` | да | нет | **ReferenceError (TDZ)** |
| `function f(){}` | да | телом функции | работает |
| `var f = function(){}` | как var | `undefined` | `TypeError: f is not a function` |

**TDZ**
- Промежуток от начала блока до строки инициализации `let`/`const`/`class`
- Переменная существует, но обращение бросает `ReferenceError` — даже `typeof`
- Зачем: превращает «использовал до объявления» из молчаливого `undefined` в явную ошибку; для `const` обязательно, значение присваивается при объявлении

```js
console.log(v); var v = 1;   // undefined
console.log(l); let l = 1;   // ReferenceError
```

**var / let / const**

| | var | let | const |
|---|---|---|---|
| Область | функциональная | блочная | блочная |
| Повторное объявление | молча можно | SyntaxError | SyntaxError |
| Переприсваивание | да | да | нет |
| Свойство `globalThis` | создаёт | нет | нет |
| TDZ | нет | да | да |

- `const` запрещает переприсваивание **связывания**, а не мутацию значения: `obj.a = 2` можно, `obj = {}` нельзя

**Цикл с таймаутом**
```js
for (var i = 0; i < 3; i++) setTimeout(() => console.log(i)); // 3,3,3
for (let i = 0; i < 3; i++) setTimeout(() => console.log(i)); // 0,1,2
```
- `let` создаёт **новое связывание на каждой итерации**; до ES2015 это чинили IIFE

**Рекомендации**
- По умолчанию `const`, `let` при необходимости, `var` не использовать
- Строгий режим (в модулях включён автоматически) запрещает неявные глобальные

**Подробнее:** [[Область видимости в JavaScript]], [[Hoisting и TDZ]], [[var, let и const]], [[Declaration statements]]

## 2. Что такое замыкание в JavaScript? Как оно возникает и как предотвратить утечки памяти, связанные с замыканиями?

**Определение**
- Функция вместе с лексическим окружением, в котором создана
- Имеет доступ к переменным внешней области после её завершения

**Как возникает**
- Автоматически при создании **каждой** функции: функция получает ссылку на окружение определения
- Пока жива функция — жива цепочка окружений → переменные не собираются GC
- Захватываются **переменные, а не значения**: функции одной области разделяют одно связывание

**Применение**
- Приватное состояние (модульный паттерн)
- Фабрики функций, каррирование
- Мемоизация
- Debounce/throttle — состояние таймера в замыкании
- React-хуки: колбэк захватывает значения конкретного рендера → проблема stale closure, решается зависимостями или `setState(prev => ...)`

**Механизм утечки**
- GC работает по достижимости; замыкание удерживает **всё окружение**, поэтому живая функция держит ненужные объекты

**Сценарии утечек**
1. Не снятый слушатель события → замыкание держит DOM-узел → detached DOM node
2. Незакрытые `setInterval` / `setTimeout`
3. Растущий без ограничений кеш мемоизации
4. Глобальные списки подписчиков, из которых не удаляют
5. Замыкание захватывает больше нужного — большой объект объявлен рядом в той же области

**Профилактика**
- Снимать слушатели, таймеры, подписки, observers; в React — cleanup в `useEffect`
- `AbortController`: `{ signal }` в `addEventListener`, один `abort()` снимает всё; он же отменяет `fetch`
- `WeakMap`/`WeakSet` для метаданных, привязанных к объектам
- Ограничивать кеши: LRU + TTL
- Обнулять ссылки на большие объекты
- Минимизировать область видимости

**Диагностика**
- DevTools → Memory: два heap snapshot, Comparison, искать растущие объекты и `Detached HTMLElement`
- Performance с Memory: пилообразный график, растущая нижняя граница после GC = утечка
- `performance.measureUserAgentSpecificMemory()`

**Подробнее:** [[Замыкания]], [[Утечки памяти в JavaScript]]

## 3. Как в JavaScript работают Promise и цепочки .then()? Чем лучше вложенных колбэков и как обрабатывать ошибки?

**Promise**
- Объект-результат асинхронной операции; состояния pending → fulfilled / rejected
- Переход происходит **один раз** и необратим; повторный `resolve` игнорируется

**Цепочки**
- `.then()` возвращает **новый промис**, отсюда цепочка
- Правила: вернул значение → промис выполняется им; вернул промис → цепочка **ждёт** его; бросил → отклоняется; обработчика нет → значение/ошибка проходят дальше

**Чем лучше вложенных колбэков**
1. Плоская структура вместо пирамиды
2. **Единая обработка ошибок** — один `.catch()` вместо `if (err)` в каждом колбэке
3. Композируемость: промис — значение, его можно передать, сохранить, вернуть
4. Гарантия контракта: колбэк вызывается ровно один раз и **всегда асинхронно** (самописные колбэк-API этого не гарантируют)
5. Комбинаторы вместо ручных счётчиков

**Комбинаторы**
- `Promise.all` — все, при первой ошибке общий reject
- `Promise.allSettled` — статусы всех, ошибки не прерывают
- `Promise.race` — первый завершившийся (таймаут)
- `Promise.any` — первый успешный, иначе `AggregateError`

**Обработка ошибок**
1. Всегда завершать цепочку `.catch()`: иначе `unhandledrejection`, в Node — завершение процесса
2. `.catch()` ловит только **предшествующие** звенья: `p.then(a).catch(h).then(b)` не поймает ошибку из `b`
3. `.then(ok, err)` ≠ `.then(ok).catch(err)`: второй аргумент не ловит ошибку из `ok`
4. `.catch()`, вернувший значение, **гасит** ошибку — способ подставить дефолт; проброс через `throw`
5. Не глушить пустым `.catch(() => {})`
6. `fetch` отклоняется только при **сетевой** ошибке — проверка `res.ok` обязательна
7. Бросать `Error`, не строки; оборачивать через `new Error(msg, { cause })`

**Типичные ошибки**
- Забытый `return` в `.then` → цепочка не дождётся вложенного промиса
- Promise constructor antipattern: `new Promise((res, rej) => fetchData().then(res).catch(rej))`
- Последовательные `await` там, где нужен `Promise.all`
- Ожидание синхронного выполнения: `Promise.resolve().then(fn)` всегда микрозадача

**Подробнее:** [[Promise и цепочки then]], [[Обработка ошибок в промисах]]

## 4. Как связаны Promise и async/await? Что происходит при await и как распространяются ошибки в асинхронных функциях?

**Связь**
- `async/await` — синтаксический сахар над промисами
- `async`-функция **всегда возвращает промис**: значение → `Promise.resolve`, исключение → `Promise.reject`
- `await` разворачивает промис: возвращает значение или бросает ошибку

**Что происходит при await**
1. Выражение справа вычисляется; не промис → оборачивается в `Promise.resolve`
2. Функция приостанавливается, состояние сохраняется, фрейм **снимается со стека** — поток не блокируется
3. Продолжение регистрируется как **микрозадача**
4. При разрешении промиса продолжение попадает в очередь микрозадач
5. При отклонении `await` **бросает** в точке остановки
- Под капотом — генератор, прокручиваемый рантаймом
- Код **до первого `await`** выполняется синхронно

**Преимущества над .then()**
- Читаемость: асинхронный код как синхронный
- Работают `try/catch/finally`, `if`, циклы, `return`
- Отладка: точки останова, информативный стек
- Промежуточные значения в одной области, не надо протаскивать

**Ошибки**
- Основной механизм — `try/catch`, `finally` выполняется всегда
- Ошибка внутри async-функции → **отклонённый промис**, вызывающий обязан обработать
- `return fetchData()` в `try` **не поймается** — нужно `return await fetchData()`
- Fire-and-forget без `await` и `.catch()` → unhandled rejection
- Ошибка в колбэке `setTimeout` не ловится внешним try/catch — другой тик
- `forEach(async ...)` ничего не ждёт и теряет ошибки → `for...of` + `await` или `Promise.all(map)`

**Последовательность и параллельность**
```js
const a = await taskA(); const b = await taskB();          // 2 сек
const [a, b] = await Promise.all([taskA(), taskB()]);      // 1 сек
```
- Промисы стартуют **в момент создания**, а не в момент `await`
- Последовательность нужна только при зависимости следующего шага от предыдущего
- Не прерывать остальные при ошибке — `allSettled`

**Отмена**
- Промисы неотменяемы; прерывание через `AbortController` / `AbortSignal.timeout(ms)`; ловить `AbortError`

**Дополнительно**
- Top-level await в ES-модулях откладывает выполнение импортёров
- `for await ... of` для асинхронных генераторов и потоков

**Подробнее:** [[async и await]], [[Event loop, задачи и микрозадачи]]

## 5. Что такое деструктуризация в JavaScript? Как работают массивы, объекты, значения по умолчанию и переименование?

**Определение**
- Синтаксис ES2015: распаковка значений массива и свойств объекта в переменные по совпадению структуры

**Массивы — по позиции**
- Работает с любым итерируемым: массив, строка, Set, Map, генератор
```js
const [a, b] = [1, 2];
const [, , third] = [1, 2, 3];       // пропуск позиций
const [head, ...tail] = [1, 2, 3];   // rest — только последним
[m, n] = [n, m];                      // обмен без временной переменной
const [p, [q, r]] = [1, [2, 3]];      // вложенность
```

**Объекты — по имени**
```js
const { name, id } = user;              // порядок не важен
const { name: userName } = user;        // переименование
const { role = 'user' } = user;         // значение по умолчанию
const { address: { city } } = user;     // вложенность
const { id, ...rest } = user;           // rest-свойства
const { [key]: value } = user;          // вычисляемое имя
({ title } = obj);                      // без объявления — нужны скобки
```

**Значения по умолчанию**
- Срабатывают **только при `undefined`**; `null`, `0`, `''`, `false` дефолт не активируют
- Вычисляются лениво и могут ссылаться на ранее объявленные: `{ width, height = width * 2 }`

**Параметры функции**
```js
function createUser({ name, age = 18 } = {}) {}
```
- Без `= {}` вызов без аргументов → `TypeError: Cannot destructure property of undefined`
- Применение: пропсы React, `req.params`/`req.query`, колбэки

**Подводные камни**
- Деструктуризация `null`/`undefined` бросает; пустого объекта — нет → `obj ?? {}`
- Копирование **поверхностное**: вложенный объект остаётся общим
- Вложенная деструктуризация не создаёт промежуточную переменную (`address` не существует)
- Rest в объекте — идиома «выбросить поле»: `const { password, ...safe } = user`

**Связь со spread**
- Деструктуризация разбирает, spread собирает: `{ ...defaults, ...options }`, `[...arr]`, `{ ...user, id: 42 }`, `fn(...args)`
- Оба поверхностные; глубокая копия — `structuredClone`

**Подробнее:** [[Деструктуризация]], [[Поверхностное и глубокое копирование]]

## 6. Чем отличаются callback в методах массивов от функций, передаваемых в setTimeout? Различия по времени выполнения и аргументам

**Время выполнения**
- Методы массива (`forEach`, `map`, `filter`, `reduce`, `sort`) — **синхронно**, в том же тике; к возврату метода работа завершена
- `setTimeout` — колбэк уходит в **очередь макрозадач**, выполнится после опустошения стека и микрозадач

**Аргументы**
- Методы массива: `(element, index, array)`; у `reduce` — `(acc, element, index, array)`
- `setTimeout`: **без аргументов**; дополнительные параметры после задержки передаются в колбэк
- Ловушка на сигнатурах: `['1','7','11'].map(parseInt)` → `[1, NaN, 3]`, потому что индекс попадает в `radix`

**Возвращаемое значение**
- Методы массива используют: `map` собирает, `filter` — булево, `reduce` — аккумулятор, `sort` — сравнение; `forEach` игнорирует
- `setTimeout` возврат игнорирует; сам возвращает id таймера

**Обработка ошибок**
- Метод массива: ошибка идёт вверх по стеку, ловится внешним `try/catch`
- `setTimeout`: ошибка в другом тике, внешний `try/catch` **не поймает**

**Контекст `this`**
- Методы массива принимают второй аргумент `thisArg`
- У `setTimeout` его нет: `this` — глобальный объект или `undefined` в модулях; стрелочные берут лексически

**Прерывание**
- Из `forEach` выйти досрочно нельзя: `break` — SyntaxError, `return` завершает итерацию → `for...of`, `some`, `every`, `find`
- Таймер отменяется `clearTimeout`

**Асинхронные колбэки в методах массива**
- `forEach(async ...)` не ждёт и теряет ошибки
- Последовательно — `for (const x of arr) await f(x)`
- Параллельно — `await Promise.all(arr.map(f))`

**Сводка**

| | Метод массива | setTimeout |
|---|---|---|
| Момент | синхронно | макрозадача |
| Аргументы | element, index, array | нет |
| Возврат | используется | игнорируется |
| Внешний try/catch | ловит | **не ловит** |
| `this` | `thisArg` | window / undefined |
| Досрочный выход | нет | `clearTimeout` |
| Блокирует поток | да | нет |

**Подробнее:** [[Колбэки — синхронные и асинхронные]]

## 7. Чем поверхностное копирование объекта отличается от глубокого? Какие способы есть и почему это важно для вложенных структур?

**Ссылочная семантика**
- Примитивы копируются по значению, объекты/массивы/функции — по ссылке
- `b = a` — одна и та же сущность

**Поверхностное копирование**
- Новый объект верхнего уровня; вложенные объекты копируются **как ссылки** и остаются общими
- Способы: `{ ...obj }`, `Object.assign({}, obj)`, `arr.slice()`, `Array.from(arr)`
- Копируют только собственные перечислимые свойства, **вызывают геттеры**, теряют прототип и дескрипторы
- Точная копия: `Object.create(Object.getPrototypeOf(o), Object.getOwnPropertyDescriptors(o))`

**Глубокое копирование**
- **`structuredClone(obj)`** — стандарт: вложенность, `Date`, `RegExp`, `Map`, `Set`, типизированные массивы, `Blob`, **циклические ссылки**
  - Не поддерживает: функции (`DataCloneError`), DOM-узлы, прототипы классов, дескрипторы, геттеры
- `JSON.parse(JSON.stringify(obj))` — ломает: `Date` → строка, `undefined`/функции/символы исчезают, `Infinity`/`NaN` → `null`, `Map`/`Set` → `{}`, `BigInt` → TypeError, циклы → исключение
- Библиотеки: `lodash.cloneDeep`, `rfdc`, `immer`
- Ручная рекурсия с `WeakMap` для защиты от циклов

**Почему важно для вложенных структур**
1. Неожиданные мутации данных вызывающего кода — причина и симптом в разных модулях
2. **React сравнивает по ссылке**: мутация вложенного объекта не меняет ссылку → нет ререндера; копировать нужно **путь до изменяемого узла** (structural sharing, Immer)
3. Общее изменяемое состояние: конфиги и значения по умолчанию
4. Кеши и снимки должны быть независимыми копиями
5. Undo/redo, сравнение «до и после», отправка на сервер

**Когда достаточно поверхностной**
- Плоский объект; вложенные по договорённости неизменяемы; глубокое копирование слишком дорого

**Альтернатива**
- Иммутабельность: `Object.freeze` (поверхностно), `readonly` в TS, Immer; даёт дешёвое сравнение по ссылке

**Подробнее:** [[Поверхностное и глубокое копирование]]

## 8. Как в Python работают аргументы функций по умолчанию? Почему изменяемые значения (список, словарь) приводят к ошибкам?

**Механика**
- Дефолты вычисляются **один раз, в момент определения функции**, хранятся в `__defaults__` и переиспользуются всеми вызовами

```python
def f(x=[]):
    x.append(1)
    return x
f()  # [1]
f()  # [1, 1]   ← тот же объект
```
- То же с `def log(msg, ts=datetime.now())` — время фиксируется при импорте модуля

**Почему так**
- `def` — обычная инструкция, выполняется один раз при загрузке модуля; выражения в сигнатуре вычисляются тогда же
- Побочная польза: `lambda i=i: i` захватывает переменную цикла по значению

**Опасные и безопасные типы**
- Опасны изменяемые: `list`, `dict`, `set`, `bytearray`, экземпляры классов
- Безопасны неизменяемые: `int`, `float`, `str`, `bool`, `None`, `tuple`, `frozenset`

**Правильное решение**
```python
def f(x=None):
    if x is None:
        x = []
```
- Если `None` — допустимое значение: сентинел `_MISSING = object()`

**Последствия**
```python
class Node:
    def __init__(self, name, children=[]):  # БАГ: список общий для всех экземпляров
```
- Проявляется не сразу, зависит от порядка вызовов, не ловится изолированными тестами

**Смежные грабли**
- Изменяемый **атрибут класса** вместо атрибута экземпляра
- `dict.fromkeys(keys, [])` — все ключи на один список
- Dataclass требует `field(default_factory=list)`; `= []` даёт `ValueError` при определении класса

**Порядок параметров**
- Параметры с дефолтом — после параметров без дефолта, иначе `SyntaxError`
- До `/` — только позиционные, после `*` — keyword-only

**Модель передачи аргументов**
- Call by object reference: `lst.append(1)` видно снаружи, `lst = [9]` — нет

**Инструменты**
- pylint W0102 dangerous-default-value, ruff / flake8-bugbear B006

## 9. Что такое генератор в Python? Чем отличается от списка, какие преимущества даёт ленивое вычисление и какие ограничения?

**Определение**
- Функция с `yield`, при вызове возвращает итератор
- Значения производятся по одному, по требованию; между вызовами функция «заморожена» с сохранением состояния
- При вызове тело **ещё не выполняется** — первый шаг на первом `next()`
- Генераторное выражение: `(x * x for x in range(n))`

**Отличия от списка**

| | Список | Генератор |
|---|---|---|
| Вычисление | сразу | **лениво** |
| Память | все элементы | текущее состояние |
| `len`, индексы, срезы | да | нет |
| Повторный проход | да | **одноразовый** |
| Бесконечность | нет | **да** |

- 10⁶ квадратов: список ~8.4 МБ, генератор ~200 байт

**Преимущества ленивости**
1. Постоянная память при любом объёме — файл на 50 ГБ построчно
2. Бесконечные последовательности + `itertools.islice`
3. Ранний выход без лишних вычислений
4. **Конвейеры**: чтение → парсинг → фильтр → нормализация без промежуточных списков
5. Меньше задержка до первого результата — стриминг

**Ограничения**
- Одноразовость: повторный `list()` вернёт пустой
- Нет `len`, индексации, срезов (только `islice` последовательным проходом)
- Отложенные ошибки — исключение во время итерации, не при создании
- Внешние переменные разрешаются во время итерации
- Накладные расходы на элемент — для малых коллекций с многократным обходом список быстрее
- Не сериализуются (pickle); `sorted` всё равно развернёт полностью
- `finally`/`with` внутри неисчерпанного генератора отработают только при `close()` или сборке мусора

**Продвинутое**
- `yield from` — делегирование
- `send()` — двусторонняя связь (сопрограмма), `throw()`, `close()`
- `return value` → в `StopIteration.value`
- Асинхронные генераторы `async def ... yield` + `async for`
- `itertools`: `count`, `cycle`, `chain`, `islice`, `takewhile`, `groupby`, `accumulate`, `tee`, `batched`

**Когда что**
- Генератор: большие/неизвестного размера данные, поток, один проход, конвейер, бесконечность
- Список: нужны длина, индексация, срезы, сортировка, многократный обход, малый объём
- Правило: возвращать генератор — вызывающий всегда может обернуть в `list()`

**Подробнее:** [[Генераторы в Python]]

## 10. Как в Python правильно создавать двумерные списки? Почему [[0] * n] * m ведёт себя неожиданно? Как ссылочная семантика влияет на это?

**Проблема**
```python
grid = [[0] * 3] * 2
grid[0][0] = 5
print(grid)  # [[5, 0, 0], [5, 0, 0]]  — изменились обе строки
```

**Причина**
- `*` для списка **повторяет ссылки, а не копирует элементы**
- `[0] * 3` — нормальный список (int неизменяем)
- Внешнее `* 2` — две ссылки на **один и тот же** внутренний список
- Проверка: `grid[0] is grid[1]` → `True`
- То же в цикле, если `append` одну и ту же переменную `row`

**Почему `[0] * 3` работает правильно**
- `int` неизменяем: `grid[0][0] = 5` не мутирует ноль, а заменяет элемент по индексу
- Проблема возникает только когда повторяемый элемент изменяем: `[{}] * 3` даёт то же самое

**Правильные способы**
```python
grid = [[0] * cols for _ in range(rows)]        # каноничный
for _ in range(rows): grid.append([0] * cols)   # явный цикл
cube = [[[0] * z for _ in range(y)] for _ in range(x)]
grid = [copy.deepcopy(template) for _ in range(rows)]
grid = defaultdict(int)                          # разреженная сетка
grid = np.zeros((rows, cols), dtype=int)         # NumPy (срез — view, не копия)
```
- Ключ: выражение вычисляется **на каждой итерации** → новый объект

**Ссылочная семантика**
- Имена связываются с объектами; присваивание копирует ссылку
- `a[:]`, `list(a)`, `copy.copy` — поверхностно; `copy.deepcopy` — глубоко
- Для двумерного списка **поверхностной копии недостаточно**: внутренние списки останутся общими

**Проверка**
- `grid[0] is grid[1]` → `False`; `len({id(r) for r in grid}) == len(grid)`

**Смежные проявления**
- Изменяемый аргумент по умолчанию
- Изменяемый атрибут класса вместо атрибута экземпляра
- `dict.fromkeys(keys, [])`

**Правило**
- Нужно n **независимых** изменяемых объектов → конструкция, создающая новый объект на каждой итерации; никогда не умножение списка
