## 1. Как сделать интерактивный элемент доступным для клавиатуры и скринридера? Требования к семантике HTML, фокусу, табуляции, ARIA

**Что нужно обеспечить элементу — четыре вещи**
1. Роль — что это за элемент
2. Доступное имя
3. Состояние
4. Клавиатурное поведение

**Семантика HTML — главное правило**
- «No ARIA is better than bad ARIA»: нативный элемент даёт всё бесплатно
- `<button>` из коробки: табуляция, `Enter` и `Space`, роль, `disabled`, отправка формы, индикатор фокуса, голосовое управление
- Нативные замены: `<button>` — действие, `<a href>` — переход, `<select>`, `<details>/<summary>`, `<dialog>` + `showModal()`, `popover`, `<progress>`, `<fieldset>`+`<legend>`, `<table>` с `<th scope>`
- `<a>` активируется только `Enter`, `<button>` — `Enter` и `Space`

**Кастомный элемент**
```html
<div role="button" tabindex="0" aria-pressed="false">…</div>
```
- Обработчик `click` + обработчик `keydown` на `Enter` и `Space` с `preventDefault` (иначе пробел прокрутит страницу)

**Табуляция**
- `tabindex="0"` — в естественный порядок обхода
- `tabindex="-1"` — не в табуляции, но доступен `element.focus()`: модалка, цель skip-link, сводка ошибок, roving tabindex
- `tabindex="1"` и больше — **антипаттерн**
- Порядок обхода = порядок в DOM; `order` во Flexbox и `grid-row` меняют визуальный порядок, но не порядок фокуса (WCAG 2.4.3)

**Индикатор фокуса**
- `*:focus { outline: none }` — недопустимо (WCAG 2.4.7, 2.4.11)
- `:focus-visible` с `outline` и `outline-offset`; контраст ≥ 3:1

**Управление фокусом**
- Модалка: фокус внутрь → focus trap → `Escape` закрывает → **фокус возвращается на открывший элемент** → фон `inert`; `<dialog>` делает это нативно
- Удалён элемент с фокусом → перевести на осмысленное место, иначе фокус упадёт на `body`
- SPA: после смены маршрута фокус на заголовок новой страницы
- Skip-link «перейти к содержимому» первым в табуляции

**Клавиатурные соглашения (ARIA APG)**
- Кнопка — `Enter`/`Space`; чекбокс — `Space`; радиогруппа — `Tab` в группу, **стрелки** между вариантами
- Табы, меню, комбобокс — стрелки, `Home`/`End`, `Escape`
- Модалка — `Escape`, `Tab` по кругу; слайдер — стрелки, `PageUp/Down`
- **Roving tabindex**: в группе один `tabindex="0"`, остальные `-1`, стрелки переносят
- Никаких клавиатурных ловушек (WCAG 2.1.2)

**Доступное имя — порядок вычисления**
1. `aria-labelledby`
2. `aria-label`
3. Нативная метка: `<label for>`, `alt`, `<caption>`, `<legend>`
4. Текстовое содержимое
5. `title` — крайний вариант
- Кнопка-иконка: `aria-label` + `aria-hidden="true"` на иконке
- `aria-label` не должен противоречить видимому тексту (WCAG 2.5.3)
- Визуально скрытый текст — класс `.visually-hidden`, не `display: none`

**ARIA**
- Роли: `button`, `tab`, `dialog`, `alert`, `navigation`, `status`
- Состояния: `aria-expanded`, `aria-pressed`, `aria-checked`, `aria-selected`, `aria-disabled`, `aria-current`, `aria-controls`, `aria-haspopup`, `aria-live`
- **ARIA ничего не делает сама** — только меняет то, что сообщается AT; поведение реализует код
- `aria-hidden` нельзя на фокусируемые элементы (останутся в табуляции) → `inert`
- Пять правил ARIA: нативное вместо ARIA; не менять нативную семантику; всё интерактивное управляется с клавиатуры; не скрывать фокусируемое; у всего интерактивного есть имя

**Live regions**
- `role="status"` / `aria-live="polite"` — сообщить, не прерывая
- `role="alert"` / `assertive` — прервать, только для критичного
- Контейнер должен быть в DOM **заранее**

**Проверка**
- Клавиатура: `Tab`, `Shift+Tab`, стрелки, `Enter`, `Space`, `Escape`
- Скринридеры: NVDA, JAWS, VoiceOver, TalkBack
- axe DevTools, Lighthouse, `eslint-plugin-jsx-a11y` — находят ~30–40 % проблем
- Дерево доступности в DevTools

## 2. Какие требования к доступной веб-форме? Как связать поле ввода, метку, подсказку и сообщение об ошибке для вспомогательных технологий?

**Схема связывания**
```html
<label for="email">Электронная почта</label>
<p id="email-hint">Например, name@example.com</p>
<input type="email" id="email" name="email" required
       autocomplete="email"
       aria-describedby="email-hint email-error"
       aria-invalid="false">
<p id="email-error" role="alert" hidden>Введите адрес в формате name@example.com</p>
```

**Метка — `<label for>` или вложение**
- Даёт: объявление подписи при фокусе, клик по подписи = фокус (для чекбокса — переключение), доступное имя
- **`placeholder` не метка**: исчезает при вводе, низкий контраст, теряется при автозаполнении
- Скрывать визуально — `.visually-hidden`, не удалять из DOM
- Размещать над полем; сохранять при масштабировании

**Подсказка — `aria-describedby`**
- Указывает на id элемента с текстом; принимает **список id через пробел**
- `aria-labelledby` — имя (что это), `aria-describedby` — описание (подробности)
- Требования к формату показывать **до** ввода (WCAG 3.3.2)

**Обязательность**
- `required` (сообщается AT автоматически), `aria-required` — только для кастомных элементов
- Звёздочку расшифровать текстом

**Сообщение об ошибке — три условия одновременно**
1. Связь с полем через `aria-describedby`
2. `aria-invalid="true"`, снимать после исправления
3. Объявление: `role="alert"`; контейнер существует **заранее**, текст добавляется в него
- Текст конкретный и с решением: не «неверное значение», а «пароль должен содержать минимум 8 символов, сейчас 5» (WCAG 3.3.1, 3.3.3)
- **Не только цветом** (WCAG 1.4.1): текст + иконка + форма границы

**Сводка ошибок при отправке**
- В начале формы: заголовок «форма содержит N ошибок», список ссылок на поля
- `role="alert"`, `tabindex="-1"`, программный перевод фокуса на неё
- Паттерн GOV.UK Design System

**Момент валидации**
- Не на каждое нажатие клавиши — шум в live region
- Формат — на `blur`, вся форма — на submit; после первой ошибки — на `input`
- CSS: `:user-invalid` вместо `:invalid`
- Не блокировать ввод символов молча

**Группировка**
- Радио и чекбоксы — `<fieldset>` + `<legend>`; легенда объявляется с каждым вариантом
- Альтернатива для кастомных — `role="radiogroup"` + `aria-labelledby`

**Автозаполнение и типы**
- `autocomplete` обязателен для полей с данными о пользователе (WCAG 1.3.5)
- Правильный `type` + `inputmode`; для числовых кодов `type="text" inputmode="numeric"`, не `type="number"`

**Время и потери данных**
- Предупреждать о таймауте и давать продлить (WCAG 2.2.1)
- Сохранять введённое при ошибке; не требовать повторного ввода тех же данных (WCAG 3.3.7)
- Не строить аутентификацию на когнитивных тестах, разрешать вставку в поле пароля (WCAG 3.3.8)

**Состояние отправки**
- `role="status"` + `aria-live="polite"`: «Отправка…», «Заявка отправлена, номер 1234»
- Для временно неактивной кнопки — `aria-disabled="true"` вместо `disabled` (остаётся в табуляции)

**Проверка**
- Пройти и отправить форму только с клавиатуры
- Прослушать в NVDA/VoiceOver, прогнать axe
- Контраст текста ≥ 4.5:1, границ полей ≥ 3:1; цель нажатия ≥ 24×24 px; масштаб 200 %
