## Общая схема

Оба алгоритма посещают все достижимые вершины ровно один раз. Различие — **в порядке**, который задаёт структура хранения «фронтира»:

- **DFS** — стек (LIFO): идём вглубь, пока можем, затем откатываемся (backtracking).
- **BFS** — очередь (FIFO): посещаем всех соседей текущего уровня, затем следующий уровень.

Сложность обоих на графе: **O(V + E)** по времени при списках смежности (O(V²) при матрице смежности).

## Память

- **BFS**: O(ширины) — в худшем случае O(V). На широком дереве (например, ветвление 10, глубина 6) очередь может содержать сотни тысяч узлов.
- **DFS**: O(глубины) — обычно меньше, но при глубоком графе рекурсия переполняет стек.

Это ключевой практический критерий: широкий граф → DFS экономнее, глубокий граф → BFS безопаснее.

```js
function bfs(start) {
  const q = [start], seen = new Set([start]);
  for (let i = 0; i < q.length; i++) {         // индекс вместо shift
    const v = q[i];
    for (const u of adj(v)) if (!seen.has(u)) { seen.add(u); q.push(u); }
  }
  return q; // порядок обхода по уровням
}
```

## Что умеет BFS и не умеет DFS

- **Кратчайший путь в невзвешенном графе** (по числу рёбер). BFS гарантирует, что вершина впервые достигается по кратчайшему пути; DFS такой гарантии не даёт.
- **Обход по уровням** — «друзья друзей», уровни вложенности DOM, распространение по слоям.
- **Поиск ближайшего** объекта — можно остановиться, как только нашли, и это точно ближайший.
- **Multi-source BFS** — от нескольких стартов сразу (например, «расстояние до ближайшего пожара»).
- **0-1 BFS** (дек) и **Дейкстра** (куча) — обобщения на взвешенные графы.

## Что естественнее делать через DFS

- **Топологическая сортировка** (post-order + разворот) и обнаружение циклов через цвета вершин (белый/серый/чёрный).
- **Компоненты связности**, **компоненты сильной связности** (Косарайю, Тарьян).
- **Мосты и точки сочленения** — алгоритмы на временах входа/выхода.
- **Backtracking-задачи**: судоку, N ферзей, генерация комбинаций и перестановок, лабиринт с проверкой всех путей.
- **Рекурсивные обходы деревьев**: сериализация, вычисление глубины, обход AST компилятором, рендер дерева компонентов.
- **Поиск любого пути** (не обязательно кратчайшего) — DFS часто находит быстрее.

## Практика во фронтенде и вебе

- DOM: `querySelector` фактически выполняет обход в глубину; `document.createTreeWalker` даёт in-order.
- Реконсиляция в React — DFS по дереву компонентов.
- Обход файловой системы, разрешение зависимостей в сборщике — DFS с проверкой циклов.
- Crawler веб-страниц — обычно BFS: ближние ссылки важнее, легче ограничить глубину.

## Сравнительная таблица

| Критерий | DFS | BFS |
|---|---|---|
| Структура | стек / рекурсия | очередь |
| Память | O(глубины) | O(ширины) |
| Кратчайший путь (невзвешенный) | нет | **да** |
| Полнота на бесконечном графе | может уйти в бесконечность | найдёт решение, если оно есть |
| Естественность рекурсии | высокая | низкая |
| Топосортировка, циклы | **да** | сложнее (алгоритм Кана — фактически BFS) |
| Риск | переполнение стека | взрыв памяти очереди |

## Компромисс

**Iterative deepening DFS (IDDFS)** — многократный DFS с ограничением глубины 1, 2, 3… Даёт оптимальность BFS при памяти DFS; повторные проходы стоят немного, так как последний уровень доминирует по числу узлов. Применяется в игровых движках.
