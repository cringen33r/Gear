## Object vs Map в JavaScript

| Критерий | Object | Map |
|---|---|---|
| Тип ключа | только string и symbol (числа приводятся к строкам) | **любое значение**: объект, функция, NaN, число |
| Порядок ключей | целочисленные ключи сортируются по возрастанию, остальные — по вставке | строго порядок вставки |
| Размер | `Object.keys(o).length` — O(n) | `map.size` — O(1) |
| Прототип | наследует `Object.prototype` — риск коллизий с `toString`, `constructor`, `__proto__` | нет прототипных ключей |
| Итерация | `for...in` обходит и унаследованные ключи; нужен `Object.keys/entries` | итерируемый по умолчанию (`for...of`, `forEach`) |
| Производительность частых вставок/удалений | хуже — движок может перевести объект в «dictionary mode» | оптимизирована под это |
| Сериализация | `JSON.stringify` работает напрямую | не сериализуется без преобразования |

## Когда выбирать Map

- **Ключи не строки** — объекты, DOM-узлы, функции. Классический кейс: связать данные с DOM-элементом.
- **Ключи приходят от пользователя** (имена полей, id из внешней системы). Ключ `"__proto__"` в обычном объекте ломает поведение или создаёт уязвимость prototype pollution.
- **Частые добавления/удаления** — Map спроектирована под изменяемую коллекцию.
- **Нужен строгий порядок вставки** и/или частое получение размера.
- **Нужна регулярная итерация** по всем парам.

## Когда достаточно Object

- Фиксированный набор известных строковых ключей (конфиг, запись, DTO).
- Нужна сериализация в JSON.
- Нужен литеральный синтаксис и деструктуризация.

Компромисс для «словаря со строковыми ключами без прототипа»: `Object.create(null)` — объект без `Object.prototype`.

## Дополнительно

- **Set** — та же структура без значений, для проверки принадлежности за O(1).
- **WeakMap / WeakSet** — ключи только объекты, удерживаются слабо: если на объект нет других ссылок, пара удаляется сборщиком мусора. Используются для приватных данных и кэшей, привязанных к объектам, — не текут по памяти.
- Ключи Map сравниваются по алгоритму SameValueZero: `NaN` равен `NaN` (в отличие от `===`), `+0` и `-0` считаются одним ключом.
