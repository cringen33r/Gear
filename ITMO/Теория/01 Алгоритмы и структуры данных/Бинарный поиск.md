## Идея

Бинарный поиск использует **отсортированность**: сравнив искомое значение с элементом в середине, мы отбрасываем половину диапазона. Инвариант — «если элемент есть, он лежит в [lo, hi]».

```js
function binarySearch(a, target) {
  let lo = 0, hi = a.length - 1;
  while (lo <= hi) {
    const mid = lo + ((hi - lo) >> 1);
    if (a[mid] === target) return mid;
    else if (a[mid] < target) lo = mid + 1;
    else hi = mid - 1;
  }
  return -1; // не найдено
}
```

Сложность: **O(log n) по времени**, O(1) по памяти (итеративная версия).

## Условия применимости

1. **Данные отсортированы** по тому же ключу, по которому ищем.
2. **Есть произвольный доступ за O(1)** — массив, типизированный массив, строка. По связному списку бинарный поиск бессмысленен: переход к середине сам стоит O(n).
3. **Предикат монотонен**. Обобщённо бинарный поиск ищет границу, где булев предикат меняется с false на true: `[F, F, F, T, T, T]`. Это позволяет искать не только значение, но и ответ на задачу («минимальная скорость, при которой успеваем») — так называемый «бинарный поиск по ответу».

## Когда бинарный поиск не окупается

Если массив нужно **сначала отсортировать** ради одного поиска — это O(n log n) против O(n) линейного просмотра. Бинарный поиск выгоден, когда массив уже отсортирован или поисков много. Если поисков много и порядок не важен — лучше хеш-таблица (O(1) в среднем).

## Типичные ошибки

**Переполнение при вычислении середины.** Классика `(lo + hi) / 2` в языках с фиксированной разрядностью даёт переполнение при больших индексах. Безопасно: `lo + ((hi - lo) >> 1)`. В JS переполнения int нет, но `>> 1` ещё и обрезает дробную часть, что необходимо.

**Забытое округление.** Без `Math.floor`/`| 0` в JS `mid` станет дробным, и индексация даст `undefined`.

**Бесконечный цикл** из-за неправильного сдвига границ: если писать `lo = mid` вместо `lo = mid + 1`, при `hi - lo === 1` середина не сдвигается. Правило: границы обязаны сужаться на каждой итерации.

**Путаница `<` и `<=` в условии цикла.** Для варианта с `hi = length - 1` цикл должен быть `while (lo <= hi)`; для полуинтервала `hi = length` — `while (lo < hi)` с `hi = mid`. Смешение двух шаблонов — источник off-by-one.

**Дубликаты.** Обычный бинарный поиск вернёт *какой-то* индекс, не обязательно первый. Для первого/последнего вхождения нужны варианты lower_bound / upper_bound: при равенстве не выходим, а продолжаем сужать в нужную сторону.

```js
function lowerBound(a, x) { // первый индекс, где a[i] >= x
  let lo = 0, hi = a.length;
  while (lo < hi) {
    const mid = lo + ((hi - lo) >> 1);
    if (a[mid] < x) lo = mid + 1; else hi = mid;
  }
  return lo;
}
```

**Нарушенная сортировка.** В JS `[1, 2, 10].sort()` даёт `[1, 10, 2]` — сортировка по умолчанию лексикографическая. Нужен компаратор `(a, b) => a - b`. Бинарный поиск по такому массиву даст молча неверный результат.

**Сравнение по другому ключу**, чем сортировка (массив отсортирован по `id`, ищем по `name`).

**Числа с плавающей точкой.** При бинарном поиске по вещественному диапазону условие `lo <= hi` не завершится; используют фиксированное число итераций (~100) или сравнение с epsilon.
