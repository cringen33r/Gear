## Алгоритм выбора

Ответьте на вопросы:

1. **Какие операции доминируют** — чтение по индексу, поиск по ключу, вставка/удаление в середину, извлечение минимума, диапазонный запрос?
2. **Нужен ли порядок** — по вставке, по значению, по приоритету?
3. **Каково соотношение чтений и записей?**
4. **Что важнее — время или память?**
5. **Нужны ли гарантии худшего случая** (реалтайм, недоверенный ввод)?
6. **Данные помещаются в память** или нужен диск/сеть?

## Сравнение сложностей

## Хеш-таблица (Map / Set / объект)

**Сильные стороны:** O(1) в среднем на вставку, поиск и удаление по ключу.

**Слабые:** нет порядка, нет диапазонных запросов, худший случай O(n), избыточная память, стоимость хеширования ключа.

**Когда:** индекс «по id», дедупликация, подсчёт частот, кеш, проверка принадлежности, группировка. Классическая оптимизация — замена вложенного цикла на предпостроенный `Map` (см. вопрос 1).

## Куча

**Сильные стороны:** минимум за O(1), извлечение и вставка за O(log n), построение за O(n), in-place.

**Слабые:** нет поиска произвольного элемента, нет полного порядка.

**Когда:** приоритетная очередь, Дейкстра/A\*, top-K из потока, планировщики и таймеры, скользящая медиана.

## Сбалансированное дерево поиска

**Сильные стороны:** гарантированное O(log n) на все операции, **упорядоченность**: диапазоны, ближайший ключ, k-й по порядку, обход по возрастанию за O(n).

**Слабые:** сложнее реализовать, константы больше, чем у хеш-таблицы; в JS нет встроенного.

**Когда:** нужны диапазонные запросы и порядок (интервалы времени, autocomplete по префиксу — там чаще trie, leaderboard). В СУБД аналог — B+-дерево индекса.

## Типичные ошибки выбора

- Линейный поиск в массиве в цикле вместо `Set`/`Map` — скрытый O(n²).
- `array.shift()` в цикле как очередь — O(n²) вместо O(n).
- Полная сортировка ради top-K — O(n log n) вместо O(n log k) с кучей.
- Хеш-таблица там, где нужны диапазоны и сортировка.
- Связный список «ради асимптотики» на малых объёмах, где массив быстрее из-за кеша.
- Преждевременная оптимизация: при n = 50 разница между O(n) и O(log n) не измерима, а читаемость страдает.

## Итоговая эвристика

- Нужен порядок и индекс → **массив**
- Нужен доступ по ключу → **хеш-таблица**
- Нужен «самый приоритетный» → **куча**
- Нужен порядок по значению и диапазоны → **дерево поиска**
- Нужны частые вставки/удаления по известной позиции → **связный список**
- Нужна уникальность → **Set**
- Нужен префиксный поиск → **trie**
