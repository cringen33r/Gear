## Приоритетная очередь

Абстракция: элементы извлекаются не в порядке поступления, а по **приоритету**. Базовые операции — `insert(x)` и `extractMin()` (или `extractMax`), плюс `peek()`.

## Двоичная куча

**Binary heap** — почти полное двоичное дерево, хранящееся в массиве. Свойство кучи (min-heap): значение любого узла ≤ значений его потомков. Корень — минимум. Никакого полного порядка нет: между братьями отношение не определено.

Индексация в массиве (0-based):

- потомки узла `i`: `2i + 1` и `2i + 2`;
- родитель: `(i - 1) >> 1`.

Дерево почти полное, поэтому высота — ⌊log₂n⌋, и массив без «дыр» (хорошая локальность кеша).

## Операции

**insert (sift-up).** Элемент кладётся в конец массива и «всплывает», меняясь с родителем, пока нарушает свойство кучи. **O(log n)**.

**extractMin (sift-down).** Берём корень (ответ), переносим последний элемент в корень, укорачиваем массив и «топим» новый корень, меняя с меньшим из потомков. **O(log n)**.

**peek** — `heap[0]`, **O(1)**.

**build-heap** — построение кучи из готового массива за **O(n)** (а не O(n log n)): sift-down применяется от середины к началу; сумма высот даёт линейную оценку.

**decrease-key** — O(log n), но требует знать позицию элемента: обычно поддерживают хеш-таблицу «элемент → индекс».

```js
class MinHeap {
  #a = [];
  get size() { return this.#a.length; }
  peek() { return this.#a[0]; }

  push(v) {
    const a = this.#a;
    a.push(v);
    let i = a.length - 1;
    while (i > 0) {
      const p = (i - 1) >> 1;
      if (a[p] <= a[i]) break;
      [a[p], a[i]] = [a[i], a[p]];
      i = p;
    }
  }

  pop() {
    const a = this.#a;
    if (a.length === 0) return undefined;
    const top = a[0];
    const last = a.pop();
    if (a.length) {
      a[0] = last;
      let i = 0;
      for (;;) {
        const l = 2 * i + 1, r = l + 1;
        let m = i;
        if (l < a.length && a[l] < a[m]) m = l;
        if (r < a.length && a[r] < a[m]) m = r;
        if (m === i) break;
        [a[m], a[i]] = [a[i], a[m]];
        i = m;
      }
    }
    return top;
  }
}
```

## Куча vs сортированный массив

| Операция | Куча | Сортированный массив |
|---|---|---|
| Вставка | **O(log n)** | O(n) — сдвиг элементов |
| Извлечение минимума | O(log n) | **O(1)** — с конца/начала |
| Просмотр минимума | O(1) | O(1) |
| Поиск произвольного элемента | O(n) | **O(log n)** — бинарный поиск |
| k-й по порядку элемент | O(n) или k·log n | **O(1)** |
| Построение из n элементов | **O(n)** | O(n log n) |
| Обход по возрастанию | O(n log n) | **O(n)** |
| Дополнительная память | O(1) (in-place) | O(1) |

Вывод: **куча даёт баланс** — обе критичные операции O(log n) и никакой лишней работы по поддержанию полного порядка. Сортированный массив хорош, если данные почти не меняются, а читать нужно много и в разных местах. Если поток данных динамический (вставки чередуются с извлечениями) — куча выигрывает.

## Где применяется

- **Алгоритм Дейкстры** и **A\*** — извлечение ближайшей вершины.
- **Алгоритм Прима** для минимального остовного дерева.
- **Кодирование Хаффмана** — слияние двух наименьших частот.
- **Top-K элементов** из потока: держим кучу размера k, суммарно O(n log k) и O(k) памяти — не нужно сортировать всё.
- **Heapsort** — O(n log n), in-place, но неустойчивая и с плохой локальностью кеша по сравнению с quicksort.
- **Планировщики задач и таймеры** (`setTimeout` в Node.js использует структуру по времени срабатывания).
- **Скользящая медиана** — две кучи (max-heap для нижней половины, min-heap для верхней).

## Альтернативы

**Фибоначчиева куча** даёт амортизированное O(1) на `insert` и `decrease-key`, что теоретически улучшает Дейкстру, но большие константы делают её невыгодной на практике. **d-арная куча** (d потомков) уменьшает высоту, ускоряя `decrease-key` за счёт замедления `extract`.
