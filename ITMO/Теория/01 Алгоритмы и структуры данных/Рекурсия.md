## Определение

**Рекурсия** — приём, при котором функция решает задачу, вызывая саму себя на подзадаче меньшего размера. Любая корректная рекурсия состоит из двух частей:

1. **Базовый случай (base case)** — условие, при котором ответ известен без рекурсивного вызова.
2. **Рекурсивный случай** — сведение задачи к меньшей и комбинация результатов.

```js
function factorial(n) {
  if (n <= 1) return 1;              // база
  return n * factorial(n - 1);       // шаг, аргумент строго убывает
}
```

## Как определять базовый случай

Практические правила:

- Возьмите **наименьший осмысленный вход**: пустой массив, пустая строка, `null`-узел, n = 0 или 1.
- Убедитесь, что **каждый рекурсивный вызов приближает к базе**: параметр монотонно убывает (по значению, длине, глубине) и не может «перепрыгнуть» базу. Ошибка `if (n === 0)` при вызове `f(n - 2)` для нечётного n даёт бесконечную рекурсию.
- **Проверяйте на границах**: массив длины 0 и 1, узел без потомков.
- Для деревьев естественная база — `if (!node) return ...`, она же обрабатывает пустое дерево.
- Для нескольких рекурсивных ветвей нужно, чтобы база покрывала все выходы (в бинарной рекурсии часто нужны и `n === 0`, и `n === 1`).
- Не забывайте про **невалидный вход**: отрицательное n, циклический граф (нужно множество посещённых).

## Плюсы рекурсии

- Код ближе к математическому определению задачи: обходы деревьев, разбор выражений, разделяй-и-властвуй, backtracking.
- Естественна для **рекурсивных структур данных** — деревьев, JSON-подобных объектов, DOM, файловых систем, AST.
- Короче и понятнее итеративной версии там, где иначе нужен ручной стек.

## Минусы

- **Память на стек вызовов**: каждый фрейм — аргументы, локальные, адрес возврата. В JS переполнение наступает примерно на 10⁴ вложений (`RangeError: Maximum call stack size exceeded`).
- **Накладные расходы** на вызов функции — в горячем цикле заметны.
- **Экспоненциальное дублирование работы** при наивной реализации перекрывающихся подзадач.

Классический пример деградации:

```js
function fib(n) { return n < 2 ? n : fib(n - 1) + fib(n - 2); } // O(2^n)
```

Лечится **мемоизацией** (top-down динамика, O(n)):

```js
const fibMemo = (n, memo = new Map()) => {
  if (n < 2) return n;
  if (memo.has(n)) return memo.get(n);
  const v = fibMemo(n - 1, memo) + fibMemo(n - 2, memo);
  memo.set(n, v);
  return v;
};
```

или итеративной bottom-up динамикой с O(1) памяти:

```js
function fibIter(n) {
  let a = 0, b = 1;
  for (let i = 0; i < n; i++) [a, b] = [b, a + b];
  return a;
}
```

## Связь стека с рекурсией

Рекурсия **реализуется через стек на уровне рантайма**. Каждый вызов функции создаёт **фрейм стека вызовов (call stack frame)**: аргументы, локальные переменные, адрес возврата. При входе фрейм кладётся, при `return` — снимается. Поэтому:

- Глубина рекурсии = высота стека вызовов. Переполнение даёт `RangeError: Maximum call stack size exceeded` (в JS предел обычно ~10⁴ фреймов).
- Любую рекурсию можно переписать в цикл с **явным стеком** — это и делают, когда глубина велика или нужен контроль над памятью.

Пример: рекурсивный и итеративный DFS эквивалентны.

```js
// Рекурсивно: неявный стек вызовов
function dfs(node, visited = new Set()) {
  if (!node || visited.has(node)) return;
  visited.add(node);
  for (const n of node.neighbors) dfs(n, visited);
}

// Итеративно: явный стек
function dfsIter(start) {
  const stack = [start], visited = new Set();
  while (stack.length) {
    const node = stack.pop();
    if (visited.has(node)) continue;
    visited.add(node);
    for (const n of node.neighbors) stack.push(n);
  }
}
```

Замена `stack.pop()` на `queue.dequeue()` превращает DFS в BFS — структура данных задаёт стратегию обхода. Это ключевая мысль: **алгоритм один, порядок определяется контейнером**.

Отдельно стоит **хвостовая рекурсия** (tail call): если рекурсивный вызов — последняя операция, теоретически фрейм можно переиспользовать. В спецификации ES2015 оптимизация хвостовых вызовов есть, но реально её поддерживает только JavaScriptCore (Safari); в V8 её нет, поэтому в JS полагаться на неё нельзя.

## Когда итеративный подход практичнее

1. **Большая или непредсказуемая глубина** — обход списка из 100 000 элементов, глубоко вложенный JSON, обход графа. Итерация с явным стеком не падает.
2. **Простые линейные задачи** — сумма, подсчёт, поиск: цикл проще и быстрее.
3. **Горячий код** — накладные расходы на вызовы значимы.
4. **Хвостовая рекурсия в JS** — оптимизация хвостовых вызовов в V8/Node не реализована, поэтому рекурсию, эквивалентную циклу, стоит сразу писать циклом.
5. **Нужен контроль над обходом** — приостановка, возобновление, ограничение по времени, прогресс-бар: явный стек даёт возможность прервать и продолжить.

## Когда рекурсия практичнее

Обход дерева произвольной глубины (но небольшой), backtracking с откатом состояния, парсинг, divide-and-conquer, задачи, где ручной стек воспроизводит логику вызовов и делает код заметно хуже.

## Преобразование рекурсии в итерацию

- **Хвостовая рекурсия** → цикл `while` напрямую (аккумулятор вместо возврата).
- **Нехвостовая** → явный стек с сохранением «состояния возврата» (какая ветвь уже обработана).
- **Перекрывающиеся подзадачи** → таблица динамического программирования (bottom-up).

## Взаимная и косвенная рекурсия

Функции A и B вызывают друг друга (например, `isEven`/`isOdd`, разбор выражения → разбор терма → разбор множителя). Правила те же: должна существовать метрика, строго убывающая на каждом шаге цикла вызовов.
