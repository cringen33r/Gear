## Сбалансированные варианты

Чтобы гарантировать h = O(log n), используют самобалансирующиеся деревья:

- **AVL-дерево** — строгий баланс (разница высот поддеревьев ≤ 1). Быстрее поиск, дороже вставка (больше поворотов).
- **Красно-чёрное дерево** — более слабый баланс, меньше поворотов при модификации. Используется в `std::map` (C++), `TreeMap` (Java), планировщике CFS в Linux.
- **B-дерево / B+-дерево** — многопутевые деревья с высоким ветвлением; узел = страница диска. Основа индексов в СУБД (см. блок 02, вопрос 4) и файловых систем.
- **Treap, Splay-дерево, Skip list** — вероятностные и самонастраивающиеся альтернативы.

## BST против хеш-таблицы

| | BST (сбалансированное) | Хеш-таблица |
|---|---|---|
| Поиск по ключу | O(log n) гарантированно | O(1) в среднем, O(n) в худшем |
| Порядок ключей | сохраняется | нет |
| Диапазонные запросы | O(log n + k) | O(n) |
| min/max, соседи | O(log n) | O(n) |
| Память | указатели на узлы | массив корзин + запас |

Выбор: нужен только доступ по точному ключу — хеш-таблица; нужны порядок, диапазоны, «ближайший ключ» — дерево.
