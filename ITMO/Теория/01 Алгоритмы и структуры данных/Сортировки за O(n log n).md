## Алгоритмы O(n log n)

**Сортировка слиянием (merge sort).** Разделяй-и-властвуй: делим пополам, сортируем рекурсивно, сливаем. Θ(n log n) во всех случаях, **устойчива**, но требует **O(n) дополнительной памяти**. Идеальна для связных списков (слияние без доп. памяти) и для внешней сортировки (данные не помещаются в RAM).

**Быстрая сортировка (quicksort).** Выбираем опорный элемент, разбиваем на «меньше/больше», рекурсивно сортируем части. Средняя O(n log n) с **лучшей константой** среди сравнительных сортировок благодаря локальности кеша и работе in-place. Худший случай **O(n²)** при неудачном выборе опорного (например, всегда первый элемент на отсортированных данных). Память O(log n) на стек. **Неустойчива.**

Смягчения худшего случая: случайный опорный, медиана из трёх, схема Hoare, трёхпутевое разбиение (для массивов с большим числом дубликатов), **introsort** — переключение на heapsort при слишком глубокой рекурсии (даёт гарантию O(n log n)).

**Пирамидальная сортировка (heapsort).** Строим кучу за O(n), затем n раз извлекаем максимум. Гарантированные O(n log n) и **O(1) памяти**, но неустойчива и медленнее quicksort из-за плохой локальности обращений к памяти.

**Timsort** — гибрид merge sort и insertion sort, использующий уже отсортированные «прогоны» (runs) в данных. O(n) на отсортированном входе, O(n log n) в худшем, устойчив, O(n) памяти. Стандарт в Python (`sorted`), Java (для объектов) и в V8 (`Array.prototype.sort` с V8 7.0).
