## Какие задачи решает контейнеризация

**1. «Работает у меня» перестаёт быть проблемой.** Образ содержит приложение вместе с рантаймом, системными библиотеками и конфигурацией. Одно и то же окружение на ноутбуке разработчика, в CI, на staging и в production.

**2. Воспроизводимость и версионирование окружения.** `Dockerfile` — код, лежащий в репозитории рядом с приложением. Инфраструктура описывается декларативно и ревьюится как обычный код.

**3. Быстрый онбординг.** `docker compose up` поднимает приложение, базу, кеш и очередь одной командой — вместо страницы инструкций по установке.

**4. Изоляция зависимостей.** Два сервиса на разных версиях Node или Python сосуществуют без конфликтов; ничего не «пачкает» хост-систему.

**5. Плотность и утилизация.** Сотни контейнеров на одном сервере против десятков ВМ — прямая экономия.

**6. Основа для оркестрации и микросервисов.** Kubernetes, ECS, Nomad управляют контейнерами: масштабирование по нагрузке, самовосстановление, rolling update, health checks, service discovery.

**7. Быстрые деплои и откаты.** Деплой — запуск нового образа, откат — запуск предыдущего тега. Секунды вместо процедур.

**8. CI/CD.** Сборка в контейнере даёт одинаковые условия для всех джоб; артефакт сборки — образ, который проходит все стадии без пересборки.

## Ключевые понятия

- **Образ (image)** — неизменяемый слоёный шаблон.
- **Контейнер** — запущенный экземпляр образа с записываемым слоем.
- **Dockerfile** — рецепт сборки образа.
- **Registry** — хранилище образов (Docker Hub, GHCR, приватные).
- **Volume** — постоянное хранилище, переживающее пересоздание контейнера.
- **Сеть** — bridge, host, overlay; контейнеры общаются по именам сервисов.
- **Docker Compose** — описание многоконтейнерного окружения в YAML.

## Пример многостадийной сборки

```dockerfile
# Стадия сборки
FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci                 # отдельный слой: кешируется, пока не меняются зависимости
COPY . .
RUN npm run build

# Финальный образ — без исходников и devDependencies
FROM node:20-alpine
WORKDIR /app
ENV NODE_ENV=production
COPY package*.json ./
RUN npm ci --omit=dev
COPY --from=build /app/dist ./dist
USER node                  # не root
EXPOSE 3000
HEALTHCHECK CMD wget -qO- http://localhost:3000/health || exit 1
CMD ["node", "dist/server.js"]
```

## Хорошие практики

- Многостадийная сборка — маленький финальный образ.
- Порядок инструкций от редко меняющихся к часто меняющимся — эффективный кеш слоёв.
- `.dockerignore` (`node_modules`, `.git`, логи).
- Минимальные базовые образы (alpine, distroless), регулярное обновление ради патчей безопасности.
- **Не запускать процесс от root**, не хранить секреты в образе (только переменные окружения или секрет-хранилища).
- Один процесс на контейнер; логи — в stdout/stderr.
- Явные теги вместо `latest`; сканирование образов на уязвимости.
- Ограничения ресурсов (`--memory`, `--cpus`), health checks.
