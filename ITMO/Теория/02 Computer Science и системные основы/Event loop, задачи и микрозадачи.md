## Однопоточность и модель выполнения

JavaScript в браузере выполняется в **одном потоке**: в каждый момент времени работает ровно один фрагмент кода. Асинхронность достигается не параллелизмом JS, а тем, что долгие операции (сеть, таймеры, файлы) выполняет **среда исполнения** (браузер, Node.js), а результат возвращается в JS через очереди задач.

## Компоненты

**Call stack (стек вызовов)** — стек фреймов исполняемых функций. Вызов кладёт фрейм, `return` снимает. Переполнение — `RangeError: Maximum call stack size exceeded`.

**Heap** — область памяти для объектов, управляемая сборщиком мусора.

**Web APIs / host environment** — `setTimeout`, `fetch`, DOM-события, `IntersectionObserver`. Реализованы вне JS-движка, часто в других потоках браузера.

**Task queue (macrotask queue / очередь задач)** — FIFO-очередь колбэков: таймеры, события ввода, `MessageChannel`, загрузка ресурсов. Технически очередей несколько, и браузер выбирает между ними по приоритету.

**Microtask queue (очередь микрозадач)** — колбэки промисов (`.then`/`.catch`/`.finally`), `queueMicrotask`, `MutationObserver`, продолжение `async`-функции после `await`.

**Event loop (цикл событий)** — бесконечный цикл, который координирует всё вышеперечисленное.

## Алгоритм цикла событий (упрощённо)

```
пока (истина):
  1. если стек пуст — взять ОДНУ задачу из task queue и выполнить её до конца
  2. выполнить ВСЕ микрозадачи, пока очередь микрозадач не опустеет
     (микрозадачи, добавленные во время обработки, тоже выполняются в этом же проходе)
  3. при необходимости — этап рендеринга:
     requestAnimationFrame → пересчёт стилей → layout → paint
  4. вернуться к шагу 1
```

Два ключевых следствия:

- **За один «тик» выполняется одна макрозадача, но все микрозадачи.**
- **Рендеринг не может произойти, пока стек не пуст и микрозадачи не исчерпаны.** Поэтому долгий синхронный код или бесконечная генерация микрозадач «замораживают» интерфейс.

## Разбор порядка на примере

```js
console.log('1');

setTimeout(() => console.log('2'), 0);

Promise.resolve().then(() => console.log('3'));

queueMicrotask(() => console.log('4'));

(async () => {
  console.log('5');
  await null;
  console.log('6');
})();

console.log('7');
```

Вывод: **1, 5, 7, 3, 4, 6, 2**

Разбор:
- `1` — синхронно.
- `setTimeout` регистрирует макрозадачу.
- `.then` ставит микрозадачу (`3`).
- `queueMicrotask` ставит микрозадачу (`4`).
- Тело async-функции до первого `await` выполняется **синхронно** → `5`. `await null` ставит продолжение (`6`) в очередь микрозадач — после уже стоящих там `3` и `4`.
- `7` — синхронно.
- Стек пуст → микрозадачи: `3`, `4`, `6`.
- Затем макрозадача: `2`.

## Почему setTimeout(fn, 0) не мгновенен

Три причины, каждая достаточная сама по себе:

**1. Это не «выполнить сейчас», а «поставить в очередь».** Даже с нулевой задержкой колбэк становится **макрозадачей**. Он не может выполниться, пока не завершится весь текущий синхронный код и не опустеет очередь микрозадач. Если синхронный код работает 3 секунды, колбэк подождёт 3 секунды.

**2. Спецификация задаёт минимальную задержку.** HTML-стандарт предписывает **clamping**: при вложенности таймеров больше 5 минимальная задержка становится **4 мс**. Браузеры также замедляют таймеры в фоновых вкладках (до 1000 мс и реже) для экономии батареи.

**3. Очередь может быть занята.** Перед вашим колбэком в очереди могут стоять другие задачи; таймер гарантирует «не раньше чем», но не «ровно через».

Итог: `setTimeout(fn, 0)` означает «выполни как можно скорее, но после текущей работы и после микрозадач». Это законный приём для того, чтобы **отдать управление браузеру** — дать ему обработать события и отрисовать кадр.

## Микрозадачи против макрозадач: практические следствия

Бесконечная генерация микрозадач полностью блокирует рендеринг:

```js
function loop() { Promise.resolve().then(loop); } // страница зависнет
loop();
```

С `setTimeout` вместо промиса страница останется отзывчивой, потому что между макрозадачами браузер успевает рендерить.

Разбивка тяжёлой работы на части:

```js
async function processChunks(items) {
  for (let i = 0; i < items.length; i++) {
    heavyWork(items[i]);
    if (i % 100 === 0) await new Promise(r => setTimeout(r, 0)); // отдать поток браузеру
  }
}
```

Современные альтернативы: `scheduler.yield()`, `scheduler.postTask()` (Prioritized Task Scheduling API), `requestIdleCallback` для несрочной работы и **Web Workers** для настоящего параллелизма (отдельный поток со своим event loop, общение через `postMessage`).

## Рендеринг и requestAnimationFrame

`requestAnimationFrame` — колбэк, выполняемый **перед следующей отрисовкой**, синхронизированный с частотой обновления экрана (обычно 60 Гц ≈ каждые 16.7 мс). Для анимаций он лучше `setTimeout`: не рассинхронизируется с кадрами и приостанавливается в фоновых вкладках.

## Отличия в Node.js

Event loop Node построен на libuv и имеет **фазы**: timers → pending callbacks → idle/prepare → **poll** → check (`setImmediate`) → close callbacks. Дополнительно `process.nextTick()` имеет приоритет **выше** микрозадач промисов. Поэтому порядок `setTimeout` vs `setImmediate` в Node на верхнем уровне недетерминирован, а внутри I/O-колбэка `setImmediate` всегда раньше.
