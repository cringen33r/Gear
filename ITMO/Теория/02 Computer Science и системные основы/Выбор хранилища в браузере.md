## Сводная таблица

| Характеристика | Cookies | localStorage | sessionStorage |
|---|---|---|---|
| Объём | ~4 КБ на cookie, ~50 на домен | ~5–10 МБ | ~5–10 МБ |
| Время жизни | до `Expires`/`Max-Age`; без них — до закрытия браузера | **бессрочно**, пока не удалят | до закрытия **вкладки** |
| Область действия | домен + путь; доступна поддоменам при `Domain` | **origin** (схема + хост + порт) | origin **в пределах одной вкладки** |
| Отправка на сервер | **автоматически с каждым запросом** | нет | нет |
| Доступ из JS | `document.cookie`, кроме `HttpOnly` | `localStorage` API | `sessionStorage` API |
| Доступ с сервера | да, заголовок `Cookie` | нет | нет |
| API | строковый парсинг или `CookieStore` | синхронный key-value | синхронный key-value |
| Тип данных | строка | строка | строка |
| Событие об изменении | нет (кроме CookieStore) | `storage` (в других вкладках) | нет между вкладками |

## Что где хранить

**Cookies:**
- идентификатор сессии и токены аутентификации — обязательно с `HttpOnly`, `Secure`, `SameSite`;
- данные, нужные серверу при каждом запросе (локаль, A/B-группа, тема для SSR);
- CSRF-токен (в паре с проверкой на сервере).

**localStorage:**
- пользовательские настройки интерфейса (тема, язык, свёрнутые панели);
- черновики и кеш некритичных данных;
- флаги «этот онбординг уже показан».

**sessionStorage:**
- временное состояние вкладки: шаг мастера, фильтры, возврат к позиции списка.

## Где хранить JWT: cookie или localStorage

Частый экзаменационный вопрос. Аргументы:

- **localStorage** уязвим к XSS: любой инжектированный скрипт прочитает токен. Зато не уязвим к CSRF (токен нужно прикреплять вручную).
- **HttpOnly cookie** недоступна JS, поэтому XSS не украдёт токен напрямую, но уязвима к CSRF, так как отправляется автоматически. Защита — `SameSite=Lax/Strict` плюс CSRF-токен.

Практический консенсус: **HttpOnly + Secure + SameSite cookie** безопаснее, при условии защиты от CSRF. Универсально верного ответа нет; важно понимать модель угроз.

## Другие механизмы хранения

- **IndexedDB** — асинхронная транзакционная NoSQL-база в браузере; сотни мегабайт, индексы, хранение структурированных объектов и Blob. Основа офлайн-приложений (часто через обёртки idb, Dexie).
- **Cache API** — хранилище пар запрос/ответ, используется Service Worker для офлайна.
- **Origin Private File System (OPFS)** — файловая система для origin, высокая производительность.
- **Web SQL** — устаревшее, не использовать.
- **Хранение в памяти (JS-переменная, состояние SPA)** — самое безопасное для access-токена короткого срока жизни.

## Приватность и ограничения

Браузеры активно ограничивают долговременное хранение: Safari ITP урезает срок жизни cookie, установленных через JS, до 7 дней; сторонние cookie блокируются или партиционируются. Хранение персональных данных требует согласия пользователя (GDPR, 152-ФЗ). Storage может быть очищен браузером при нехватке места, если не запрошен `navigator.storage.persist()`.
