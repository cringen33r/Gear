## Виртуальная машина

Гипервизор (VMware, KVM, Hyper-V, VirtualBox) виртуализирует **аппаратуру**. Поверх него запускается **полноценная гостевая ОС со своим ядром**, драйверами, системными службами. Приложение работает внутри этой гостевой ОС.

```
┌─────────────┬─────────────┐
│  Прил. A    │   Прил. B   │
│  Гостевая   │  Гостевая   │
│  ОС + ядро  │  ОС + ядро  │
├─────────────┴─────────────┤
│        Гипервизор         │
├───────────────────────────┤
│      Хостовая ОС / железо │
└───────────────────────────┘
```

## Контейнер

Контейнер виртуализирует **операционную систему**: процессы изолируются средствами **ядра хоста** и разделяют его.

```
┌─────────┬─────────┬─────────┐
│ Прил. A │ Прил. B │ Прил. C │
│ + зависимости (образ)       │
├─────────────────────────────┤
│    Docker Engine / runtime  │
├─────────────────────────────┤
│  Хостовая ОС (общее ядро)   │
└─────────────────────────────┘
```

Технологическая основа в Linux:

- **namespaces** — изоляция видимости: PID (свои номера процессов), NET (свой сетевой стек), MNT (своя файловая система), UTS (hostname), IPC, USER, cgroup.
- **cgroups** — ограничение ресурсов: CPU, память, ввод-вывод, число процессов.
- **union-файловая система** (OverlayFS) — послойный образ: слои только для чтения плюс тонкий записываемый слой контейнера.
- **capabilities, seccomp, AppArmor/SELinux** — сужение прав.

## Сравнение

| Критерий | Виртуальная машина | Контейнер |
|---|---|---|
| Уровень изоляции | аппаратный, очень сильный | на уровне ядра, слабее |
| Ядро ОС | собственное у каждой ВМ | **общее с хостом** |
| Размер | гигабайты | мегабайты (иногда < 10 МБ) |
| Время старта | десятки секунд — минуты | **миллисекунды — секунды** |
| Накладные расходы | заметные (CPU, RAM) | близки к нулю |
| Плотность на хосте | десятки | сотни и тысячи |
| Разные ОС на одном хосте | да (Windows на Linux-хосте) | нет: Linux-контейнеры требуют Linux-ядра |
| Граница безопасности | сильная (гипервизор) | слабее; root в контейнере ближе к root на хосте |
| Снапшоты, живая миграция | зрелые механизмы | ограниченно |

Важная деталь: Docker на macOS и Windows на самом деле запускает **лёгкую Linux-ВМ**, внутри которой уже работают контейнеры. Отсюда особенности с производительностью примонтированных томов.

Промежуточные решения (там, где нужна и скорость, и сильная изоляция): **Firecracker** (микроВМ, основа AWS Lambda), **gVisor**, **Kata Containers**.

## Ограничения

Контейнеры не заменяют ВМ там, где нужна сильная изоляция между недоверенными арендаторами, нужны другое ядро или ОС, специфические драйверы и модули ядра. Кроме того, оркестрация добавляет собственную операционную сложность — для маленького проекта Kubernetes может оказаться дороже пользы.
