## Реляционная модель

Данные хранятся в **отношениях** — таблицах. Строка (кортеж, запись) описывает один объект; столбец (атрибут) имеет имя, тип и ограничения. Порядок строк не определён — он задаётся только `ORDER BY`. Работа с данными ведётся декларативно на **SQL**: вы описываете *что* нужно, планировщик решает *как* это получить.

## Ключи

**Первичный ключ (PRIMARY KEY)** — столбец или набор столбцов, однозначно идентифицирующий строку. Уникален и NOT NULL. Бывает **естественным** (ИНН, ISBN) или **суррогатным** (автоинкремент, UUID). Суррогатные предпочитают, потому что естественные ключи имеют свойство меняться.

**Уникальный ключ (UNIQUE)** — гарантирует уникальность, но допускает NULL (в большинстве СУБД — несколько NULL).

**Внешний ключ (FOREIGN KEY)** — ссылка на первичный ключ другой таблицы. Обеспечивает **ссылочную целостность**: нельзя вставить заказ с несуществующим `user_id`. Правила `ON DELETE`/`ON UPDATE`: `CASCADE`, `SET NULL`, `RESTRICT`, `NO ACTION`.

**Составной ключ** — из нескольких столбцов, типичен для таблиц-связок.

## Виды связей

**Один-к-одному (1:1)** — внешний ключ с ограничением UNIQUE. Применяется для выноса редко используемых или чувствительных полей в отдельную таблицу.

**Один-ко-многим (1:N)** — самая частая. Внешний ключ хранится **на стороне «многих»**: у заказа есть `user_id`.

**Многие-ко-многим (M:N)** — реализуется через **промежуточную таблицу** (junction/join table) с двумя внешними ключами и составным первичным ключом:

```sql
CREATE TABLE students (id SERIAL PRIMARY KEY, name TEXT NOT NULL);
CREATE TABLE courses  (id SERIAL PRIMARY KEY, title TEXT NOT NULL);

CREATE TABLE enrollments (
  student_id INT REFERENCES students(id) ON DELETE CASCADE,
  course_id  INT REFERENCES courses(id)  ON DELETE CASCADE,
  enrolled_at TIMESTAMPTZ DEFAULT now(),
  PRIMARY KEY (student_id, course_id)
);
```

## Нормализация

Процесс устранения избыточности:

- **1НФ** — атомарные значения, нет повторяющихся групп.
- **2НФ** — 1НФ + все неключевые атрибуты зависят от **всего** составного ключа.
- **3НФ** — 2НФ + нет транзитивных зависимостей (неключевой атрибут не зависит от другого неключевого).

Нормализация убирает аномалии вставки, обновления и удаления. **Денормализация** — осознанное дублирование данных ради скорости чтения (меньше JOIN), ценой сложности поддержания согласованности. Типична в аналитических хранилищах и кешах.
