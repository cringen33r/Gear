## Определение

**Транзакция** — последовательность операций, выполняемая как единое неделимое целое: либо применяются все изменения (`COMMIT`), либо ни одного (`ROLLBACK`).

```sql
BEGIN;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;
COMMIT;
```

Без транзакции сбой между двумя `UPDATE` уничтожил бы 100 единиц денег.

## Свойства ACID

**Atomicity (атомарность)** — «всё или ничего». Реализуется через журнал отмены (undo log) и WAL: незавершённые изменения откатываются при сбое.

**Consistency (согласованность)** — транзакция переводит БД из одного корректного состояния в другое, соблюдая все ограничения (PK, FK, CHECK, UNIQUE, триггеры) и бизнес-инварианты.

**Isolation (изолированность)** — параллельные транзакции не видят промежуточных состояний друг друга. Степень изоляции настраивается.

**Durability (долговечность)** — после успешного `COMMIT` данные переживут сбой питания. Обеспечивается **write-ahead logging**: журнал сбрасывается на диск (`fsync`) до подтверждения коммита.

## Когда транзакция необходима

1. **Изменяются несколько таблиц/строк, и они должны меняться вместе**: перевод денег, оформление заказа (заказ + позиции + резерв склада), регистрация (пользователь + профиль + настройки).
2. **Read-modify-write**: списание баланса, декремент остатка, инкремент счётчика. Иначе — потерянное обновление. Часто лечится атомарным `UPDATE ... SET x = x - 1 WHERE x >= 1` без явной блокировки.
3. **Нужна согласованная выборка** нескольких связанных сущностей для отчёта.
4. **Пакетная обработка**, где частичное применение недопустимо (импорт, миграции данных).
5. **Уникальность с проверкой**: «проверить, что email свободен, и вставить» — здесь ещё лучше положиться на UNIQUE-ограничение и обработать ошибку.

## Когда транзакция не нужна и вредна

- Одиночные `INSERT`/`UPDATE` — они уже атомарны (autocommit).
- Только чтение без требования согласованного снимка.
- **Длительные операции внутри транзакции**: HTTP-вызовы к внешнему API, отправка почты, обработка файлов. Транзакция удерживает блокировки и соединение, блокирует VACUUM и может привести к каскадной деградации. Правило: **транзакция должна быть короткой**, а внешние эффекты выносятся за её пределы (например, через outbox-таблицу).
