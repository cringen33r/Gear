## Что такое Promise

**Promise** — объект, представляющий результат асинхронной операции, который станет известен в будущем. Три состояния:

- **pending** — ожидание;
- **fulfilled** — успешно завершён со значением;
- **rejected** — завершён с ошибкой.

Переход происходит **ровно один раз** и необратим (промис *settled*). Повторные вызовы `resolve`/`reject` игнорируются.

```js
const p = new Promise((resolve, reject) => {
  setTimeout(() => (Math.random() > 0.5 ? resolve('ok') : reject(new Error('fail'))), 100);
});
```

## Цепочки .then()

`.then(onFulfilled, onRejected)` **возвращает новый промис**, поэтому вызовы можно выстраивать в цепочку. Правила преобразования результата:

- обработчик вернул обычное значение → новый промис выполняется с этим значением;
- обработчик вернул промис → цепочка **ждёт** его разрешения и берёт его результат (thenable-раскрытие);
- обработчик бросил исключение → новый промис отклоняется этой ошибкой;
- обработчик отсутствует → значение или ошибка **проходят дальше по цепочке**.

```js
fetch('/api/user')
  .then(res => {
    if (!res.ok) throw new Error(`HTTP ${res.status}`); // fetch не бросает на 4xx/5xx!
    return res.json();                                  // возвращаем промис — цепочка ждёт
  })
  .then(user => fetch(`/api/orders?userId=${user.id}`))
  .then(res => res.json())
  .then(orders => render(orders))
  .catch(err => showError(err))       // ловит ошибку из ЛЮБОГО предыдущего звена
  .finally(() => hideSpinner());      // выполнится в любом случае
```

## Чем лучше вложенных колбэков

**Callback hell («пирамида судьбы»):**

```js
getUser(id, (err, user) => {
  if (err) return handle(err);
  getOrders(user.id, (err, orders) => {
    if (err) return handle(err);
    getDetails(orders[0].id, (err, details) => {
      if (err) return handle(err);
      render(details);
    });
  });
});
```

Преимущества промисов:

1. **Плоская структура** вместо растущей вправо пирамиды — код читается сверху вниз.
2. **Единая обработка ошибок**: один `.catch()` вместо `if (err)` в каждом колбэке.
3. **Композируемость**: промис — значение, его можно передать, сохранить, вернуть из функции, положить в массив.
4. **Гарантии контракта**: колбэк вызывается **ровно один раз** и **всегда асинхронно** (как микрозадача). Самописные колбэк-API этого не гарантируют — бывает «иногда синхронно, иногда асинхронно» (проблема Залго), что приводит к трудноуловимым багам.
5. **Комбинаторы** для параллельной работы (см. ниже) — с колбэками пришлось бы вручную считать счётчики.
6. **Инверсия контроля возвращается к вызывающему**: вы решаете, когда и как подписаться, а не отдаёте свою функцию чужому коду.
7. **Интеграция с async/await** — синтаксис поверх промисов.

Промисы не отменяют колбэки полностью: для повторяющихся событий (клики, поток данных) нужны именно колбэки/события/стримы, потому что промис разрешается один раз.

## Комбинаторы

```js
// Все должны выполниться; при первой ошибке — общий reject
const [a, b] = await Promise.all([fetchA(), fetchB()]);

// Ждём все, получаем статусы каждого — ошибки не прерывают
const results = await Promise.allSettled([fetchA(), fetchB()]);
// [{status:'fulfilled', value}, {status:'rejected', reason}]

// Первый завершившийся (успех или ошибка)
const fastest = await Promise.race([fetchData(), timeout(5000)]);

// Первый УСПЕШНЫЙ; если все упали — AggregateError
const anyOk = await Promise.any([mirror1(), mirror2()]);
```

`Promise.race` с таймаутом — стандартный приём ограничения времени операции. Важно: race не отменяет проигравшие промисы — для реальной отмены нужен `AbortController`.
