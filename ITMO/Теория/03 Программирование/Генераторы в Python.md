## Определение

**Генератор** — функция, которая вместо `return` использует `yield` и при вызове возвращает объект-итератор. Значения производятся **по одному, по требованию**; между вызовами функция «замораживается», сохраняя состояние (локальные переменные и точку выполнения).

```python
def countdown(n):
    while n > 0:
        yield n
        n -= 1

gen = countdown(3)      # тело ещё НЕ выполнялось
print(next(gen))        # 3
print(next(gen))        # 2
for x in gen:           # 1
    print(x)
next(gen)               # StopIteration
```

**Генераторное выражение** — компактная форма:

```python
squares = (x * x for x in range(1_000_000))   # круглые скобки, а не квадратные
```

## Отличия от списка

| Критерий | Список | Генератор |
|---|---|---|
| Вычисление | немедленное (eager) | **ленивое (lazy)** |
| Память | хранит все элементы | хранит только текущее состояние |
| Длина | `len()` работает | `len()` **не работает** |
| Индексация, срезы | да | нет |
| Повторный проход | сколько угодно | **одноразовый** |
| Бесконечность | невозможна | **возможна** |
| Первый результат | после вычисления всего | сразу |

Разница в памяти наглядна:

```python
import sys
sys.getsizeof([x * x for x in range(1_000_000)])   # ~8.4 МБ
sys.getsizeof((x * x for x in range(1_000_000)))   # ~200 байт
```

## Преимущества ленивого вычисления

**1. Постоянная память при любом объёме данных.** Обработка файла в 50 ГБ строка за строкой:

```python
def read_lines(path):
    with open(path, encoding='utf-8') as f:
        for line in f:          # файловый объект сам является итератором
            yield line.rstrip('\n')

errors = (l for l in read_lines('app.log') if 'ERROR' in l)
first_ten = itertools.islice(errors, 10)
```

**2. Бесконечные и потенциально бесконечные последовательности:**

```python
def naturals():
    n = 0
    while True:
        yield n
        n += 1

from itertools import islice
print(list(islice(naturals(), 5)))   # [0, 1, 2, 3, 4]
```

**3. Ранний выход без лишней работы.** Если нужен первый подходящий элемент, генератор не станет вычислять остальные.

**4. Конвейеры обработки.** Генераторы соединяются в цепочки, каждый элемент проходит весь конвейер, не создавая промежуточных списков:

```python
lines      = read_lines('data.csv')
records    = (parse(l) for l in lines)
valid      = (r for r in records if r.is_valid)
normalized = (normalize(r) for r in valid)
for r in normalized:
    save(r)
```

**5. Меньшая задержка до первого результата** — важно для стриминга, потоковых API, отзывчивых интерфейсов.

## Ограничения

**Одноразовость.** После исчерпания генератор пуст:

```python
g = (x for x in range(3))
print(list(g))   # [0, 1, 2]
print(list(g))   # []
```

Нужно пройти дважды — сохраните в список или создайте генератор заново (`itertools.tee` тоже возможен, но буферизует).

**Нет `len()`, индексации и срезов.** Помогает `itertools.islice`, но она проходит элементы последовательно.

**Отложенные ошибки.** Исключение возникнет не при создании генератора, а во время итерации — сложнее отлаживать и обрабатывать.

**Замыкание над изменяемым состоянием.** Генераторное выражение вычисляет **первый** итерируемый объект сразу, а остальные — лениво; ссылки на внешние переменные разрешаются во время итерации:

```python
xs = [1, 2, 3]
g = (x * factor for x in xs)
factor = 10
print(list(g))    # [10, 20, 30] — factor взят на момент итерации
```

**Накладные расходы на элемент.** Для маленьких коллекций, по которым нужно ходить многократно, список быстрее.

**Не сериализуются** (нельзя pickle), не работают напрямую с `random.choice`, `sorted` требует полного разворачивания.

**Проблема с отложенным закрытием ресурсов.** Если генератор не исчерпан, `finally`/`with` внутри выполнится только при сборке мусора или явном `.close()`.

## Продвинутые возможности

**`yield from`** — делегирование другому итератору:

```python
def chain(*iterables):
    for it in iterables:
        yield from it
```

**Двусторонняя связь через `send()`** — генератор как сопрограмма:

```python
def accumulator():
    total = 0
    while True:
        value = yield total     # получает значение из send()
        total += value

acc = accumulator()
next(acc)          # запуск до первого yield
print(acc.send(10))  # 10
print(acc.send(5))   # 15
```

Также есть `throw()` (бросить исключение внутрь) и `close()` (завершить, вызвав `GeneratorExit`).

**Возврат значения:** `return value` внутри генератора помещает значение в `StopIteration.value` и доступен как результат `yield from`.

**Асинхронные генераторы:**

```python
async def fetch_pages(urls):
    for url in urls:
        yield await http_get(url)

async for page in fetch_pages(urls):
    process(page)
```

## Модуль itertools

Стандартная библиотека ленивых инструментов: `count`, `cycle`, `repeat` (бесконечные), `chain`, `islice`, `takewhile`, `dropwhile`, `groupby`, `product`, `permutations`, `combinations`, `accumulate`, `tee`, `zip_longest`, `batched` (3.12+). Их комбинирование покрывает большинство задач потоковой обработки.

## Когда что выбирать

**Генератор:** большие или неизвестного размера данные; поток/файл/сеть; один проход; конвейер преобразований; бесконечная последовательность; экономия памяти критична.

**Список:** нужны длина, индексация, срезы, сортировка; данные нужны многократно; коллекция мала; требуется передавать структуру дальше как значение.

Практическое правило: функции, возвращающие данные, лучше делать генераторами — вызывающий всегда может обернуть результат в `list()`, а обратное преобразование невозможно без потери преимуществ.
