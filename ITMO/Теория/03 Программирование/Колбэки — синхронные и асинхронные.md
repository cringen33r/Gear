## Главное различие: синхронность

**Колбэки методов массива выполняются синхронно.** `forEach`, `map`, `filter`, `reduce`, `some`, `every`, `find`, `sort` вызывают функцию немедленно, в том же тике, в рамках текущего кадра стека. К моменту возврата метода вся работа завершена.

**Колбэк `setTimeout` выполняется асинхронно.** Он регистрируется в среде исполнения и попадает в **очередь макрозадач**; выполнится только после того, как опустеет стек вызовов и очередь микрозадач (см. блок 02, вопрос 6).

```js
console.log('start');
[1, 2].forEach(n => console.log('forEach', n));
setTimeout(() => console.log('timeout'), 0);
console.log('end');

// start, forEach 1, forEach 2, end, timeout
```

## Различие в аргументах

**Методы массива** передают колбэку **три аргумента**: `(element, index, array)`. У `reduce` сигнатура другая: `(accumulator, element, index, array)`.

```js
['a', 'b'].forEach((el, i, arr) => console.log(el, i, arr));
// a 0 ['a','b'] ; b 1 ['a','b']
```

**setTimeout** вызывает функцию **без аргументов**, но дополнительные параметры после задержки передаются в колбэк:

```js
setTimeout((a, b) => console.log(a + b), 100, 1, 2);   // 3
```

Классическая ловушка на несовпадении сигнатур:

```js
['1', '7', '11'].map(parseInt);   // [1, NaN, 3]
```

`map` передаёт индекс вторым аргументом, а `parseInt(string, radix)` принимает его как систему счисления: `parseInt('7', 1)` → NaN, `parseInt('11', 2)` → 3. Правильно: `.map(Number)` или `.map(s => parseInt(s, 10))`.

## Возвращаемое значение

Методы массива **используют** возврат колбэка: `map` собирает результаты, `filter` трактует его как булево, `reduce` — как новый аккумулятор, `sort` — как результат сравнения. `forEach` возврат игнорирует.

`setTimeout` возврат колбэка **полностью игнорирует**. Сам `setTimeout` возвращает идентификатор таймера для `clearTimeout`.

## Обработка ошибок

Ошибка в колбэке метода массива **распространяется вверх по стеку** и ловится внешним `try/catch`:

```js
try { [1].forEach(() => { throw new Error('x'); }); } catch (e) { /* поймано */ }
```

Ошибка в колбэке `setTimeout` возникает в другом тике, когда `try` уже завершён, — она **не будет поймана** и станет глобальной необработанной ошибкой:

```js
try { setTimeout(() => { throw new Error('x'); }, 0); } catch (e) { /* НЕ поймано */ }
```

Ловить нужно внутри самого колбэка либо через `window.onerror`.

## Контекст `this`

Методы массива принимают **второй аргумент `thisArg`**:

```js
[1, 2].forEach(function (n) { console.log(this.prefix, n); }, { prefix: '>' });
```

У `setTimeout` такого параметра нет. В нестрогом режиме `this` внутри колбэка — глобальный объект (`window`), в модулях/строгом режиме — `undefined`. Стрелочные функции берут `this` из лексического окружения, что обычно и требуется.

## Прерывание

Из `forEach` **нельзя выйти досрочно**: `break` — синтаксическая ошибка, `return` завершает только текущую итерацию. Нужен ранний выход — используйте `for...of`, `some`/`every` (они останавливаются при первом true/false) или `find`.

Таймер отменяется до срабатывания: `clearTimeout(id)`.

## Асинхронные колбэки в методах массива

Метод массива **не умеет ждать** промис:

```js
[1, 2, 3].forEach(async (n) => { await save(n); });
console.log('готово');  // выведется ДО завершения сохранений; ошибки потеряются
```

Правильные варианты:

```js
for (const n of arr) await save(n);           // строго последовательно
await Promise.all(arr.map(save));             // параллельно
await Promise.allSettled(arr.map(save));      // параллельно, без прерывания на ошибке
```

`map` с async-колбэком возвращает **массив промисов** — это как раз то, что нужно передать в `Promise.all`.

## Практическое следствие: разбиение долгой работы

Синхронный `forEach` по большому массиву **блокирует главный поток** и замораживает интерфейс. Чтобы этого избежать, работу разбивают на части, уступая управление браузеру через `setTimeout(..., 0)`, `scheduler.yield()` или перенося вычисления в Web Worker.

## Сводная таблица

| Критерий | Колбэк метода массива | Колбэк setTimeout |
|---|---|---|
| Момент выполнения | немедленно, синхронно | позже, макрозадача |
| Аргументы | `(element, index, array)` | нет (или переданные после delay) |
| Возврат | используется методом | игнорируется |
| try/catch снаружи | ловит | **не ловит** |
| `this` | настраивается `thisArg` | window / undefined |
| Досрочный выход | нет (у forEach) | `clearTimeout` |
| Число вызовов | по числу элементов | один раз (`setInterval` — многократно) |
| Блокирует поток | да | нет |
