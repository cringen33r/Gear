## Ссылочная семантика

В JavaScript примитивы (number, string, boolean, null, undefined, symbol, bigint) копируются **по значению**, а объекты, массивы, функции — **по ссылке**.

```js
let a = { x: 1 };
let b = a;        // копируется ссылка, не объект
b.x = 2;
console.log(a.x); // 2 — это один и тот же объект
console.log(a === b); // true
```

## Поверхностное копирование (shallow copy)

Создаётся **новый объект верхнего уровня**, но значения свойств копируются как есть. Для примитивов это настоящие копии, для вложенных объектов — **копии ссылок**, то есть вложенные структуры остаются общими.

```js
const original = { name: 'Alice', address: { city: 'СПб' }, tags: ['a', 'b'] };
const shallow = { ...original };

shallow.name = 'Bob';
console.log(original.name);          // 'Alice' — верхний уровень независим

shallow.address.city = 'Москва';
console.log(original.address.city);  // 'Москва' — вложенный объект общий!

shallow.tags.push('c');
console.log(original.tags);          // ['a','b','c'] — массив тоже общий
```

Способы поверхностного копирования:

```js
const c1 = { ...obj };                       // spread
const c2 = Object.assign({}, obj);           // assign
const c3 = [...arr];                          // spread для массива
const c4 = arr.slice();                       // slice
const c5 = Array.from(arr);
const c6 = Object.fromEntries(Object.entries(obj));
const c7 = structuredClone(obj);             // ← это уже глубокое, см. ниже
```

Нюанс: spread и `Object.assign` копируют только **собственные перечислимые** свойства, включая символьные; они **вызывают геттеры** (сохраняется результат, а не сам геттер) и **теряют прототип**, дескрипторы (writable, enumerable, configurable) и не копируют неперечислимые свойства. Для точного копирования с дескрипторами:

```js
const exact = Object.create(
  Object.getPrototypeOf(obj),
  Object.getOwnPropertyDescriptors(obj)
);
```

## Глубокое копирование (deep copy)

Рекурсивно копируются все уровни вложенности; результат полностью независим от оригинала.

**1. `structuredClone()` — современный стандарт** (браузеры и Node 17+):

```js
const deep = structuredClone(original);
```

Поддерживает: вложенные объекты и массивы, `Date`, `RegExp`, `Map`, `Set`, `ArrayBuffer`, типизированные массивы, `Blob`, `File`, `Error`, **циклические ссылки**.

Не поддерживает: **функции** и методы (бросает `DataCloneError`), DOM-узлы, символы как ключи, прототипы классов (объект становится обычным), дескрипторы свойств, геттеры/сеттеры (сохраняется вычисленное значение).

**2. `JSON.parse(JSON.stringify(obj))` — старый приём**, работает, но с серьёзными ограничениями:

```js
const bad = JSON.parse(JSON.stringify({
  date: new Date(),        // → строка
  undef: undefined,        // → свойство исчезает
  fn() {},                 // → исчезает
  sym: Symbol('s'),        // → исчезает
  inf: Infinity,           // → null
  nan: NaN,                // → null
  map: new Map([[1, 2]]),  // → {}
  set: new Set([1]),       // → {}
  big: 10n,                // → TypeError
}));
```

Плюс: **циклические ссылки вызывают исключение**, `BigInt` — тоже; производительность хуже, чем у `structuredClone`. Использовать можно только для заведомо JSON-совместимых данных.

**3. Библиотеки** — `lodash.cloneDeep` (обрабатывает функции-ссылки, циклы, прототипы), `rfdc`, `immer` (структурное разделение с иммутабельным API).

**4. Ручная рекурсия** — когда нужен контроль:

```js
function deepClone(value, seen = new WeakMap()) {
  if (value === null || typeof value !== 'object') return value;
  if (seen.has(value)) return seen.get(value);          // защита от циклов

  let clone;
  if (Array.isArray(value)) clone = [];
  else if (value instanceof Date) return new Date(value);
  else if (value instanceof Map) clone = new Map();
  else if (value instanceof Set) clone = new Set();
  else clone = Object.create(Object.getPrototypeOf(value));

  seen.set(value, clone);

  if (value instanceof Map) {
    for (const [k, v] of value) clone.set(deepClone(k, seen), deepClone(v, seen));
  } else if (value instanceof Set) {
    for (const v of value) clone.add(deepClone(v, seen));
  } else {
    for (const key of Reflect.ownKeys(value)) clone[key] = deepClone(value[key], seen);
  }
  return clone;
}
```

## Почему это важно для вложенных структур

**1. Неожиданные мутации.** Функция, «безопасно» скопировавшая объект поверхностно и изменившая вложенное поле, испортит данные вызывающего кода. Такие баги трудно локализовать, потому что причина и симптом находятся в разных модулях.

**2. React и другие библиотеки со сравнением по ссылке.** React решает, нужно ли перерисовать компонент, сравнивая ссылки (`Object.is`). Мутация вложенного объекта не меняет ссылку — интерфейс не обновится:

```js
// НЕ вызовет ререндер
setState(prev => { prev.user.name = 'Bob'; return prev; });

// правильно — новые ссылки на изменённом пути
setState(prev => ({ ...prev, user: { ...prev.user, name: 'Bob' } }));
```

Обратите внимание: копировать нужно **только путь до изменяемого узла**, а не всё дерево — это и есть структурное разделение (structural sharing), которое автоматизирует Immer.

**3. Общее изменяемое состояние.** Значения по умолчанию, конфиги, «эталонные» объекты, случайно изменённые потребителем, — источник плавающих багов.

**4. Кеши и снимки.** Сохранённое в кеш значение должно быть независимой копией, иначе последующая мутация «задним числом» изменит содержимое кеша.

**5. Undo/redo, сравнение до/после, отправка на сервер.** Нужны настоящие снимки состояния.

## Когда достаточно поверхностной копии

- Объект плоский (все значения — примитивы).
- Вложенные объекты по договорённости неизменяемы.
- Нужна производительность: глубокое копирование больших структур дорого по времени и памяти.

## Альтернатива копированию — иммутабельность

Если данные не мутируются по соглашению, необходимость в глубоком копировании отпадает. Инструменты: `Object.freeze` (поверхностная заморозка), TypeScript `readonly`/`as const`, библиотеки Immer и Immutable.js, а также функциональный стиль обновления через spread. Иммутабельные обновления дают дешёвое сравнение по ссылке, простую отладку и предсказуемость.
