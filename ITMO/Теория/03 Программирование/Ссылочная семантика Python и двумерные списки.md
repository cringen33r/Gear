## Проблема

```python
grid = [[0] * 3] * 2
print(grid)          # [[0, 0, 0], [0, 0, 0]] — выглядит правильно

grid[0][0] = 5
print(grid)          # [[5, 0, 0], [5, 0, 0]] — изменились обе строки!
```

## Почему так происходит

Оператор `*` для списка **не копирует элементы**, а повторяет **ссылки** на них.

Разбор по шагам:

1. `[0] * 3` создаёт `[0, 0, 0]`. Здесь всё в порядке: `0` — неизменяемое целое, а операции над ним создают новые объекты.
2. `[ [0,0,0] ] * 2` создаёт новый внешний список из **двух ссылок на один и тот же внутренний список**.

Проверка:

```python
grid = [[0] * 3] * 2
print(id(grid[0]) == id(grid[1]))   # True — один объект
print(grid[0] is grid[1])           # True
```

Изменение `grid[0][0] = 5` мутирует единственный внутренний список, а он «виден» по обеим ссылкам.

Тот же эффект в цикле:

```python
row = [0] * 3
grid = []
for _ in range(2):
    grid.append(row)     # добавили одну и ту же ссылку дважды
```

## Почему `[0] * 3` работает «правильно»

Потому что `int` неизменяем. `grid[0][0] = 5` не мутирует число 0 — оно заменяется на другой объект по индексу. Мутировать можно только изменяемые объекты, поэтому проблема проявляется, лишь когда повторяемый элемент — список, словарь, множество или экземпляр класса.

Тот же класс ошибки:

```python
rows = [{}] * 3
rows[0]['a'] = 1
print(rows)          # [{'a': 1}, {'a': 1}, {'a': 1}]
```

## Правильные способы

**1. Списковое включение (canonical):**

```python
rows, cols = 2, 3
grid = [[0] * cols for _ in range(rows)]
```

Выражение `[0] * cols` вычисляется **на каждой итерации**, создавая новый список. Это стандартный, самый читаемый вариант.

**2. Явный цикл:**

```python
grid = []
for _ in range(rows):
    grid.append([0] * cols)
```

**3. Трёхмерный и более:**

```python
cube = [[[0] * z for _ in range(y)] for _ in range(x)]
```

**4. `copy.deepcopy` для шаблона:**

```python
import copy
template = [0, 0, 0]
grid = [copy.deepcopy(template) for _ in range(rows)]
```

**5. Словарь с кортежем-ключом** — удобно для разреженных сеток:

```python
from collections import defaultdict
grid = defaultdict(int)
grid[(0, 1)] = 5
```

**6. NumPy** — для численных задач:

```python
import numpy as np
grid = np.zeros((rows, cols), dtype=int)
grid[0, 0] = 5          # никаких проблем с общими ссылками
```

NumPy даёт компактное хранение, векторизованные операции и настоящую двумерность. Но осторожно: срез NumPy — это **представление (view)**, а не копия; для копии нужен `.copy()`.

## Ссылочная семантика Python

Ключевая модель: **имена связываются с объектами**; присваивание копирует ссылку, а не объект.

```python
a = [1, 2, 3]
b = a                # одна ссылка
b.append(4)
print(a)             # [1, 2, 3, 4]

c = a[:]             # поверхностная копия
c = list(a)          # то же
c = copy.copy(a)     # то же
c = copy.deepcopy(a) # глубокая копия
```

Поверхностная копия двумерного списка **не спасает**:

```python
grid = [[0] * 3 for _ in range(2)]
shallow = grid[:]           # копия внешнего списка
shallow[0][0] = 9
print(grid[0][0])           # 9 — внутренние списки общие
deep = copy.deepcopy(grid)  # вот теперь независимо
```

## Как проверять

```python
print(grid[0] is grid[1])                    # должно быть False
print([id(r) for r in grid])                 # все id разные
print(len({id(r) for r in grid}) == len(grid))
```

## Смежные проявления той же ошибки

**Изменяемый аргумент по умолчанию** (см. вопрос 8):

```python
def add(item, target=[]):   # один список на все вызовы
    target.append(item)
    return target
```

**Атрибут класса вместо атрибута экземпляра:**

```python
class Board:
    grid = [[0] * 3 for _ in range(3)]   # общий для всех экземпляров
```

**`dict.fromkeys` с изменяемым значением:**

```python
d = dict.fromkeys(['a', 'b'], [])   # оба ключа ссылаются на ОДИН список
d['a'].append(1)
print(d)   # {'a': [1], 'b': [1]}
# правильно:
d = {k: [] for k in ['a', 'b']}
```

**Копирование объектов со вложенными коллекциями** — нужен `deepcopy` или собственный `__deepcopy__`.

## Общее правило

Всякий раз, когда нужно «n независимых изменяемых объектов», используйте **конструкцию, которая создаёт новый объект на каждой итерации** — списковое включение, цикл, `default_factory`, — и никогда не полагайтесь на умножение списка или повторное использование одной ссылки.
