## Блочная модель

Каждый элемент на странице представлен прямоугольной областью, состоящей из четырёх вложенных зон:

```
┌──────────── margin ────────────┐
│  ┌───────── border ─────────┐  │
│  │  ┌────── padding ─────┐  │  │
│  │  │      content       │  │  │
│  │  └────────────────────┘  │  │
│  └──────────────────────────┘  │
└────────────────────────────────┘
```

- **content** — содержимое (текст, изображение, дочерние элементы); его размер задают `width`/`height`;
- **padding** — внутренний отступ, часть фона элемента, входит в область клика;
- **border** — рамка;
- **margin** — внешний отступ, всегда прозрачный, не входит в фон и в область клика.

## content-box — значение по умолчанию

При `box-sizing: content-box` свойства `width` и `height` задают размер **только области содержимого**. Padding и border **прибавляются** сверху:

```css
.box {
  box-sizing: content-box;   /* по умолчанию */
  width: 200px;
  padding: 20px;
  border: 5px solid;
}
/* Итоговая занимаемая ширина = 200 + 20*2 + 5*2 = 250px */
```

Плюс ещё margin — но он не входит в размер самого элемента, а влияет на расстояние до соседей.

## border-box

При `box-sizing: border-box` свойство `width` задаёт **полную ширину, включая padding и border**; область содержимого вычисляется вычитанием:

```css
.box {
  box-sizing: border-box;
  width: 200px;
  padding: 20px;
  border: 5px solid;
}
/* Занимаемая ширина = ровно 200px; content = 200 - 40 - 10 = 150px */
```

## Зачем различать: практические причины

**1. Предсказуемость сеток.** С `content-box` две колонки по 50% с внутренним отступом переполняют контейнер:

```css
.col { width: 50%; padding: 16px; }   /* content-box → суммарно > 100% → перенос/скролл */
```

С `border-box` `width: 50%` действительно означает половину.

**2. Меньше арифметики.** Не нужно писать `width: calc(50% - 32px)` и пересчитывать при каждом изменении отступов или рамки.

**3. Стабильность при интерактивных состояниях.** Добавление рамки на `:hover` при `content-box` увеличивает элемент и сдвигает соседей; при `border-box` размер не меняется.

**4. Совместимость с UI-библиотеками.** Практически все современные фреймворки (Bootstrap, Tailwind) сбрасывают модель глобально.

Стандартный сброс:

```css
*, *::before, *::after { box-sizing: border-box; }
```

Причина, по которой `content-box` остаётся значением по умолчанию, — обратная совместимость: изменение сломало бы миллионы существующих страниц. Исторически в CSS1 предполагался content-box, а IE до версии 6 в quirks mode использовал border-box — и разработчики со временем признали второй вариант удобнее.

## Что не входит в box-sizing

`box-sizing` **не влияет на margin** — внешние отступы всегда прибавляются к занимаемому месту. Также не влияет на `outline` и `box-shadow`: они рисуются вне потока и не занимают места.

## Схлопывание внешних отступов (margin collapsing)

Вертикальные margin соседних или вложенных блочных элементов **объединяются** в один, равный наибольшему:

```html
<p style="margin-bottom: 20px">A</p>
<p style="margin-top: 30px">B</p>
<!-- расстояние между ними = 30px, а не 50px -->
```

Схлопывание происходит между соседями, между родителем и первым/последним потомком, и у пустых блоков. Оно **не происходит** во flex- и grid-контейнерах, при наличии padding/border между margin, при `overflow` не `visible`, при абсолютном позиционировании и в контекстах форматирования BFC.

Горизонтальные margin не схлопываются никогда.

## Другие свойства размеров

- `min-width` / `max-width`, `min-height` / `max-height` — ограничения; `max-width` побеждает `width`, `min-width` побеждает `max-width`.
- **Ключевые слова размера**: `min-content` (минимально возможная ширина без переполнения), `max-content` (ширина содержимого без переносов), `fit-content` (компромисс).
- `aspect-ratio` — фиксирует пропорции.
- `width: 100%` считается от **content-box родителя**; `width: 100vw` — от ширины окна, включая полосу прокрутки (частая причина горизонтального скролла). Безопаснее `100dvw`/`100%`.
- Единицы: `px`, `%`, `em` (относительно шрифта элемента), `rem` (относительно корневого), `vw`/`vh`/`dvh`/`svh`/`lvh`, `ch`, `fr` (в grid).

## Типы боксов

`display` определяет, как элемент участвует в раскладке:

- `block` — занимает всю доступную ширину, `width`/`height` работают;
- `inline` — в строке; **`width` и `height` игнорируются**, вертикальные padding/margin не влияют на высоту строки;
- `inline-block` — в строке, но размеры работают;
- `flex`, `grid` — контейнеры со своими правилами раскладки;
- `none` — не отображается и не занимает места (в отличие от `visibility: hidden`).

## Отладка

DevTools → Computed → диаграмма блочной модели показывает фактические content/padding/border/margin. Быстрый способ увидеть границы всех элементов:

```css
* { outline: 1px solid rgba(255, 0, 0, .3); }
```

`outline` предпочтительнее `border`, потому что не влияет на раскладку.
