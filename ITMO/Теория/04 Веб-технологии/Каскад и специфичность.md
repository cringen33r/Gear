## Каскад

**Каскад (cascade)** — алгоритм, определяющий, какое из конкурирующих объявлений применится к свойству элемента. Он рассматривает объявления последовательно по критериям; переход к следующему критерию происходит только при равенстве по предыдущему.

Порядок критериев:

**1. Происхождение и важность (origin & importance).** От низшего приоритета к высшему:

1. стили браузера по умолчанию (user agent);
2. пользовательские стили (user);
3. авторские стили (author) — CSS сайта;
4. анимации (`@keyframes`);
5. авторские `!important`;
6. пользовательские `!important`;
7. `!important` браузера;
8. переходы (`transition`) во время выполнения.

Обратите внимание: для `!important` порядок происхождений **инвертируется** — это сделано, чтобы пользователь (например, с нарушением зрения, задавший свои стили) мог переопределить сайт.

**2. Слои каскада (`@layer`).** Современный механизм явного управления приоритетом:

```css
@layer reset, base, components, utilities;   /* порядок = приоритет */

@layer components { .btn { color: blue; } }
@layer utilities  { .text-red { color: red; } }   /* победит независимо от специфичности */
```

Стили вне слоёв имеют приоритет **выше** любого слоя. Для `!important` порядок слоёв тоже инвертируется.

**3. Специфичность селектора** — если происхождение и слой совпали.

**4. Порядок появления** — при равной специфичности побеждает объявление, идущее **последним** в порядке подключения и расположения в файле.

## Специфичность

Специфичность — тройка чисел **(A, B, C)**, где:

- **A** — количество селекторов идентификатора (`#id`);
- **B** — количество классов, атрибутов и псевдоклассов (`.class`, `[type="text"]`, `:hover`, `:not()` считается по содержимому);
- **C** — количество типов элементов и псевдоэлементов (`div`, `::before`).

Сравнение лексикографическое: сначала A, при равенстве B, затем C. **Разряды не переносятся**: 11 классов (0,11,0) всё равно проигрывают одному id (1,0,0).

| Селектор | Специфичность |
|---|---|
| `*` | 0,0,0 |
| `li` | 0,0,1 |
| `ul li` | 0,0,2 |
| `.item` | 0,1,0 |
| `li.item` | 0,1,1 |
| `input[type="text"]` | 0,2,0 |
| `#main` | 1,0,0 |
| `#main .item p` | 1,1,1 |
| inline `style=""` | выше любых селекторов |
| `!important` | вне шкалы специфичности |

Особые случаи:

- `:where()` имеет **нулевую специфичность** — идеально для сбросов и библиотечных стилей, которые должны легко переопределяться;
- `:is()` и `:not()` принимают специфичность **самого сильного** аргумента;
- `:has()` — аналогично `:is()`;
- вложенные селекторы (CSS Nesting) считаются как `:is()`.

```css
:where(.a, #b) p { color: red; }   /* специфичность 0,0,1 */
:is(.a, #b) p    { color: blue; }  /* специфичность 1,0,1 */
```

## `!important`

Флаг, помещающий объявление в отдельную, более приоритетную категорию происхождения:

```css
.btn { color: blue !important; }
```

Он **не увеличивает специфичность**, а меняет уровень каскада. Между двумя `!important` одного происхождения конфликт разрешается обычным образом — по специфичности, затем по порядку.

**Проблемы:**

- Ломает нормальную работу каскада, делая стили непредсказуемыми.
- Порождает «гонку важности»: чтобы переопределить, приходится добавлять ещё один `!important` с большей специфичностью.
- Затрудняет поддержку и отладку.
- Мешает переопределению состояний (`:hover`, `:focus`) и утилитарных классов.

**Оправданные применения:**

- Утилитарные классы, которые обязаны побеждать (`.sr-only`, `.hidden`) — хотя `@layer` решает это чище;
- переопределение стилей стороннего виджета или встроенных `style=""`, до которых нет доступа;
- пользовательские стили и стили доступности;
- отладка (временно).

**Как обойтись без него:** снизить специфичность конкурирующего правила, использовать `@layer`, поднять правило по порядку, применить `:where()` в библиотечных стилях, воспользоваться CSS-переменными для точечной настройки.

## Итоговый алгоритм вычисления значения

1. **Фильтрация** — какие объявления применимы к элементу (селектор совпал, медиа-запрос выполнен).
2. **Каскад** — выбор победителя по происхождению/важности, слою, специфичности, порядку.
3. **Значение по умолчанию** — если объявлений нет: унаследованное (для наследуемых свойств) или начальное.
4. **Вычисленное значение (computed)** — разрешение относительных единиц (`em` → px), ключевых слов.
5. **Использованное значение (used)** — окончательные размеры после раскладки (проценты → пиксели).

DevTools показывают это в панели Styles: перечёркнутые объявления — проигравшие каскаду; вкладка Computed — итоговые значения с указанием источника.

## Практические рекомендации

- Держать специфичность **низкой и плоской**: селекторы из одного класса переопределяются легко.
- Избегать id в CSS — их специфичность почти непреодолима.
- Использовать методологии (BEM) или утилитарный подход, чтобы избежать длинных вложенных селекторов.
- Применять `@layer` для явного управления приоритетом слоёв (reset → base → components → utilities).
- Использовать CSS-переменные для тем и вариаций вместо переопределяющих правил.
- `!important` — крайняя мера, а не инструмент.
