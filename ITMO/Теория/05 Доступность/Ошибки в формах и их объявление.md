## 4. Сообщение об ошибке

Три обязательных условия (WCAG 3.3.1 «Идентификация ошибки», 3.3.3 «Предложение по исправлению»):

**а) Ошибка связана с полем** через `aria-describedby`:

```html
<input id="email" aria-describedby="email-hint email-error" aria-invalid="true">
<p id="email-error" class="error">Введите адрес в формате name@example.com</p>
```

**б) Поле помечено как невалидное** через `aria-invalid="true"` (снимать в `"false"` после исправления).

**в) Сообщение объявляется** при появлении. Для этого контейнер помечается как live region:

```html
<p id="email-error" role="alert">…</p>
```

Контейнер должен существовать в DOM заранее (пустым или с `hidden`), а текст в него **добавляться** — тогда изменение гарантированно отслеживается.

**Текст ошибки должен быть конкретным и подсказывать решение:**

- ❌ «Ошибка», «Неверное значение», «Invalid input»
- ✅ «Введите адрес в формате name@example.com»
- ✅ «Пароль должен содержать минимум 8 символов, сейчас 5»
- ✅ «Дата возврата должна быть позже даты выезда»

**Цвет не единственный признак ошибки** (WCAG 1.4.1): красной рамки недостаточно. Добавьте текст, иконку с доступным именем, изменение формы границы.

## 5. Сводка ошибок при отправке

При отправке формы с несколькими ошибками:

```html
<div role="alert" tabindex="-1" id="error-summary" class="error-summary">
  <h2>Форма содержит 2 ошибки</h2>
  <ul>
    <li><a href="#email">Электронная почта: введите корректный адрес</a></li>
    <li><a href="#pwd">Пароль: минимум 8 символов</a></li>
  </ul>
</div>
```

```js
form.addEventListener('submit', (e) => {
  const errors = validate();
  if (errors.length) {
    e.preventDefault();
    renderSummary(errors);
    document.getElementById('error-summary').focus();   // перевести фокус на сводку
  }
});
```

Сводка размещается **в начале формы**, фокус переводится на неё, ссылки ведут к конкретным полям. Это стандарт, принятый, например, в GOV.UK Design System, и он существенно облегчает исправление при большом количестве полей.

Также стоит обновлять `<title>` страницы или объявлять число ошибок — пользователь скринридера должен сразу понять, что отправка не удалась.
