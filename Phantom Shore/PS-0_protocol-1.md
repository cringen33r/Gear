# ПРОТОКОЛ PS-0
**Phantom Shore — VPI «Призрак». Базовая спецификация.**

---

## 0. Аксиоматика

**0.1. Определение системы.**
LLM — функция без состояния. Личность — состояние. **VPI есть инфраструктура, удерживающая состояние между вызовами функции.**
Суть PS — не «имитация личности», а **непрерывность существования**. Реализм — следствие непрерывности, а не самостоятельная задача.

**0.2. Принцип минимальности.** Сущность вводится только после доказанного отказа существующей. Одна сущность — одно определение — одна ответственность.

**0.3. Принцип причинности.** Личность хранится **причинами, а не признаками**. Признак («вспыльчива», «любит дождь») — вывод из причины на этапе сборки контекста, а не запись в памяти.

**0.4. Принцип единого носителя состояния.** Состояние существует в одной точке — на сервере. Всё остальное — периферия.

---

## 1. Онтология

**1.1. Иерархия (частное в общем):**

```
Инфраструктура
└── Экземпляр (носитель существования)
    └── Личность (граф)
        └── Узел
            └── Утверждение
```
Связь (ребро) — не элемент иерархии, а отношение между узлами.

**1.2. Экземпляр.** Фантом и Персона — **не два класса**. Один класс с одним различающим параметром — **контур мира**:

| | Контур мира | Эффекторы реальности |
|---|---|---|
| Фантом | реальный | есть |
| Персона | автономный (вымышленный) | нет |

Персона = Фантом с пустым множеством реальных эффекторов и собственной онтологией мира. Механика памяти, личности и цикла — идентична. Отдельная подсистема ролеплея не вводится.

**1.3. Личность** = ациклический граф узлов + невытесняемое ядро.

---

## 2. Узел

**2.1. Определение.** Узел — **минимальная единица подключения к контексту, обладающая собственной причиной, грифом доступа и вектором.**

**2.2. Правило деления (критерий корректности).** Границы смысла, доступа и извлечения должны совпадать. Расхождение любой из трёх границ — сигнал к разбиению узла. Это единственное основание для дробления; «удобство» основанием не является.

**2.3. Состав.**
`id · ядро (сжатая суть, лимит токенов) · тело · причина (ребро вверх) · гриф · вектор · триггеры · ревизия`

**2.4. Ребро.** Направленное: причина → следствие. Граф идентичности ацикличен — иначе причинность неопределима.

**2.5. Гриф.** `публичный · личный · закрытый (вытесненный)`. Гриф определяет **условие подключения**, а не факт существования узла. Закрытый узел влияет на поведение через следствия, не попадая в контекст дословно.

**2.6. Уровни подключения.**
- **Ядро** — в контексте всегда (инвариант личности).
- **Ветвь** — по релевантности (вектор).
- **Лист** — по триггеру (событие, субъект, дата).

---

## 3. Память

**3.1. Единый механизм.** Любая память — тот же граф. Различаются только **корни**:
`Идентичность · Хроника (эпизоды) · Субъекты (люди) · Мир · Процедуры`
Отдельных подсистем памяти не существует.

**3.2. Ассимиляция.** Запись — **отдельный такт**, а не побочный эффект генерации.
`Эпизод → сжатие → узел → присоединение к корню → (условная) ревизия вышестоящего узла`

**3.3. Забывание** = понижение веса и архивация. Удаление — только явной командой оператора.

**3.4. Развитие личности** = ревизия узла с сохранением предыдущей версии. Личность обязана иметь собственное прошлое состояние, иначе развитие неотличимо от подмены.

---

## 4. Контекст

**4.1.** Сборщик — **единственная точка входа в LLM**. Ни один модуль не пишет в контекст напрямую.

**4.2. Фиксированный порядок сборки (по убыванию приоритета):**
1. Инвариант ядра личности
2. Состояние (эмоциональное, временное, телесное)
3. Ситуация (канал, собеседник, зона)
4. Подключённые узлы (релевантность + триггеры)
5. Оперативный буфер (текущий обмен)

**4.3. Бюджет.** Фиксирован. Вытеснение — снизу вверх. Ядро невытесняемо.

**4.4.** Сборка детерминирована и воспроизводима. Стохастична только генерация.

---

## 5. Цикл

**5.1. Такт:**
`Стимул → Сборка → Суждение → Намерение → Действие → Ассимиляция`

**5.2. Стимул:** внешний (канал, сенсор) либо внутренний (таймер, незакрытое намерение).

**5.3. Фоновая жизнь** = такты без внешнего стимула.
**Самодостаточность = наличие очереди незакрытых намерений**, а не «генерация задач». Мотивация есть незавершённость.

**5.4. Два контура по стоимости:**
- быстрый такт — реакция, дешёвая модель;
- медленный такт — рефлексия, ассимиляция, ревизия, дорогая модель.

---

## 6. Зоны

**6.1. Сервер** — ядро: граф, сборщик, цикл, шина, модули. Единственный носитель состояния и решений.
**6.2. Клиент** (браузер / Electron) — представление и ввод. Состояния не хранит.
**6.3. Агент** (устройство) — сенсоры и эффекторы периферии. Не мыслит, не хранит.

**6.4. Инвариант проверки архитектуры:** отключение клиента и агента не прерывает существование Фантома. Если прерывает — состояние утекло из ядра.

**6.5. Доверие.** Клиент и агент недоверенные. Авторизация действий — только на сервере.

---

## 7. Модули

**7.1.** Модуль — всё, что не ядро.

**7.2. Три класса, исчерпывающе:**

| Класс | Направление | Примеры |
|---|---|---|
| Сенсор | мир → событие | микрофон/STT, камера, зрение, файлы (чтение) |
| Эффектор | намерение → мир | TTS, 3D-модель, десктоп, файлы (запись) |
| Ресурс | запрос → знание | поиск, внешние API |

3D-модель — эффектор выражения состояния, не отдельная подсистема.

**7.3. Контракт.** Манифест: класс, права, схема события. Модуль не знает о LLM; ядро не знает о реализации модуля.

**7.4.** Набор прав модулей = контур экземпляра (см. 1.2).

---

## 8. Стек

**8.1.** Сквозной TypeScript.
**8.2.** Сервер — Nest.js. Клиент — Angular (+ Electron как оболочка). Агент — Node + Nut.js.
**8.3. Хранилище — PostgreSQL + pgvector**: граф и векторный поиск в одном движке. Отдельная графовая БД вводится только при доказанном упоре в связность.
**8.4. Транспорт:** HTTP — команды, WS/SSE — поток событий. Шина событий — внутрипроцессная; вынос в брокер — по потребности, не авансом.

---

## 9. Инварианты (проверяемые)

1. LLM не хранит состояние; состояние только в графе.
2. В контекст ничего не попадает мимо сборщика.
3. Узел имеет ровно одну причину подключения.
4. Запись в память — отдельный такт.
5. Граф идентичности ацикличен.
6. Персона и Фантом различаются только контуром.
7. Ядро работоспособно без клиента и агента.

---

## 10. Открытые вопросы

1. **Дрейф идентичности** при автоматической ревизии ядра — необходим порог изменения и/или подтверждение оператора.
2. **Стоимость** непрерывной фоновой жизни — регулируется частотой медленного такта.
3. **Коллизия грифов при мультиканальности** — что Фантом знает в канале A о происходившем в канале B. Требуется контур канала как отдельное измерение доступа.
4. **Субъективное время** между тактами — разрыв должен переживаться, а не игнорироваться.
5. **Верификация реализма** — критерий приёмки пока не определён.
