

Клиент-серверный протокол передачи данных, статeless — то есть не хранит состояние между запросами.

**Клиенты:** user-agent (браузер, прокси, кроулеры).

**Расширяемость:** через заголовки, включая кастомные (`X-...`).

**Особенности версий:**

- **HTTP/0.9** — примитивный протокол, запрос состоит из одной строки с GET без указания версии.
    
- **HTTP/1.0** — базовая версия с заголовками, введён заголовок `Content-Type`.
    
- **HTTP/1.1** — стандартизация и развитие протокола. Добавлен пайплайн (асимметричная отправка запросов). Заголовок `Host` позволил поддерживать виртуальный хостинг — размещение нескольких доменов на одном сервере.
    
- **HTTP/2** и выше — поддерживают единое соединение для множества запросов (мультиплексирование).

# REST (Representational State Transfer)

Архитектурный стиль проектирования сетевых API, направленный на простоту и масштабируемость обмена данными.

Основные принципы:

1. **Клиент-серверная модель** — чёткое разделение ответственности.
    
2. **Stateless** — каждый запрос содержит всю необходимую информацию, сервер не хранит состояние между запросами.
    
3. **Кеширование** — поддерживается на уровне клиента или прокси, чтобы снизить нагрузку.
    
4. **Единообразие интерфейса** — упрощает взаимодействие и интеграцию:
    
    1. Чёткая идентификация ресурсов (через URI).
        
    2. Ресурсы отделены от представления (можно запрашивать данные в формате JSON, XML и т.д.).
        
    3. Манипуляция ресурсами через их представление (клиент может изменять, удалять ресурсы).
        
    4. Каждое сообщение (запрос/ответ) содержит всю информацию для его обработки без дополнительного контекста.
        
    5. **HATEOAS** (Hypermedia As The Engine Of Application State) — сервер в ответе отдаёт не только данные, но и ссылки на возможные действия с ресурсом, позволяя клиенту динамически ориентироваться в API без жёсткого хардкода.
        
    6. Наличие слоёв — клиент не обязан знать, с каким именно уровнем сервера он взаимодействует (балансировщик, кэш и т.д.).
        
    7. **Код по требованию (Code on Demand)** — необязательное правило, позволяющее серверу отправлять исполняемый код клиенту для расширения его функциональности.

# Апплет

Несамостоятельный компонент программного обеспечения, работающий внутри полнофункционального приложения.

Предназначен для узкой задачи, не имеет самостоятельной ценности вне базового приложения.
