# MDN (общее)

## Типы MIME

### Основные категории

- **Discrete** — одиночные файлы
    
- **Multipart** — несколько файлов в одной транзакции или несколько компонентов одного ресурса
    

### Дискретные типы

1. **application**  
    Все ресурсы, не подпадающие под другие категории. Включает исполняемые файлы и бинарные данные, требующие специфической интерпретации.  
    Пример: `application/octet-stream` — сырые данные.
    
2. **audio**
    
3. **example**  
    Используется только в примерах как плейсхолдер.
    
4. **font**
    
5. **image**
    
6. **text**
    
7. **video**
    

### Мультипарты

1. **message**  
    Узкоспециализированное применение при пересылке писем и сообщений.
    
2. **multipart**  
    Подтипы:
    

	- `multipart/form-data` — используется в формах
    
	- `multipart/byterange` — передача неполного содержимого (`206 Partial Content`, применяется редко)
    

### Наиболее важные типы

- `text/plain`
    
- `text/css`
    
- `text/html`
    
- `text/javascript`
    
- `application/json`
    
- `image/svg+xml` — для SVG
    

# Атака путаницы MIME-типа

## MIME-сниффинг

Алгоритм агентов для определения MIME-типа ресурса по содержимому, чаще всего по сигнатурам (магическим числам).

- Ранее использовался в режиме совместимости (quirks-mode)
    
- Сейчас применяется стандарт WHATWG ["MIME sniffing"](https://mimesniff.spec.whatwg.org/)
    

### Проблемные случаи

Если ресурс в элементе с `src`:

- не содержит MIME-типа,
    
- имеет неожиданный для элемента MIME-тип (например, `image/jpeg` в `<script>`),
    
- имеет неопределённые типы: `text/plain`, `application/octet-stream`  
    → запускается MIME-сниффинг.
    

> Современные браузеры блокируют выполнение скриптов с MIME-типами изображений (например, `image/jpeg`, `image/gif`).  
> Однако [атака с подменой MIME-типа](https://csplite.com/ru/csp326/?rnd=6839815499d5f#githubcom) до сих пор возможна в Midori, IE 11, Safari 10.1.2 и, конечно, в IE 8.

Если на сайте есть [XSS-уязвимость](https://csplite.com/ru/csp16/#attack_XSS), возможно [обойти CSP](https://csplite.com/ru/csp320/#bypass_CSP), так как скрипт исполняется с происхождением `self`.

### Поведение браузеров

MIME-сниффинг активируется, если:

1. MIME-тип отсутствует
    
2. MIME-тип не соответствует элементу (`<script>`, `<img>`, и т.п.)
    
3. MIME-тип является неопределённым (`text/plain`, `application/octet-stream`)  
    Пример реализации сниффера:  
    [Chromium MIME Sniffer](https://source.chromium.org/chromium/chromium/src/+/refs/tags/118.0.5981.4:net/base/mime_sniffer.cc)
    

## Сценарий атаки

1. Злоумышленник загружает файл с некорректным расширением (например, изображение со встроенным скриптом).
    
2. Сервер сохраняет файл без проверки содержимого и MIME-типа.
    
3. При запросе сервер не указывает MIME-тип.
    
4. Агент проводит MIME-сниффинг и исполняет скрипт как код.
    

## Методы защиты

1. **Изоляция пользовательского контента**  
    Хранение загруженных файлов на отдельном домене/поддомене, открытом только в `img-src`, но не в `script-src`.  
    → [CORS](https://csplite.com/ru/csp150/#CORS) ограничит доступ внедрённого скрипта к основному домену.
    
2. **Ограничение `script-src`**
    

- Исключение `'self'`
    
- Разрешение скриптов только через `nonce-<base64-value>` или `<hash-algorithm>-<base64-value>`
    

3. **Указание MIME-типа и запрет сниффинга**
    

- Явно указывать MIME-тип
    
- Заголовок: `X-Content-Type-Options: nosniff`
    

4. **Проверка содержимого**  
    Сравнивать реальное содержимое файла с его MIME-типом при загрузке на сервер.
