НЕЛЬЗЯ ПУТАТЬ КОНТЕКСТ И `this`.

Перед выполнением кода создаётся контекст который содержит:
1. ThisBinding
2. LexicalEnvironment
3. VariableEnvironment

`this` определяется в момент **вызова** метода, указывая на связанный объект.
```ts
class.method() -> this = class
func = class.method
func() -> this = window
```

| Структура            | Когда создаётся     | Что хранит                          | Роль                                       |
| -------------------- | ------------------- | ----------------------------------- | ------------------------------------------ |
| Lexical Environment  | во время объявления | ссылки на внешние области видимости | поиск переменных (scope chain)             |
| Variable Environment | во время выполнения | локальные переменные и функции      | хранение и обновление значений в контексте |
Tail Call - функция, которая сразу же возвращает другую функцию.
## Причина потери контекста
Причина в том, что при передаче метода как коллбек или при присвоении его переменной при выполнении код не видит объект откуда мы вызываем метод.
# Движок и хост-окружение
Выполнение JS зависит от двух кусков софта - движка и хоста.
Движок - реализация ECMA, который парсит код и выполняет его. Хост-окружение позволяет получать доступ к конкретному окружению и его ресурсам. Например, на странице хостом выступает DOM, на сервере - Node.js.

# Событийный цикл
Механизм, позволяющий симулировать многопоточность в единопотоковом JS.
Порядок выполнения (одной итерации цикла):
Таска => микротаски таски => рендеринг

Истинную многопоточность представляют воркеры.

Событийный цикл как и глобальные объекты трех видов - для окна, воркера и ворклета.
# Агент
Автономный исполнитель кода, содержащий:
1. Куча - ну куча это куча, неструктурированная область памяти
2. Очередь тасков - она же событийный цикл. Механизм, позволяющий выполнять код асинхронно в единопотоковом JS
3. Стек контекстов - колстек, массив

Агент аналогичен потоку. Агентом может являться набор окон, или же воркеры (для каждого свой агент)

# Область (realm)
Каждый агент имеет несколько областей, которые по сути являются глобальным объектов (Window, WorkerGlobalScope или WorkletGlobalScope). Область это причина, по которой требуются методы типа `Array.isArra()`, поскольку массив созданный в другой области будет иметь другой прототип, потому `instanceof Array` вернет `false`.

Содержит:
1. Встроенные объекты
2. Глобальные переменные

# Использование микротасков
Необходимы для того, чтобы выполнить код сразу после завершения контекста выполнения но до срабатывания тасков (слушатели, таймауты, обработчики и тд).
