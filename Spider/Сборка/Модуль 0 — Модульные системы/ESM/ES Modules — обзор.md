ES Modules (ESM, ECMAScript Modules) — единственная модульная система, встроенная в **сам язык**. Стандартизирована в ES2015, реализована в браузерах к 2017 году и в Node.js к версии 12+. Все предыдущие форматы — [[CommonJS]], [[AMD и RequireJS]], [[UMD]] — были соглашениями поверх языка; ESM определён в спецификации ECMAScript и HTML.

# Что именно стандартизировали

Три вещи, которых раньше не было ни у кого одновременно:

**1. Синтаксис вместо функций.** `import`/`export` — грамматические конструкции, а не вызовы. Движок разбирает их на этапе парсинга, до выполнения. См. [[Синтаксис импортов и экспортов]].

**2. Статическая структура.** Список импортов и экспортов модуля известен **до того, как выполнится хоть одна строка**. Из этого растут tree shaking, HMR, автодополнение в IDE и проверка «такого экспорта нет» на этапе сборки. См. [[Статическая структура ESM]].

**3. Разделение загрузки и выполнения.** Граф сначала целиком строится и связывается, и только потом выполняется. См. [[Фазы загрузки ESM]].

# Отличия от CommonJS: сводка

| | CommonJS | ESM |
|---|---|---|
| Синтаксис | `require()` / `module.exports` | `import` / `export` |
| Природа | функция, вызывается в рантайме | синтаксис, разбирается при парсинге |
| Расположение | где угодно | верхний уровень (динамика — через `import()`) |
| Спецификатор | любое выражение | только строковый литерал |
| Загрузка | синхронная | асинхронная |
| Что импортируется | копия значения на момент вызова | живая ссылка на ячейку ([[Live bindings]]) |
| Изменяемость импорта | можно присвоить | только чтение, `TypeError` |
| Strict mode | нет по умолчанию | всегда |
| `this` на верхнем уровне | `module.exports` | `undefined` |
| `__dirname`, `__filename` | есть | нет, вместо них [[import.meta]] |
| Циклы | частично заполненный объект | TDZ и `ReferenceError` |
| Tree shaking | практически невозможен | возможен |

Каждая строка таблицы — потенциальная поломка при миграции. Практический разбор: [[ESM и CommonJS — взаимодействие]].

# Минимальный пример

```js
// math.js
export function add(a, b) { return a + b; }
export const PI = 3.14159;
export default function multiply(a, b) { return a * b; }
```

```js
// app.js
import multiply, { add, PI } from './math.js';
import * as math from './math.js';

console.log(add(1, 2), multiply(2, 3), math.PI);
```

Важная деталь для браузера: расширение `.js` в спецификаторе **обязательно**. Браузер не «дописывает» расширения и не ищет `index.js` — это делали сборщики, приучив к обратному. Подробнее в [[Спецификаторы модулей]].

# Свойства, которые нужно знать наизусть

**Всегда strict mode.** Никаких `with`, `arguments.callee`, неявных глобалей. Присваивание необъявленной переменной — `ReferenceError`, а не создание глобали.

**Собственная область видимости.** Верхнеуровневые `var`/`let`/`const`/`function` не попадают в `window`. Чтобы намеренно опубликовать глобаль, нужно явно `globalThis.x = ...`.

**Отложенное выполнение.** `<script type="module">` не блокирует парсер, ведёт себя как `defer`. См. [[Модули в браузере — script type=module]].

**Выполняется ровно один раз.** Сколько бы модулей ни импортировало `./math.js`, тело выполнится однократно, результат кэшируется. См. [[Реестр модулей и singleton-семантика]].

**Импорты — read-only.** `import { add } from './math.js'; add = 1;` даёт `TypeError`. Модуль-владелец при этом может менять своё значение, и импортёр это увидит — см. [[Live bindings]].

**Импорты «поднимаются».** Все зависимости загружаются и выполняются до тела текущего модуля, независимо от того, где написан `import`.

# Что ESM дал сборке

Практический смысл всего стандарта для нашей работы:

- **Tree shaking.** Известно, какие именно имена импортируются, значит остальное можно удалить (при отсутствии побочных эффектов — см. [[Побочные эффекты модулей]]).
- **Code splitting.** [[Динамический import()]] — стандартная точка разрыва графа, понятная любому бандлеру.
- **HMR.** Точный граф зависимостей позволяет заменить один модуль, не перезагружая страницу.
- **Dev-сервер без бандлинга.** Vite в dev отдаёт модули по одному через нативный ESM браузера — это возможно только потому, что браузер сам умеет разрешать и связывать граф.
- **Кросс-инструментальная совместимость.** ESM понимают все: браузер, Node, Deno, Bun, webpack, Rollup, esbuild.

# Чего ESM не решает сам по себе

Нативного ESM недостаточно для продакшена — это важно понимать, чтобы не считать бандлер пережитком:

- нет поддержки bare-спецификаторов без [[Import maps]];
- водопад запросов на глубоком графе (см. [[Предел нативного ESM в браузере]]);
- нет минификации, хеширования имён, инлайна ассетов;
- половина npm до сих пор в CJS.
