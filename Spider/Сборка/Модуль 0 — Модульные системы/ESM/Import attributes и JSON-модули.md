Import attributes — синтаксис `with { ... }` в операторе импорта, позволяющий передать загрузчику дополнительную информацию о том, **как трактовать импортируемый ресурс**. Основное применение сегодня — импорт JSON и CSS без плагинов сборщика.

# Синтаксис

```js
import data from './data.json' with { type: 'json' };

// динамическая форма
const data = await import('./data.json', { with: { type: 'json' } });

// ре-экспорт
export { default as config } from './config.json' with { type: 'json' };
```

## Про устаревший `assert`

Раньше предложение называлось Import Assertions и использовало ключевое слово `assert`:

```js
import data from './data.json' assert { type: 'json' };   // устарело
```

Комитет переименовал его в `with` из-за смены семантики: `assert` подразумевал «проверь, что это JSON», `with` — «интерпретируй это как JSON» (атрибут может влиять на то, как ресурс загружается, включая заголовки запроса). `assert` объявлен устаревшим и убирается из рантаймов. При виде `assert` в коде — это признак файла возрастом в пару лет, стоит обновить.

# Зачем это нужно: вопрос безопасности

Импорт не-JS ресурса нельзя было разрешить «просто так» из-за реальной атаки. Сервер отдаёт файл по `.json`, но с MIME-типом `text/javascript` — если бы браузер решал по расширению, он бы выполнил его как скрипт. Расширение в URL ничего не гарантирует.

Атрибут решает это: браузер отправляет запрос с ожиданием конкретного типа и **отказывается** интерпретировать ответ, если MIME не совпал. Отсюда и обязательность атрибута — без него JSON-импорт не разрешён вовсе.

# JSON-модули

```js
import config from './config.json' with { type: 'json' };
console.log(config.apiUrl);
```

Свойства:

- экспортируется **только default** — весь разобранный объект;
- named-импорты запрещены: `import { apiUrl } from './config.json'` — ошибка. Это намеренно: named-экспорты требуют статически известного списка ключей, а JSON парсится в рантайме;
- объект **изменяемый**, но модуль кэширован (см. [[Реестр модулей и singleton-семантика]]) — мутация видна всем импортёрам. Ошибиться легко: `config.apiUrl = x` затронет всё приложение.

## Node.js

Требует атрибут. Без него — ошибка `ERR_IMPORT_ATTRIBUTE_MISSING`.

Отдельно стоит помнить старую альтернативу, которая всё ещё в ходу в CJS:

```js
const config = require('./config.json');   // CJS умеет JSON давно и без атрибутов
```

Разница в поведении между `require('./x.json')` и `import ... with { type: 'json' }` — типовая точка поломки при миграции скриптов на ESM.

## Сборщики

webpack, Vite, Rollup поддерживали импорт JSON **задолго до стандарта**, своими средствами и без атрибутов:

```js
import config from './config.json';           // работает в Vite/webpack
import { apiUrl } from './config.json';       // тоже работает — named из JSON!
```

Отсюда важная практическая ловушка: **код, работающий в сборке, может не работать в Node напрямую**. Скрипт, отлаженный внутри Vite, при запуске через `node script.js` упадёт на отсутствии атрибута или на named-импорте.

Плюс сборщика: named-импорт из JSON поддаётся tree shaking — Vite и Rollup умеют выбросить неиспользуемые ключи. Это заметная экономия на больших словарях локализации. Ценой переносимости.

# CSS-модули (браузерные)

```js
import sheet from './styles.css' with { type: 'css' };
document.adoptedStyleSheets = [sheet];
```

Импортируется объект `CSSStyleSheet`, готовый к `adoptedStyleSheets`. Основное применение — Web Components и Shadow DOM, где нужен разделяемый между экземплярами стиль без дублирования `<style>`.

Не путайте с `import './styles.css'` в сборщике — там это расширение бандлера, которое извлекает CSS в отдельный файл или инжектит `<style>`. Механики разные, синтаксис похож. Именно этот «эффектный» импорт без атрибута — главный враг tree shaking, см. [[sideEffects в package.json]].

Поддержка CSS-модулей в браузерах и Node неравномерна — проверяйте до использования в проде.

# Влияние на сборку

**Сборщик должен понимать атрибут.** Современные версии Vite/Rollup/webpack его разбирают и не ломаются, но старые могут споткнуться на синтаксисе.

**Атрибут может сохраняться в выводе.** При сборке в ESM для Node атрибут остаётся в коде — иначе Node не примет импорт. При сборке в CJS импорт превращается в `require`, и атрибут исчезает.

**Транспиляторы.** TypeScript поддерживает синтаксис, но требует подходящего `module` (`esnext`/`nodenext`) и `resolveJsonModule` для JSON. При `module: commonjs` конструкция не транспилируется корректно.

# Практические рекомендации

- В **приложении**, собираемом Vite/webpack: можно писать `import config from './config.json'` без атрибута — короче и даёт tree shaking. Переносимости всё равно нет.
- В **скриптах и инструментах**, запускаемых Node напрямую: всегда с атрибутом, только default-импорт. Либо `readFileSync` + `JSON.parse`, если нужна свежесть данных без кэширования модуля.
- В **библиотеке**: избегайте JSON-импортов вообще. Они по-разному ведут себя у разных потребителей. Если данные нужны — вкомпилируйте их в `.js` как экспортируемую константу.
- `assert` в коде — заменить на `with`.
