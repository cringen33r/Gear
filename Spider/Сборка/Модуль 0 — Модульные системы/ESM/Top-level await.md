Top-level await (TLA) — возможность использовать `await` на верхнем уровне модуля, вне `async`-функции. Доступно **только в ESM**. Выглядит как мелкое синтаксическое удобство, но меняет семантику загрузки графа и ограничивает форматы вывода сборщика — поэтому заслуживает отдельного разбора.

# Синтаксис

```js
// config.js
const response = await fetch('/api/config');
export const config = await response.json();
```

```js
// app.js
import { config } from './config.js';
console.log(config);   // уже загружен — импортёр дождался
```

Никакой обёртки в `async function` и последующего `.then` — модуль сам стал асинхронным.

# Что происходит на уровне графа

Модуль с TLA становится **асинхронным модулем**. Из [[Фазы загрузки ESM]] меняется третья фаза: выполнение перестаёт быть синхронным обходом.

Правила:

1. Модуль с TLA приостанавливает своё выполнение на каждом `await`.
2. **Все его импортёры ждут** его завершения, прежде чем выполнить свои тела.
3. Асинхронность транзитивна: импортёр асинхронного модуля сам становится асинхронным для своих импортёров.
4. Модули-«соседи», не зависящие от него, выполняются параллельно и не блокируются.

Последний пункт важен: TLA задерживает только ветку графа, а не всё приложение.

# Практическая польза

## Асинхронная инициализация без гонок

Классическая проблема: модуль экспортирует объект, который «когда-нибудь» будет заполнен.

```js
// без TLA — потребитель обязан знать про ready
export let db = null;
export const ready = initDb().then(d => { db = d; });
```

Каждый потребитель обязан помнить про `await ready`. С TLA контракт исчезает:

```js
// с TLA — импортёр просто получает готовое
export const db = await initDb();
```

## Условная загрузка зависимости

```js
const parser = process.env.LEGACY
  ? await import('./parser-legacy.js')
  : await import('./parser.js');

export const parse = parser.parse;
```

## Загрузка ESM из CJS-подобного кода

`await import('./esm-only.js')` на верхнем уровне — способ подтянуть ESM-only пакет.

## Инициализация WASM

```js
const wasm = await WebAssembly.instantiateStreaming(fetch('/module.wasm'));
export const { compute } = wasm.instance.exports;
```

Один из самых естественных сценариев TLA.

# Цена и риски

## Блокировка ветки графа

TLA на старте приложения задерживает всё, что от него зависит. `await fetch(...)` в модуле конфига, импортируемом точкой входа, — это отложенный рендер на время сетевого запроса. Часто именно этого и хотят; но иногда это неявная просадка LCP, о которой никто не помнит, потому что задержка «спрятана» в импорте.

## Дедлок при циклах

Два модуля с TLA, ждущие друг друга, зависают **без ошибки**:

```js
// a.js
import './b.js';
await new Promise(() => {});   // никогда не разрешится

// b.js
import './a.js';
```

Отладка тяжёлая: нет исключения, нет стека — просто ничего не происходит. См. [[Циклические зависимости]].

## Ограничение форматов вывода

Здесь TLA бьёт по сборке напрямую. Форматы `cjs`, `iife`, `umd` **синхронны по своей природе** — в них нет способа выразить «модуль ещё не готов».

Последствия:

- Rollup при `format: 'iife'` с TLA в графе выдаст ошибку;
- сборка библиотеки в CJS с TLA невозможна без изменения контракта;
- esbuild требует `target`, поддерживающий TLA (`es2022`+), иначе ошибка;
- webpack требует включения экспериментального флага (`experiments.topLevelAwait`) в старых версиях; в webpack 5 современных версий поддержка есть, но чанк с TLA обрабатывается особым образом.

**Практическое правило: не используйте TLA в коде библиотеки, которая публикуется в CJS.** В приложении, собираемом в ESM, — можно.

## Поддержка окружения

TLA требует ESM и относительно современного таргета. Если ваш `tsconfig` понижает `target` до `es2017`, конструкция не транспилируется — TLA нельзя выразить в старом синтаксисе без изменения семантики модуля. Компилятор выдаст ошибку, а не «сделает как-нибудь».

# Когда лучше не использовать

| Ситуация | Почему | Альтернатива |
|---|---|---|
| Библиотека с CJS-сборкой | формат не поддерживает | экспортировать промис/функцию инициализации |
| Модуль на критическом пути старта | задержка первого рендера | ленивая инициализация по требованию |
| Есть циклы в графе | риск дедлока | сначала разомкнуть циклы |
| Нужна обработка ошибки загрузки | исключение в TLA валит весь импорт | `try/catch` вокруг `await` внутри модуля |

Про последнее: непойманное исключение в TLA приводит к тому, что модуль навсегда остаётся в состоянии ошибки, и **все импортёры получают это же исключение** (см. [[Реестр модулей и singleton-семантика]] — результат кэшируется, включая отказ). Оборачивайте рискованный `await` в `try/catch` внутри самого модуля.
