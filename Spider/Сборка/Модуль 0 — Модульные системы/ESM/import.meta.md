`import.meta` — объект с метаданными текущего модуля. Синтаксическая конструкция, доступная **только в ESM** (в [[CommonJS]] — синтаксическая ошибка). Заменяет собой `__dirname`/`__filename` и служит точкой расширения для сборщиков.

# Стандартная часть

## `import.meta.url`

Абсолютный URL текущего модуля. В браузере — `https://example.com/src/app.js`, в Node — `file:///home/user/app.js`.

Главное применение — путь к ресурсу **рядом с модулем**:

```js
const workerUrl = new URL('./worker.js', import.meta.url);
const worker = new Worker(workerUrl, { type: 'module' });
```

Конструкция `new URL('./x', import.meta.url)` — **распознаваемый сборщиками паттерн**. Vite, webpack 5 и Rollup видят его, включают файл в сборку как ассет и подставляют финальный путь с хешем. Это стандартный способ сослаться на воркер, wasm-модуль или картинку без плагинов:

```js
const imgUrl = new URL('./logo.png', import.meta.url).href;
```

Важно: паттерн должен быть записан **буквально**. `new URL(path, import.meta.url)` с переменной сборщик не разрешит.

## `import.meta.resolve()`

Резолвит спецификатор по правилам текущего модуля и возвращает URL:

```js
const url = import.meta.resolve('lodash');   // file:///.../node_modules/lodash/lodash.js
```

Полезно, когда нужен путь к пакету, а не сам пакет: чтение файла из зависимости, передача пути инструменту.

## Node-специфичное

```js
import.meta.dirname;    // аналог __dirname (Node 21.2+)
import.meta.filename;   // аналог __filename
```

До их появления писали:

```js
import { fileURLToPath } from 'node:url';
import { dirname } from 'node:path';
const __filename = fileURLToPath(import.meta.url);
const __dirname = dirname(__filename);
```

Этот шаблон до сих пор встречается в конфигах и скриптах — узнавайте его.

# Расширения сборщиков

Спецификация намеренно оставила `import.meta` открытым для хостов. Инструменты этим активно пользуются, и вот здесь начинается практика.

## `import.meta.env` (Vite)

Переменные окружения, подставляемые **на этапе сборки**:

```js
import.meta.env.MODE          // 'development' | 'production'
import.meta.env.PROD          // boolean
import.meta.env.DEV
import.meta.env.BASE_URL
import.meta.env.VITE_API_URL  // ваша переменная из .env
```

Критично понимать: это **не чтение переменной в рантайме**, а текстовая подстановка при сборке. `import.meta.env.VITE_API_URL` буквально заменяется на строку в выходном файле.

Два следствия:

1. **Всё, что попало сюда, попало в бандл и публично.** Префикс `VITE_` — не механизм безопасности, а защита от случайной утечки: без него переменная просто не подставится. Секретов здесь быть не может в принципе.
2. **Смена окружения требует пересборки.** Если нужен один артефакт на все стенды — читайте конфиг в рантайме (`fetch('/config.json')` при старте), а не через `import.meta.env`.

Подстановка `import.meta.env.PROD` в `if` — ещё и инструмент удаления кода: минификатор схлопывает `if (false) {...}` и выбрасывает ветку целиком.

## `import.meta.hot` (Vite) / `import.meta.webpackHot`

API горячей замены модулей:

```js
if (import.meta.hot) {
  import.meta.hot.accept('./dep.js', (newDep) => { /* применить */ });
  import.meta.hot.dispose(() => { /* очистить таймеры, подписки */ });
  import.meta.hot.data;   // состояние, переживающее замену
}
```

Обёртка `if (import.meta.hot)` обязательна: в продакшен-сборке значение — `undefined`, а весь блок вырезается минификатором.

`dispose` — то, что чаще всего забывают: без него при каждом HMR-обновлении накапливаются интервалы и подписки.

## `import.meta.glob` (Vite)

Импорт множества файлов по маске — явная и читаемая альтернатива `import()` с шаблонной строкой:

```js
// ленивые: объект { путь: () => Promise<Module> }
const pages = import.meta.glob('./pages/*.vue');

// нетерпеливые: сразу импортируются
const icons = import.meta.glob('./icons/*.svg', { eager: true });
```

Раскрывается на этапе сборки в список конкретных импортов. Типовое применение: автоматическая регистрация маршрутов, иконок, локалей без ручного перечисления.

# Что важно для практики

**`import.meta` не работает в CJS.** При сборке в формат `cjs` или `iife` сборщик обязан его чем-то заменить (обычно эмулирует через `__filename`). Если пишете код, который может быть собран в оба формата, — это точка риска.

**`import.meta.env` привязывает код к Vite.** Библиотека, использующая его, не соберётся webpack'ом без шимов. Для переносимого кода лучше `process.env` с заменой через `define` или собственный слой конфигурации.

**Проверка на наличие.** Универсальный код пишет `if (import.meta.hot)`, а не обращается напрямую — иначе падение в окружении, где расширения нет.
