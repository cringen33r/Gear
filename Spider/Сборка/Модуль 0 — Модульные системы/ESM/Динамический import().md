`import()` — синтаксическая конструкция, возвращающая промис с namespace-объектом модуля. Единственный стандартный способ загрузить модуль **условно или по требованию**, и одновременно — та точка, по которой сборщик разрезает граф на чанки. Практически весь code splitting стоит на ней.

# Синтаксис и базовое поведение

```js
const module = await import('./heavy.js');
module.doWork();

// или без await
import('./heavy.js').then(m => m.doWork());
```

Что возвращается — **namespace-объект**, тот же, что при `import * as m`. Поэтому default лежит в свойстве `default`:

```js
const { default: Chart, helper } = await import('./chart.js');
```

Забытый `.default` — одна из самых частых ошибок при переходе на ленивую загрузку.

# Чем отличается от статического import

| | `import ... from` | `import()` |
|---|---|---|
| Где можно | только верхний уровень | где угодно |
| Спецификатор | строковый литерал | любое выражение |
| Возвращает | связывания | `Promise<Namespace>` |
| Когда грузится | до выполнения модуля | в момент вызова |
| Для сборщика | ребро графа | **точка разреза графа** |

Это по-прежнему не функция: `import` нельзя присвоить переменной, передать в `map`, вызвать через `call`. Ограничение намеренное — оно оставляет конструкцию распознаваемой для статического анализа (см. [[Статическая структура ESM]]).

# Ключевые свойства

**Кэшируется.** Повторный `import()` того же модуля не грузит его снова — возвращается тот же экземпляр из реестра (см. [[Реестр модулей и singleton-семантика]]). Поэтому не нужно вручную мемоизировать результат.

**Работает в CommonJS.** `import()` доступен и в CJS-файлах — это был единственный способ загрузить ESM из CJS до появления [[require(esm) в Node.js]].

**Отклоняется, а не бросает.** Ошибка загрузки — это rejected promise. Ловится обычным `try/catch` вокруг `await` или `.catch()`.

**Асинхронен даже при попадании в кэш.** Промис разрешается минимум в следующем микротаске.

# Как это видит сборщик

Здесь сосредоточена вся практика.

## Статический литерал — идеальный случай

```js
const m = await import('./features/reports.js');
```

Сборщик создаёт **отдельный чанк** для `reports.js` и всего, что тянется только через него. В точке вызова остаётся код загрузки чанка.

## Шаблонная строка — создаётся набор чанков

```js
const locale = await import(`./locales/${lang}.js`);
```

webpack и Vite анализируют шаблон и создают чанк **для каждого файла**, подходящего под маску `./locales/*.js`. Работает, но легко раздувает вывод: положили в папку 40 локалей — получили 40 чанков в манифесте.

Управление в webpack — «магические комментарии»:

```js
const locale = await import(
  /* webpackChunkName: "locale-[request]" */
  /* webpackInclude: /\.js$/ */
  /* webpackExclude: /\.test\.js$/ */
  `./locales/${lang}.js`
);
```

В Vite аналог — `import.meta.glob` (см. [[import.meta]]), который делает то же самое явно и читаемо.

## Полностью динамический путь — граф обрывается

```js
const path = getPathFromConfig();
const m = await import(path);          // сборщик не знает, что сюда попадёт
```

webpack выдаст `Critical dependency: the request of a dependency is an expression`, Vite не сможет разрешить путь. В бандле такой модуль просто не окажется. Единственные корректные сценарии — загрузка по абсолютному URL с внешнего источника (плагины, микрофронтенды), и тогда путь нужно исключить из анализа (`/* @vite-ignore */`).

**Практическое правило: путь в `import()` должен быть литералом или шаблоном с максимально узкой статической частью.**

# Типовые применения

## Ленивые маршруты

```ts
// Angular
{ path: 'reports', loadComponent: () => import('./reports/reports.component')
    .then(m => m.ReportsComponent) }
```

Основной инструмент сокращения начального бандла: код страницы грузится при первом переходе на неё.

## Тяжёлая зависимость по требованию

```js
async function exportToExcel(rows) {
  const { utils, writeFile } = await import('xlsx');   // ~1 МБ, нужен редко
  // ...
}
```

Одна из самых окупаемых оптимизаций: библиотеки графиков, редакторы, PDF-генераторы, `moment`-подобные пакеты уходят из основного чанка.

## Условная загрузка полифила

```js
if (!('IntersectionObserver' in window)) {
  await import('intersection-observer');
}
```

Современные браузеры не платят за полифил вовсе.

## Разрыв циклической зависимости

`import()` превращает статическое ребро графа в динамическое, что разрывает [[Циклические зависимости|цикл]] ценой асинхронности.

# Предзагрузка: как убрать задержку

Ленивый чанк начинает грузиться только в момент вызова — пользователь ждёт. Лечится подсказками загрузки:

```js
// webpack
import(/* webpackPrefetch: true */ './reports.js');   // загрузить в простое
import(/* webpackPreload: true */ './critical.js');   // загрузить параллельно текущему
```

Или вручную — вызвать `import()` заранее (например, при наведении на ссылку) и проигнорировать результат: модуль осядет в кэше, а второй вызов вернёт его мгновенно.

Механика на уровне HTML — в [[Загрузка скриптов — async, defer, modulepreload]].

# Обработка ошибок

Ленивый чанк — это сетевой запрос, и он может не выполниться. Самый частый продовый сценарий: пользователь держит вкладку открытой, происходит деплой, старые чанки с прежними хешами удалены с CDN → `Failed to fetch dynamically imported module`.

```js
try {
  const m = await import('./reports.js');
} catch (e) {
  // предложить перезагрузку страницы
}
```

Это не экзотика, а обязательный обработчик в приложениях с ленивыми маршрутами. Разбор — в [[Диагностика ошибок модульных систем]].
