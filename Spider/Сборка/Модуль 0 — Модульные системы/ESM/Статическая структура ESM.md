Ключевое свойство ESM, из которого вырастает почти вся современная сборка: **список импортов и экспортов модуля известен до выполнения кода**. Достаточно распарсить файл — выполнять не нужно.

# Что означает «статически»

```js
import { add } from './math.js';
import defaultThing from './other.js';
export const VERSION = '1.0';
```

Распарсив этот файл, инструмент уже знает: модуль зависит от `./math.js` (нужно имя `add`) и `./other.js` (нужен `default`), и предоставляет наружу `VERSION`. Ни одна строка не выполнена.

Сравните с [[CommonJS]]:

```js
const name = process.env.MOD;
const mod = require(`./${name}`);      // что это? неизвестно до рантайма
if (flag) module.exports.extra = 1;    // есть ли экспорт extra? неизвестно
```

Разница не в удобстве синтаксиса, а в **разрешимости**: у ESM граф вычислим, у CJS — нет.

# Правила, которые обеспечивают статичность

Три ограничения языка, каждое существует ради анализируемости:

**1. Только верхний уровень модуля.** `import`/`export` нельзя внутри функции, блока, условия.

**2. Спецификатор — строковый литерал.** Никаких переменных и шаблонных строк.

**3. Импорты неизменяемы.** Импортёр не может переприсвоить связывание, значит, никто не подменит зависимость незаметно для анализатора.

Если нужна динамика — есть отдельная конструкция [[Динамический import()]], которая честно возвращает промис и явно маркирует точку, где граф разрывается.

# Что это даёт на практике

## Tree shaking

Главная выгода. Сборщик знает, что из `./math.js` нужно только `add`, и может удалить `sub`, `mul`, `div` — при условии, что их удаление не меняет наблюдаемое поведение (см. [[Побочные эффекты модулей]]).

```js
// utils.js экспортирует 40 функций
import { formatDate } from './utils.js';
// в бандл попадёт formatDate и то, что ей нужно
```

С CJS так нельзя: `const utils = require('./utils')` даёт объект целиком, и доказать, что `utils.parseDate` никогда не вызовут, невозможно (его могли достать через `utils[key]`).

## Проверка до запуска

Опечатка в имени импорта — ошибка на этапе связывания, а не `undefined is not a function` в проде:

```
SyntaxError: The requested module './math.js' does not provide an export named 'addd'
```

В CJS то же самое даст `undefined`, и упадёт оно в момент вызова, возможно, в редкой ветке.

## Загрузка графа наперёд

Браузер, разобрав модуль, сразу видит все зависимости и запускает их загрузку **параллельно**, не дожидаясь выполнения. Без статичности пришлось бы выполнять код, чтобы узнать следующий запрос — ровно та проблема, из-за которой [[AMD и RequireJS]] парсил исходники регулярками.

## Code splitting и предзагрузка

Сборщик знает весь граф, поэтому может: разделить его на чанки по точкам `import()`, вычислить общие зависимости, сгенерировать `<link rel="modulepreload">` для чанков, нужных на старте (см. [[Загрузка скриптов — async, defer, modulepreload]]).

## HMR

Замена одного модуля без перезагрузки страницы требует точного знания, кто от него зависит и куда распространять инвалидацию. Граф даёт это бесплатно.

## Инструменты разработчика

Автоимпорт, «найти все использования», безопасное переименование, определение мёртвого кода — всё это работает на статическом графе. Динамические `require` для IDE непрозрачны.

# Границы статичности

Статичность легко потерять, и это ежедневная практическая проблема.

**Namespace-импорт.** `import * as utils from './utils.js'` — сборщик видит запрос всего модуля. Хорошие бандлеры разворачивают его при статических обращениях (`utils.foo()`), но при `utils[key]()` анализ обрывается и в бандл попадает всё.

**Ре-экспорты и barrel-файлы.** `export * from './a.js'` требует разрешения всех имён; глубокие цепочки барелей раздувают граф. См. [[Синтаксис импортов и экспортов]].

**CJS-зависимость внутри ESM-графа.** Как только вы импортируете CJS-пакет, статичность заканчивается на его границе: содержимое анализируется эвристикой. См. [[ESM и CommonJS — взаимодействие]].

**Динамический `import()` с переменной.** `import(path)` сборщик разрешить не может. `import(`./locales/${lang}.js`)` — частично может: webpack и Vite создадут чанки для **всех** файлов, подходящих под шаблон. Это работает, но легко раздувает вывод.

**Побочные эффекты.** Статичность даёт знание графа, но не право удалять код. Модуль с эффектом на верхнем уровне останется, даже если из него ничего не импортируют.

# Практический чеклист

- Импортируйте именованно, а не через `* as`, если хотите tree shaking.
- Избегайте глубоких barrel-файлов в библиотеках; давайте subpath-экспорты.
- Динамические импорты пишите с максимально узким шаблоном пути.
- Проверяйте `sideEffects` у своих пакетов — статичность без этого не конвертируется в удаление кода.
