`<script type="module">` — точка входа ESM-графа в браузере. Отличается от классического `<script>` не только форматом содержимого: у него другие правила загрузки, области видимости и безопасности.

# Отличия от классического скрипта

| | `<script>` | `<script type="module">` |
|---|---|---|
| Блокирует парсер | да (без `defer`/`async`) | нет, всегда отложен |
| Порядок выполнения | по порядку в документе | по порядку в документе, после парсинга |
| Область видимости | глобальная | собственная |
| Strict mode | нет | всегда |
| `this` на верхнем уровне | `window` | `undefined` |
| Выполнение при дублировании | каждый раз | один раз на URL |
| CORS для внешних | не требуется | требуется |
| `import`/`export` | нет | да |

# Отложенность по умолчанию

```html
<script type="module" src="/app.js"></script>
<!-- ведёт себя как <script defer src="/app.js"></script> -->
```

Загрузка стартует сразу и идёт параллельно парсингу HTML, но **выполнение** откладывается до завершения парсинга документа. Три следствия:

1. DOM уже построен — `document.querySelector` в модуле работает без `DOMContentLoaded`.
2. `document.write` не работает (документ закрыт).
3. Модуль в `<head>` не блокирует рендер — прятать скрипты в конец `<body>` больше не нужно.

Инлайновые модули тоже отложены — в отличие от инлайновых классических скриптов, которые выполняются немедленно:

```html
<script>console.log('1');</script>
<script type="module">console.log('3');</script>
<script>console.log('2');</script>
<!-- вывод: 1, 2, 3 -->
```

Подробно про порядок — [[Загрузка скриптов — async, defer, modulepreload]].

# Собственная область видимости

```html
<script type="module">
  const secret = 42;       // не попадает в window
  window.exposed = 42;     // так — попадает, явно
</script>
<script>
  console.log(typeof secret);   // 'undefined'
</script>
```

Модули не могут «общаться» через глобали случайно — только через импорты или явную запись в `globalThis`.

Практическое следствие для отладки: переменную из модуля не посмотреть в консоли DevTools напрямую. Приёмы — `debugger`, точка останова, либо временно `globalThis.x = x`.

# Выполнение один раз на URL

```html
<script type="module" src="/app.js"></script>
<script type="module" src="/app.js"></script>
<!-- app.js выполнится ОДИН раз -->
```

Работает [[Реестр модулей и singleton-семантика|реестр модулей]] с ключом по URL. Классические скрипты выполнились бы дважды.

# CORS обязателен

Модули загружаются в режиме CORS **всегда**, включая same-origin. Кросс-доменный модуль без `Access-Control-Allow-Origin` не загрузится:

```html
<script type="module" src="https://cdn.example.com/lib.js"></script>
<!-- нужен заголовок CORS на стороне CDN -->
```

По умолчанию запрос идёт без креденшелов. Изменить:

```html
<script type="module" crossorigin="use-credentials" src="..."></script>
```

Это регулярная причина «на CDN не работает, локально работает» — классический скрипт с того же CDN грузился бы без вопросов.

Дополнительно: локальный файл через `file://` не загрузит модули — origin считается `null`. Нужен любой HTTP-сервер, даже `python -m http.server`.

# MIME-тип обязателен

Сервер должен отдавать модуль с JS-совместимым MIME (`text/javascript`, `application/javascript`). При `text/plain` браузер откажется выполнять. Частая проблема при раздаче статики самописным сервером или при неправильной конфигурации nginx для `.mjs`.

# Обязательные расширения в спецификаторах

```js
import { x } from './utils';       // ❌ 404 — браузер не дописывает .js
import { x } from './utils.js';    // ✅
import { x } from 'lodash';        // ❌ без import maps
```

Браузер не ищет `index.js`, не перебирает расширения — этому нас приучили сборщики. См. [[Спецификаторы модулей]] и [[Import maps]].

# Фолбэк для старых браузеров: `nomodule`

```html
<script type="module" src="/app.modern.js"></script>
<script nomodule src="/app.legacy.js"></script>
```

Браузер с поддержкой модулей игнорирует `nomodule`; без поддержки — игнорирует `type="module"` как неизвестный тип. Так работала «дифференциальная загрузка».

Сегодня это в основном история: поддержка ESM повсеместна с 2018 года. Angular убрал дифференциальную загрузку, Vite предлагает `@vitejs/plugin-legacy` для тех, кому она всё ещё нужна. Знать конструкцию стоит для чтения старых сборок.

# `async` на модуле

```html
<script type="module" async src="/analytics.js"></script>
```

Разрешено и работает: модуль выполнится сразу после загрузки своего графа, **не дожидаясь** парсинга документа и не соблюдая порядок относительно других скриптов. Для аналитики и независимых виджетов — уместно. Для кода приложения — нет.

Отличие от классического скрипта: `async` работает и на **инлайновых** модулях, что для обычных скриптов бессмысленно.

# Модули в Web Workers

```js
const worker = new Worker(new URL('./worker.js', import.meta.url), { type: 'module' });
```

Без `{ type: 'module' }` воркер загружается как классический скрипт и `import` в нём не работает. Конструкция `new URL(..., import.meta.url)` — распознаваемый сборщиками паттерн, см. [[import.meta]].

У воркера **собственный реестр модулей**: синглтон из главного потока туда не попадает.

# Что это значит для дев-сервера

Vite строит свой dev-режим ровно на этих правилах: отдаёт `index.html` с `<script type="module" src="/src/main.ts">`, а дальше браузер сам запрашивает граф. Задача сервера — переписать bare-спецификаторы в пути и оттранспилировать TS на лету. Никакой сборки не происходит — отсюда мгновенный старт.

Обратная сторона — [[Предел нативного ESM в браузере]].
