AMD (Asynchronous Module Definition) — модульный формат, созданный для браузера в те годы, когда [[CommonJS]] уже был у Node, а сборщиков ещё практически не было. Главная идея: модуль объявляет зависимости, а загрузчик подтягивает их **асинхронно**, без блокировки страницы. Эталонная реализация — RequireJS.

Сегодня AMD почти не пишут вручную, но читать его приходится: он лежит в `dist` многих старых библиотек и внутри [[UMD]]-обёрток.

# Синтаксис

```js
// math.js
define(['./utils'], function (utils) {
  return {
    add: function (a, b) { return utils.check(a + b); }
  };
});
```

```js
// app.js — точка входа
require(['./math'], function (math) {
  console.log(math.add(1, 2));
});
```

`define(id?, dependencies?, factory)`:
- **id** — имя модуля. Обычно опускается: загрузчик выводит его из пути. Явный id ставится при склейке нескольких модулей в один файл (`r.js`);
- **dependencies** — массив спецификаторов;
- **factory** — функция, получающая разрешённые зависимости аргументами; её возврат становится экспортом.

Обратите внимание: зависимости объявлены **до** выполнения тела — это статичность, которой нет у CommonJS, и именно она позволила загрузчику работать асинхронно.

# Как это работает в браузере

1. Загрузчик встречает `require(['./math'], cb)`.
2. Создаёт `<script>` для `math.js` и вставляет в документ — загрузка не блокирует парсинг.
3. `math.js` вызывает `define(['./utils'], ...)` — загрузчик рекурсивно грузит `utils.js`.
4. Когда весь граф загружен, фабрики выполняются снизу вверх, результаты передаются в колбэки.

Это ровно то, что позже стандартизировали в [[Фазы загрузки ESM]], только вручную и на колбэках вместо промисов.

# CommonJS-обёртка (simplified wrapper)

AMD допускает форму, имитирующую CommonJS:

```js
define(function (require, exports, module) {
  const utils = require('./utils');
  exports.add = function (a, b) { return utils.check(a + b); };
});
```

Здесь загрузчик **читает исходник функции через `Function.prototype.toString()`, регулярным выражением выдёргивает вызовы `require`** и предзагружает их. Приём работал, но ломался на минифицированном коде и комментариях — наглядная демонстрация, почему статический синтаксис лучше эвристик. Ту же цену платят современные инструменты, разбирая CJS через `cjs-module-lexer` (см. [[ESM и CommonJS — взаимодействие]]).

# Плюсы и минусы

Дал: асинхронную загрузку без блокировки, явный граф зависимостей, работу в браузере без сборки, изоляцию областей видимости.

Стоил: многословности (обёртка вокруг каждого файла), рассинхрона порядка аргументов и массива зависимостей при рефакторинге, водопада запросов на большом графе, отдельного шага оптимизации (`r.js`) для продакшена — то есть всё равно сборки.

# Что осталось сегодня

- **`dist/*.amd.js` в старых библиотеках.** Если такой файл попал в бандл, webpack его поймёт (он поддерживает AMD нативно), Rollup и Vite — нет без плагина.
- **`define.amd` в проверках UMD** — см. [[UMD]].
- **`libraryTarget: 'amd'`** в webpack — формат вывода, изредка нужен для интеграции в старое приложение.
- **Ложные срабатывания.** Библиотека с UMD-обёрткой внутри бандлера может уйти в AMD-ветку, если в окружении оказался `define` с флагом `amd`. Отсюда рекомендация некоторых пакетов `define = undefined` перед подключением.

# Практический вывод

AMD важен как доказательство одного тезиса: **асинхронная загрузка требует статически объявленных зависимостей**. Именно поэтому в ESM `import` — синтаксис, а не функция, и именно поэтому там, где нужна динамика, введён отдельный [[Динамический import()]], возвращающий промис.
