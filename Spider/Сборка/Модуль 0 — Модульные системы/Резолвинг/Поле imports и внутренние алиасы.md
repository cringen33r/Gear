`imports` — зеркало [[Поле exports]] для **внутреннего** использования. Позволяет объявить приватные спецификаторы, видимые только внутри пакета. Стандартная альтернатива алиасам сборщика.

# Синтаксис

```json
{
  "imports": {
    "#config": "./src/config.js",
    "#utils/*": "./src/utils/*.js",
    "#db": {
      "node": "./src/db-postgres.js",
      "default": "./src/db-memory.js"
    }
  }
}
```

```js
import config from '#config';
import { format } from '#utils/format';
import db from '#db';
```

# Правила

**Префикс `#` обязателен.** Он и делает спецификатор однозначно внутренним: `#` не может начинать имя npm-пакета, поэтому конфликт исключён.

**Область действия — только свой пакет.** Потребитель вашей библиотеки не может импортировать `#config` — это не часть публичного API. `imports` описывает внутреннюю кухню, `exports` — витрину.

**Поддерживает условия и шаблоны.** Тот же механизм, что в `exports` — см. [[Условия резолвинга]].

**Можно указывать на внешние пакеты** — в отличие от `exports`:

```json
{ "imports": { "#lodash": "lodash-es" } }
```

# Зачем это нужно: проблема относительных путей

Знакомая картина:

```js
import { formatDate } from '../../../shared/utils/date.js';
```

Хрупко (ломается при перемещении файла), нечитаемо, шумит в diff при рефакторинге.

Классическое лечение — алиасы. И вот здесь ключевое отличие.

# `imports` против алиасов сборщика

```ts
// подход 1: tsconfig paths + конфиг сборщика
{ "paths": { "@app/*": ["src/app/*"] } }
// + resolve.alias в vite.config.ts
// + moduleNameMapper в jest.config.js
// + ещё раз в конфиге Storybook, ESLint-resolver, ...
```

```json
// подход 2: imports в package.json
{ "imports": { "#app/*": "./src/app/*.js" } }
```

| | Алиасы сборщика | `imports` |
|---|---|---|
| Стандарт | нет | да |
| Работает в Node напрямую | нет | да |
| Где настраивается | в каждом инструменте отдельно | в одном месте |
| Понимает TypeScript | через `paths` | через `paths` или автоматически при `nodenext` |
| Условия окружения | вручную | встроены |

Главная боль алиасов — **дублирование конфигурации**. `paths` в tsconfig влияет только на типы; чтобы алиас работал в рантайме, его нужно повторить в сборщике, в тест-раннере, в линтере. Рассинхрон даёт классическое «типы резолвятся, сборка падает» (см. [[Спецификаторы модулей]]).

`imports` объявляется один раз и понимается всеми, кто читает `package.json`.

# Практические сценарии

## Подмена реализации по платформе

```json
{
  "imports": {
    "#storage": {
      "browser": "./src/storage-local.js",
      "node": "./src/storage-fs.js",
      "default": "./src/storage-memory.js"
    }
  }
}
```

```js
import storage from '#storage';   // одинаковый код везде
```

Изоморфный код без ветвлений `if (typeof window !== 'undefined')` — а значит, серверная реализация вообще не попадёт в браузерный бандл.

## Полифил только там, где нужен

```json
{
  "imports": {
    "#fetch": {
      "node": "./src/fetch-polyfill.js",
      "default": "./src/fetch-native.js"
    }
  }
}
```

## Моки в тестах

```json
{
  "imports": {
    "#api": {
      "test": "./src/api.mock.js",
      "default": "./src/api.js"
    }
  }
}
```

Активируется `node --conditions=test`. Подмена происходит **на уровне резолвинга**, без магии тест-раннера — это особенно ценно в ESM, где привычная подмена импортов запрещена (см. [[Live bindings]]).

## Исходники в dev, сборка в prod (монорепа)

```json
{
  "imports": { "#ui": { "source": "../ui/src/index.ts", "default": "../ui/dist/index.js" } }
}
```

# Поддержка

- **Node** — с версии 12.19/14.6, полноценно с 16+;
- **TypeScript** — понимает при `moduleResolution: node16`/`nodenext`/`bundler`;
- **Vite, webpack 5, Rollup (node-resolve), esbuild** — поддерживают;
- **Jest** — требует свежих версий, в старых нужен `moduleNameMapper`.

Практический совет: перед переводом проекта на `imports` проверьте всю цепочку инструментов, включая тест-раннер и Storybook. Один не поддерживающий инструмент сводит выгоду на нет.

# Ограничения

- Не заменяет `paths` полностью: TypeScript при некоторых конфигурациях всё равно требует дублирования;
- Шаблон `*` — подстановка подстроки, не glob;
- В монорепе с workspaces пути относительны **своему** `package.json`, что усложняет ссылки на соседние пакеты (там честнее workspace-зависимости).
