Исторические поля `package.json`, указывающие, какой файл считать входом пакета. Все они постепенно вытесняются полем [[Поле exports]], но живут в тысячах пакетов и их приходится читать ежедневно.

Ключевой факт: **только `main` — стандарт Node. Остальные — соглашения сборщиков**, которые Node игнорирует.

# `main`

```json
{ "main": "./dist/index.cjs" }
```

Единственное поле, которое Node понимает нативно. Указывает точку входа при отсутствии `exports`. Если не задано — Node ищет `index.js` в корне пакета.

Читают все: Node, webpack, Vite, Rollup, TypeScript. Обычно указывает на CJS-сборку.

# `module`

```json
{ "module": "./dist/index.mjs" }
```

**Не стандарт.** Соглашение, придуманное Rollup и подхваченное всеми сборщиками: «здесь ESM-версия того же кода».

Смысл в том, что сборщик предпочтёт `module`, потому что ESM даёт tree shaking (см. [[Статическая структура ESM]]), а Node возьмёт `main` и получит CJS. Один пакет обслуживает обоих.

Проблемы поля:

- **Node его не знает** — при прямом запуске всегда идёт CJS-путь;
- **нет условий** — нельзя различить браузер и сервер;
- **неоднозначность формата** — `.js` в `module` формально должен быть ESM, но `type` пакета может говорить обратное, и разные инструменты трактуют это по-разному;
- **источник [[Dual package hazard]]** — один потребитель через `main`, другой через `module` = два экземпляра.

Правильная замена — условие `import` в `exports`.

# `browser`

Соглашение сборщиков для браузерных замен. Две формы.

**Строка** — альтернативная точка входа:

```json
{ "main": "./dist/index.cjs", "browser": "./dist/browser.js" }
```

**Объект** — карта замен отдельных файлов и модулей:

```json
{
  "browser": {
    "./lib/fs-storage.js": "./lib/local-storage.js",
    "fs": false,
    "crypto": "./lib/crypto-browser.js"
  }
}
```

`false` означает «заменить пустым модулем» — так вырезают серверный код из браузерного бандла.

Объектная форма мощная, но малопонятная инструментам за пределами webpack/browserify. Современная замена — условие `browser` в `exports`, см. [[Условия резолвинга]].

# `types` / `typings`

```json
{ "types": "./dist/index.d.ts" }
```

Поле TypeScript: где лежат декларации. Node и сборщики его игнорируют.

Важный практический момент: при `moduleResolution: node16/nodenext/bundler` TypeScript читает **`exports`** и ищет там условие `types`. Корневое поле `types` остаётся фолбэком для старого `moduleResolution: node10`. Отсюда типовая ситуация: «типы работали, обновили tsconfig — перестали». Правильный пакет описывает типы в обоих местах.

`typesVersions` — механизм отдачи разных деклараций для разных версий TS; встречается в пакетах, поддерживающих широкий диапазон.

# Порядок предпочтения у инструментов

Условный порядок при отсутствии `exports`:

| Инструмент | Порядок |
|---|---|
| Node (CJS) | `main` → `index.js` |
| webpack (браузер) | `browser` → `module` → `main` |
| Vite/Rollup (браузер) | `browser` → `module` → `main` |
| Vite (SSR) | `module` → `main` |
| TypeScript | `types` → вывод из `main` |

Порядок настраивается: `resolve.mainFields` в webpack, `resolve.mainFields` в Vite. Иногда это единственный способ заставить проблемный пакет работать.

# Как читать чужой `package.json`

Практический навык. Пример:

```json
{
  "name": "some-lib",
  "main": "./dist/index.js",
  "module": "./dist/index.esm.js",
  "browser": "./dist/index.umd.js",
  "types": "./dist/index.d.ts",
  "sideEffects": false
}
```

Читается так:
- Node возьмёт `dist/index.js` (CJS);
- сборщик для браузера возьмёт `dist/index.umd.js` — и это **плохо**, потому что [[UMD]] не поддаётся tree shaking, хотя ESM-сборка рядом есть;
- `sideEffects: false` обещает, что удаление неиспользуемого безопасно (см. [[sideEffects в package.json]]).

Вывод: у пакета проблемная конфигурация; в браузерный бандл он попадёт целиком. Обход — `resolve.alias` на `dist/index.esm.js` или настройка `mainFields`.

Именно такой анализ вы делаете, когда разбираетесь, почему библиотека занимает 300 КБ вместо 20.

# Что писать в своём пакете сегодня

Современная раскладка: `exports` как основной механизм плюс легаси-поля для старых инструментов.

```json
{
  "type": "module",
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.js",
      "require": "./dist/index.cjs"
    }
  },
  "main": "./dist/index.cjs",
  "module": "./dist/index.js",
  "types": "./dist/index.d.ts",
  "sideEffects": false
}
```

`exports` перекрывает всё для современных инструментов; `main`/`module`/`types` — фолбэк для старых. Подробности — [[Публикация пакета для ESM и CJS]].
