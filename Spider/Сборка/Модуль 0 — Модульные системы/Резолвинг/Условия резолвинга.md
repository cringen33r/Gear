Условия (conditions) — механизм, позволяющий одному спецификатору разрешаться в разные файлы в зависимости от того, **кто и как** импортирует. Используются в [[Поле exports]] и [[Поле imports и внутренние алиасы]].

# Как работает

Каждое окружение задаёт набор активных условий. Резолвер идёт по ключам объекта **сверху вниз** и берёт первый, который есть в этом наборе.

```json
{
  "exports": {
    ".": {
      "types": "./index.d.ts",
      "browser": "./index.browser.js",
      "import": "./index.mjs",
      "require": "./index.cjs",
      "default": "./index.js"
    }
  }
}
```

- Node + `import 'pkg'` → активны `node`, `import` → берётся `./index.mjs`;
- Node + `require('pkg')` → активны `node`, `require` → `./index.cjs`;
- Vite для браузера → активны `browser`, `import` → `./index.browser.js` (стоит выше);
- TypeScript → `types` → `./index.d.ts`.

**Порядок ключей в объекте — это приоритет.** Единственное место в JSON, где порядок влияет на семантику.

# Стандартные условия

| Условие | Когда активно |
|---|---|
| `import` | загрузка через `import` / `import()` |
| `require` | загрузка через `require()` |
| `node` | рантайм Node.js |
| `browser` | сборка для браузера (сборщики, не Node) |
| `default` | всегда; терминальный фолбэк |
| `types` | резолвинг типов в TypeScript |
| `development` / `production` | режим сборки |
| `module` | ESM-вариант без разделения на import/require (Vite, webpack) |
| `node-addons` | нативные аддоны разрешены |
| `deno`, `bun`, `worker`, `react-native`, `electron` | соответствующие платформы |

`import`/`require` описывают **синтаксис обращения**, `node`/`browser` — **платформу**. Это ортогональные оси, и их можно комбинировать вложенно.

# Вложенные условия

```json
{
  "exports": {
    ".": {
      "types": "./index.d.ts",
      "browser": {
        "import": "./browser.mjs",
        "require": "./browser.cjs"
      },
      "node": {
        "import": "./node.mjs",
        "require": "./node.cjs"
      },
      "default": "./index.mjs"
    }
  }
}
```

Резолвер спускается вглубь по первому совпавшему ключу. Если внутри ветки ничего не подошло — **возвращается наружу** и продолжает перебор на верхнем уровне. Поэтому осмысленный `default` в конце обязателен.

# Два обязательных правила

**1. `types` — первым.** TypeScript активирует условие `types` вместе с остальными. Если `import` стоит выше, TS возьмёт `.mjs` вместо `.d.ts` и типы не найдутся.

**2. `default` — последним.** `default` совпадает всегда; всё после него недостижимо. Инструменты вроде `publint` ловят эту ошибку.

# Development / production

```json
{
  "exports": {
    ".": {
      "development": "./dist/index.dev.js",
      "production": "./dist/index.prod.js",
      "default": "./dist/index.js"
    }
  }
}
```

Так React отдаёт версию с проверками в dev и без них в prod. Условие подставляет сборщик: Vite делает это по `mode`, webpack — по `mode`, Node — только с явным `--conditions=development`.

Не рассчитывайте, что оно активируется само по себе в Node — там его по умолчанию нет.

# Пользовательские условия

Можно объявить любое своё:

```json
{ "exports": { ".": { "my-app": "./special.js", "default": "./index.js" } } }
```

Активация:

```bash
node --conditions=my-app app.js
```

```js
// vite.config.ts
resolve: { conditions: ['my-app', 'browser', 'import', 'default'] }
```

Реальный сценарий: монорепа, где приложения импортируют **исходники** библиотек в dev (быстрый HMR, нет шага сборки) и собранные файлы в prod:

```json
{
  "exports": {
    ".": {
      "source": "./src/index.ts",
      "import": "./dist/index.js"
    }
  }
}
```

Условие `source` — распространённое соглашение в монорепах (Nx, Turborepo его используют).

# Как условия задают инструменты

**Node.** По умолчанию `node`, `import`/`require`, `default`. Добавить — `--conditions`.

**Vite.** `resolve.conditions` для клиента, `ssr.resolve.conditions` для SSR. По умолчанию в клиентской сборке активны `browser`, `module`, `import`; в SSR — `node`, `import`.

**webpack.** `resolve.conditionNames`, значение по умолчанию зависит от `target`. Для `target: 'web'` включает `browser`.

**Rollup.** `@rollup/plugin-node-resolve` с опциями `exportConditions` и `browser`.

**TypeScript.** Условия зависят от `moduleResolution`: при `bundler` активны `types`, `import`; при `node16`/`nodenext` — в соответствии с тем, ESM или CJS текущий файл; при `node10` `exports` не читается вовсе. Дополнительно `customConditions` в tsconfig.

# Диагностика

Симптом: **в браузерном бандле оказался серверный код**. Скорее всего, сборщик не активировал `browser` (проверьте `target`/`platform`), либо `node` стоит в `exports` выше `browser`.

Симптом: **`ERR_REQUIRE_ESM`**. Условие `require` указывает на ESM-файл. См. [[Поле type и расширения mjs cjs]].

Симптом: **типы не находятся у одного пакета**. Условие `types` не первое, или его нет в нужной ветке. Проверка — `npx @arethetypeswrong/cli`.

Симптом: **одна библиотека попала в бандл дважды**. Разные части приложения резолвятся по разным условиям (`import` и `require`) в разные файлы — [[Dual package hazard]].

Общий приём отладки: временно поставьте в подозрительную ветку заведомо несуществующий путь. Если ошибка появилась — ветка выбирается; если нет — резолвер идёт другим путём.
