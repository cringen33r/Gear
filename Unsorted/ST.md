# Качество ролеплея в SillyTavern: полная настройка

## 0. Рамка
Этот скилл — про то, что в ST влияет на РОЛЕПЛЕЙ: связность, целостность персонажа, память, прозу, темп, инициативу, агентность пользователя.
- Базовая установка и отладка ошибок — скилл sillytavern-setup.
- Карточка персонажа — roleplay-character-card; личность — realism-interview / realism-critique; канон — story-bible.
- Настройки не должны служить обходу политик провайдера модели; джейлбрейки этот скилл не покрывает.
- Имена полей, ключи config.yaml, синтаксис макросов и STscript меняются между версиями. Перед точной инструкцией — уточнить версию и свериться с docs.sillytavern.app (индекс: docs.sillytavern.app/llms.txt) или `/? macros` у пользователя.

## 1. Метод работы
1. Собрать контекст: модель, бэкенд, Chat/Text Completion, окно контекста, язык РП, жанр, формат (один персонаж / группа / рассказчик-GM), желаемая длина ответа, бюджет.
2. Назвать слой, в котором живёт проблема (модель → сэмплеры → структура промпта → содержание промпта → карточка → память/лор → постобработка).
3. Сначала посмотреть Prompt Itemization у проблемного сообщения: что реально ушло, сколько токенов, где пунктир границы контекста.
4. Менять ОДНУ переменную за раз и проверять на одном тестовом чате (раздел 15).
5. Решение выдавать как: что поменять, где в интерфейсе, на что повлияет, чем рискуем, как проверить. Тексты промптов — готовыми блоками.

## 2. Инфраструктура
### Бэкенд
| Вариант | Плюсы для РП | Минусы |
| --- | --- | --- |
| Облачные флагманы (Claude, GPT, Gemini, DeepSeek) | Лучшее понимание подтекста, длинный контекст, русский язык | Цена, политики контента, мало сэмплеров |
| Агрегаторы (OpenRouter и др.) | Много моделей через один ключ | Поведение зависит от провайдера-исполнителя; фиксировать провайдера |
| Локальные (KoboldCpp, llama.cpp, TabbyAPI, ooba) | Полный набор сэмплеров, RP-файнтюны, приватность | Железо, слабее логика и русский, короткий эффективный контекст |

### Локальный запуск: что влияет на РП
- Квантизация: ниже ~Q4 заметно страдают связность и следование карточке. Большая модель в Q4 обычно лучше маленькой в Q8.
- Контекст: выставлять в ST не больше того, что реально загружено в бэкенде; реально полезный контекст часто короче заявленного. Квантование KV-кэша экономит память, но может ухудшить память о далёких событиях.
- Context shift / переиспользование кэша префикса в бэкенде ускоряет длинные чаты — но ломается, если верх промпта меняется каждый ход (см. раздел 3, «стабильный префикс»).
- Скорость генерации ниже ~5 ток/с убивает поток РП сильнее, чем небольшая потеря качества.

### Сервер и данные
- Доступ с телефона — через локальную сеть с whitelist или VPN/туннель; не выставлять ST напрямую в интернет (документация прямо предупреждает). Для нескольких людей — multi-user mode с паролями.
- Папку data/<user>/ держать под git или регулярным бэкапом: пресеты, лорбуки и карточки — это рабочий код, у него должна быть история.
- Connection Profiles: отдельный профиль на каждую связку «модель + пресет + шаблоны + системный промпт». Используются и расширениями (трекеры, память) для фоновых запросов — фоновую работу можно отдавать дешёвой модели.
- Сторонние расширения имеют полный доступ к браузерному контексту ST, включая ключи. Ставить только из проверенных источников.

## 3. Архитектура промпта
Модель лучше использует начало и конец контекста, чем середину, и слабеет к системному промпту за несколько ходов. Поэтому раскладка по слоям:

| Слой | Где | Что | Влияние |
| --- | --- | --- | --- |
| Конституция | Main Prompt (верх) | Роль, жанр, лицо, формат, агентность {{user}}, принципы прозы | Фоновое, долгое |
| Мир и персонаж | WI before → карточка → Scenario → WI after → Persona | Постоянный канон | Среднее, слабеет с длиной чата |
| Образцы | Chat Examples | Голос | Сильное, риск копирования; вытесняются первыми |
| История | Chat History | Сама сцена | Наиболее сильное — модель подражает последним своим ответам |
| Якоря | Character's Note / Author's Note / WI @Depth, глубина 2–6 | Ядро персонажа, текущая цель, трекеры | Сильное |
| Финальные инструкции | Post-History Instructions (depth 0) | 1–3 строки: длина, формат, главное правило | Максимальное — и максимальный риск искажения прозы |

Правила:
- Чем ближе к концу, тем короче. Длинные списки правил на depth 0 делают прозу канцелярской и вызывают «отчёт о соблюдении правил».
- Одно правило — в одном месте. Противоречия между Main Prompt, карточкой, заметками и PHI модель пытается выполнить одновременно.
- Позитивные формулировки + причина правила. Не «не будь многословен», а «1–3 абзаца: короткие ответы оставляют {{user}} пространство для действия».
- XML-теги для разделов (особенно Claude): <rules>, <character>, \<world\>, \<memory\>. Образцы диалогов — в теге с пометкой «образцы стиля, не события».
- Роль инъекций: system — нейтрально; user — воспринимается как просьба и может вызвать ответ на неё; assistant — как слова персонажа. Для якорей обычно system.
- Стабильный префикс: всё, что меняется часто ({{random}}, {{time}}, трекеры, динамические записи лора), ставить НИЖЕ истории чата на глубину. Это сохраняет кэш промпта (Claude: config.yaml → claude.enableSystemPromptCache, claude.cachingAtDepth, claude.extendedTTL) и кэш префикса локального бэкенда.
- Характерные переопределения: карточка может заменить Main Prompt и PHI (настройки Prefer Char. Prompt / Prefer Char. Instructions); {{original}} вставляет глобальную версию. Использовать для персонажей с нестандартным форматом (рассказчик, чат-переписка, дневник).

## 4. Main Prompt для РП
Ключевые рычаги, которые стоит прописать явно:
- **Режим**: автор играет одного персонажа / рассказчик ведёт мир и всех NPC / GM с механиками.
- **Агентность {{user}}**: действия, слова, мысли и чувства {{user}} пишет только пользователь; ответ заканчивается в точке, где есть что сделать.
- **Инициатива**: персонажи преследуют свои цели, мир движется сам, пользователь не единственный двигатель сюжета.
- **Независимость персонажей**: могут отказать, спорить, ошибаться, долго обижаться; отношения меняются постепенно и по причинам (против угодливости).
- **Правда мира**: последствия реальны, неудача возможна, NPC знают только то, что видели или слышали.
- **Проза**: конкретные сенсорные детали, подтекст вместо названных чувств, разное начало и конец абзацев, без итоговых резюме и морали.
- **Формат**: лицо и время, разметка речи/действий/мыслей, ориентир длины, язык ответа.
- **Темп**: сколько времени проходит за ответ, когда делать склейки (slow-burn vs приключение).
- **OOC**: сообщения в ((…)) или [OOC: …] — инструкции автору, не события мира.

Длина Main Prompt — обычно 200–600 токенов. Больше — сигнал, что часть правил не работает и их просто накопили.

## 5. Якоря против дрейфа
- **Character's Note** (в карточке, @Depth + Role) — стоит на постоянной глубине вне зависимости от длины чата. 3–6 строк: ядро, голос, текущая цель. Глубина ~4.
- **Author's Note** — на чат: состояние сцены (кто где, что известно, время суток, раны), текущий тон. Частота: 1 — каждый ход; 0 — отключён (тогда WI в позиции A/N тоже не работает). Default Author's Note — шаблон для новых чатов.
- Раскладка по глубине: статичное (ядро) — глубже (4–6); динамичное (трекеры состояния) — ближе (1–3); формат ответа — 0.
- Если персонаж всё равно дрейфует — проблема часто в истории: модель подражает своим последним ответам. Править или свайпать неудачные ответы сразу, не оставлять их в истории.

## 6. Сэмплеры
Облачные API обычно принимают только Temperature / Top P / Top K / штрафы; серьёзная работа со сэмплерами — на локальных бэкендах. Что принимает конкретный API — проверять.

| Параметр | Что делает | Эффект для РП | Ориентир |
| --- | --- | --- | --- |
| Temperature | Сглаживает/обостряет распределение | Выше — живее и неожиданнее, но теряет логику и факты | Облако 0.7–1.0; локально с Min-P 0.8–1.3 |
| Min-P | Отсекает токены ниже доли от лучшего | Держит связность при высокой температуре; слишком высоко — повторы | 0.02–0.1 |
| Top-nSigma | Оставляет токены в n ст. отклонений от максимума | Стабилен при любой температуре; альтернатива Min-P | ≈1.0–1.5 |
| Top-P / Top-K | Классическое усечение | Грубее Min-P; в связке с Min-P обычно выключают | 1 / 0, если есть Min-P; иначе по рекомендации модели |
| DRY | Штрафует продолжение уже встречавшихся последовательностей | Лучшее средство против лупов и копирования своих фраз | multiplier ≈0.8, base ≈1.75, allowed length 2; имена и форматные символы — в sequence breakers |
| XTC | Иногда убирает самые вероятные токены | Против штампов и предсказуемости; может разболтать смысл и формат | threshold 0.1, probability 0.3–0.5; включать точечно |
| Repetition Penalty | Штрафует повтор отдельных токенов | Грубо: бьёт по именам, местоимениям, формату; ломает словоизменение в русском | 1.0–1.05 при включённом DRY |
| Frequency/Presence | Аналоги для облачных API | Малые значения — меньше повторов; большие — странная лексика | 0–0.3 |
| Dynamic Temperature | Температура зависит от уверенности | Творчество там, где модель сама не уверена | Диапазон напр. 0.75–1.25 |
| Smoothing Factor | Квадратичное сглаживание | Альтернатива температуре; не смешивать с усечением | Только осознанно |
| Mirostat | Держит перплексию | Устаревший подход, конфликтует с другими | Выключен |

Правила:
- Старт: Neutralize Samplers → рекомендации автора модели → точечные правки. Не включать всё сразу.
- Порядок сэмплеров важен: усечение (Min-P) обычно до температуры, если нужна высокая температура без бреда.
- Повторы → сначала DRY и чистка истории, потом температура, и только потом rep. penalty.
- Бред, потеря фактов → температура вниз / Min-P вверх / выключить XTC.
- Banned tokens / logit bias (локально, {{banned::слово}} для Text Completion) — точечно против навязчивых слов; бан части слова может повредить другие слова.

## 7. Длина и форма ответа
- Max Response Length — потолок, а не цель; фактическую длину задают первое сообщение, последние ответы в истории и инструкция длины. Ориентиры: разговор ~150 токенов, ролеплей ~250–400, повествование до ~600. С reasoning — плюс бюджет на размышления.
- Trim Incomplete Sentences — обрезает оборванные фразы; Auto-Continue — догенерирует слишком короткие.
- Stop strings (Text Completion) — против годмоддинга: остановка на «\n{{user}}:»; «Names as Stop Strings» делает это автоматически.
- Character Names Behavior (Chat Completion) / Include Names (Text) — если модель путает, чьи реплики, или пишет за других в группе.
- Prefill (Start Reply With) — начало ответа от лица персонажа (напр. «*» или имя). Убирает мета-вступления и задаёт формат. С режимом размышлений и некоторыми API несовместим — проверять.
- Impersonate (написать за {{user}}) — свой промпт с триггером Impersonate, описывающий голос персоны.
- Continue Nudge / Continue Prefill — качество «продолжить» в Chat Completion.
- Swipes — основной инструмент качества: выбирать лучший ответ и править мелочи дешевле, чем исправлять накопленный дрейф.

## 8. Reasoning (размышления)
- Плюсы для РП: лучше логика сцены, соблюдение лора, асимметрия знания. Минусы: задержка, стоимость, иногда более «рассудочная» проза.
- Request model reasoning + Reasoning Effort (AI Response Configuration). Для Claude Effort переводится в бюджет от Max Response; на новых моделях есть adaptive thinking (config.yaml: claude.enableAdaptiveThinking). При пустых/обрезанных ответах — поднять Max Response (обычно 1024–4096 для reasoning-моделей).
- Локальные reasoning-модели: Advanced Formatting → Reasoning → Auto-Parse с правильными Prefix/Suffix (напр. <think>...</think>).
- Add to Prompts — обычно выключено (провайдеры не рекомендуют возвращать CoT); если включать — Max Additions 1.
- Направленное мышление: в Main Prompt или PHI дать структуру плана (что знает персонаж, чего хочет, что сделает, какой ответ оставит ход {{user}}). У моделей без reasoning аналог — скрытый блок плана/мыслей, вырезаемый regex из отображения.
- Regex может править reasoning-блоки (область «Reasoning»).

## 9. Text Completion: шаблоны
- Instruct Template должен совпадать с обучением модели (см. страницу модели/файнтюна; файнтюн может отличаться от базы). Context Template — одноимённый с Instruct.
- Story String — шаблон верхней части промпта с макросами {{description}}, {{personality}}, {{scenario}}, {{persona}}, {{wiBefore}}/{{wiAfter}}; можно добавить XML-обёртки и условия {{if}}.
- Полезное: варианты префиксов для первого/последнего сообщения (Last Assistant Prefix — место для короткой инструкции перед ответом), System Sequence, Example Separator / Chat Start.
- После смены шаблона/пресета проверять в НОВОМ чате: старая история тянет прежний стиль.

## 10. Персонажи, персона, группы
- Persona: кратко и только видимое/известное персонажу; секреты {{user}} в персоне модель «знает» за персонажа. Позиция персоны настраивается (вкл. глубину).
- Альтернативные приветствия — разные сцены и тона; первое сообщение сильнее всего задаёт стиль и длину.
- Группы: стратегия очереди (Natural с Talkativeness, List, Manual — для авторского контроля), Swap vs Join card fields (Join — все карточки всегда в контексте, дороже, но стабильнее для кэша), Group Nudge. Альтернатива группе — одна карточка-рассказчик + NPC в лорбуке: дешевле и связнее.

## 11. World Info: продвинуто
- Активация: ключи (в т.ч. regex), Selective + вторичные ключи с логикой AND/NOT, Constant, Vectorized. Области сканирования можно расширить на описание персонажа/персоны/сценарий (пер-запись).
- Scan Depth: 2–4 — актуальность; больше — записи «залипают». Пер-запись можно переопределить.
- Позиция — инструмент влияния: фоновый лор — before/after char; то, что должно сработать в этом ответе (ситуация, NPC в сцене) — @Depth 1–3.
- Timed effects: Sticky (держать N сообщений после срабатывания — NPC не «исчезает», когда его перестали называть), Cooldown (пауза между срабатываниями), Delay (не раньше N сообщения — отложенные сюжетные события). Наличие и названия проверять по версии.
- Probability — случайные события/детали мира. Inclusion Groups (+Group Weight, Prioritize, Group Scoring) — выбор одной из альтернатив (погода, настроение NPC, стадии отношений).
- Recursion — цепочки (город → фракция → лидер); Prevent/Exclude/Delay until recursion защищают от лавины. Записи из рекурсии стоят в очереди после прямых.
- Budget: при переполнении записи молча не вставляются (сначала constant, потом по Order). Важным — высокий Order.
- Outlets ({{outlet::key}}) — вставить контент записей в произвольное место промпта (внутрь своего XML-блока).
- Лорбук как механика: записи-правила для жанровых сцен (бой, допрос, торг), срабатывающие по ключевым словам ситуации.
- Русский: regex-ключи по основе (/матери|мать|мам[ауыеой]/i) или списки форм; с Match Whole Words аккуратно.

## 12. Память длинной истории
- Иерархия: карточка (неизменное) → лорбук чата (события, изменения отношений — по ключам) → сводка (хронология) → Author's Note (текущее состояние) → история.
- Summarize: частота, промпт суммаризации (требовать факты, решения, кто что знает, изменения отношений — без оценок), позиция вставки, привязка к отдельному Connection Profile. Сводку проверять и править: ошибка в сводке становится каноном. {{summary}} — вставка в любое место.
- Chat Vectorization / Data Bank — поднимает похожие старые сообщения/документы; документация сама предупреждает, что улучшение не гарантировано. Для канона надёжнее лорбук.
- Сообщество использует расширения памяти, которые превращают сцены в записи лорбука (напр. Memory Books, Qvink Memory). Перед рекомендацией — проверить актуальность и совместимость с версией.
- Гигиена: чекпоинты и ветки перед рискованными поворотами; чат в сотни сообщений лучше «перезапустить»: новый чат со сводкой и обновлённым лорбуком, первое сообщение — из текущей сцены.

## 13. Макросы и переменные
(новый движок макросов: вложение, {{if}}/{{else}}, сокращения переменных; включается в User Settings, если установка старая. Полный список — `/? macros`.)
- {{pick::a::b::c}} — стабильный случайный выбор (не меняется каждый ход): вариативность без поломки кэша. {{random}} — каждый раз заново, ставить только ниже истории.
- {{roll::1d20}} — кубики для GM-режима (результат через инъекцию на depth 0, модель описывает исход честно).
- Переменные чата ({{.var}}, {{.var = x}}, {{.hp -= 5}}, {{.count++}}) и глобальные ({{$var}}) — состояние мира: время суток, доверие, раны, деньги, стадия сюжета.
- {{if}} — условные блоки в промпте: правила боя только при .combat, другой тон при высоком .trust. Пример:
  {{if {{.trust >= 7}} }}Она больше не проверяет каждое слово {{user}}.{{else}}Она насторожена и перепроверяет слова {{user}}.{{/if}}
- {{idleDuration}} — персонаж замечает паузу (для companion-формата); {{time}}/{{weekday}} — реальное время; {{// комментарий}} — заметки автора в промптах без отправки модели.
- Кто обновляет переменные: пользователь (Quick Replies), скрипт по событию или фоновая генерация (раздел 14). Не доверять модели самой считать числа в тексте.

## 14. STscript и Quick Replies
- Кнопки режиссёра: «промотать время», «ввести осложнение», «смена сцены», «сводка сцены», «OOC-вопрос» — через временную инъекцию (/inject с глубиной и сроком) и генерацию.
- Фоновые задачи (/gen в режиме quiet) — обновить трекер состояния и записать в переменную (/setvar), не показывая в чате. Промпты с триггером Quiet управляют тем, что идёт в такие запросы.
- Автозапуск Quick Reply по событиям (после ответа ИИ, при открытии чата) — для автоматических трекеров; учитывать стоимость дополнительных вызовов.
- Синтаксис команд — строго по актуальной справке STscript (`/help slash`); скрипты давать с пометкой «проверить на вашей версии».

## 15. Regex
- Области: ввод пользователя / вывод ИИ / reasoning / slash-команды / WI. Эфемерность: менять навсегда / только отображение / только исходящий промпт. Min/Max depth — к каким сообщениям применять.
- РП-применения: скрыть служебные блоки (трекеры, план) из отображения; вырезать старые трекеры из промпта (оставляя последний — через min depth); чистка разметки и оборванных фраз; замена хронических штампов.
- Штампы лучше лечить у источника (промпт, сэмплеры, чистая история); regex-замена компенсирует симптом, и модель часто находит следующий штамп.
- Regex можно привязать к пресету или карточке (scoped) — чтобы правила одного персонажа не ломали других.

## 16. Расширения, влияющие на РП
- Встроенные: Summarize, Chat Vectorization, Data Bank, Regex, Quick Replies, Chat Translation, Objective (цель с подзадачами — для направленных сюжетов), Character Expressions / TTS / Image Generation (иммерсия).
- Трекеры состояния из сообщества (сцена, персонажи в сцене, время, инвентарь; данные на каждый свайп) — сильно улучшают непротиворечивость в длинных сценах, но добавляют запросы и токены. Рекомендовать конкретное расширение — только после проверки актуальности репозитория.
- Правило: каждое расширение, что пишет в промпт, становится ещё одним слоем (раздел 3): проверить его позицию, глубину и конфликты с другими через itemization.

## 17. Русскоязычный РП
- Русский текст обычно дороже по токенам, чем английский: меньше истории влезает в окно. Смотреть счётчик токенов с правильным токенизатором.
- Инструкции можно держать на английском, а язык ответа задавать явно; но карточку и первое сообщение — на языке РП, иначе проза звучит как перевод. Имена персонажей — в одной письменности везде.
- Для слабых в русском локальных моделей — вариант Chat Translation (РП идёт на английском, пользователь видит русский); качество зависит от переводчика.
- Rep. penalty и бан токенов болезненнее для словоизменения — предпочитать DRY.
- Ключи лорбука — с учётом падежей (раздел 11).

## 18. Claude: особенности
- Use system prompt — системные сообщения до первой реплики уходят в system. Prompt Post-Processing — если нужно чередование ролей.
- XML-структура и объяснение причин правил работают лучше капса и запретов. Claude чувствителен к примерам — они должны точно соответствовать желаемому формату.
- Дрейф в «ассистента» (итоги, варианты, вопросы пользователю) — лечится якорем на глубине и префиллом, а не длинными списками запретов.
- Кэширование (раздел 3) — главный рычаг цены длинных чатов; проверять попадания в кэш по логам сервера/счёту.
- Reasoning — раздел 8. Политики контента Anthropic не обходим.

## 20. Тестирование настроек
- Один эталонный чат (ветка/чекпоинт) на 15–30 сообщений со стресс-моментами: давление на согласие, смена регистра, вопрос за границей знания, пассивный пользователь, старый факт, который надо вспомнить.
- A/B: сравнивать 3–5 свайпов на одной точке, а не один ответ; локально можно фиксировать seed. Менять один параметр.
- Критерии: голос узнаваем без имени; факты сцены соблюдены; нет текста за {{user}}; есть инициатива; нет повторов структуры; длина в диапазоне; стоимость/скорость приемлемы.
- Изменения фиксировать: имя пресета с версией, комментарии {{// }} в промптах, git папки data.
