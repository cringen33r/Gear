## День 3 — Векторы, плоскости, определители (K, L, O)

Все три задачи используют один и тот же инструментарий — линейную алгебру. Выучив один раз, закрываешь все три.

### Векторы и плоскости (K, L)

- [ ] Уравнение плоскости $Ax + By + Cz + D = 0$ → вектор нормали $(A, B, C)$
- [ ] Длина вектора: $|\vec{v}| = \sqrt{A^2+B^2+C^2}$
- [ ] Нормировка вектора до заданной длины $L$: $$\vec{v}_{new} = L \cdot \frac{(A,B,C)}{|(A,B,C)|}$$
- [ ] Разобрать задачу K:
    - Плоскость: $2x+y+2z+24=0$ → нормаль $(2,1,2)$, длина $\sqrt{4+1+4}=3$
    - Масштабировать до длины 6: умножить на $6/3=2$ → $(4,2,4)$
    - Ответ: $|4|+|2|+|4|=10.000$
- [ ] Формула расстояния от точки до плоскости: $$d = \frac{|Ax_0+By_0+Cz_0+D|}{\sqrt{A^2+B^2+C^2}}$$
- [ ] Разобрать задачу L: точка на высоте 500 м, координаты x=0, y=0 → подставить в формулу расстояния и найти z (**важно:** не просто подставить в уравнение плоскости, а использовать формулу расстояния, так как "высота" — это перпендикулярное расстояние до плоскости, а не буквальная подстановка)

### Системы линейных уравнений (O)

- [ ] Система имеет более одного решения ⟺ определитель матрицы коэффициентов = 0
    
- [ ] Вычисление определителя 3×3 разложением по строке/правилом Саррюса
    
- [ ] Разобрать задачу O: $$\begin{vmatrix} 3 & -2 & 1 \ a & -14 & 15 \ 1 & 2 & -3 \end{vmatrix} = 0$$
    
    - Раскрыть определитель, получить линейное уравнение относительно $a$, решить
- [ ] Дополнительно: ранг матрицы, когда система несовместна (нет решений) vs имеет единственное решение vs бесконечно много — три случая, не только "det=0"
    
- [ ] Угол между плоскостями / между вектором и плоскостью через скалярное произведение (может встретиться вариация K)
    

**Практика:** реши 3-4 системы 3×3 с разными числами (не только систему из задачи O) на подбор параметра, посчитай 3-4 нормали и расстояния от точки до плоскости с другими уравнениями.

**Чек в конце дня:** решить самостоятельно составленные аналоги K, L, O (поменяй числа в уравнениях) — если получается быстро без ошибок, метод усвоен, а не просто ответ пробника запомнен.

## День 4 — Комбинаторика, вероятность, графы (I, J, M, N)

### Вероятность (M)

- [ ] Классическая вероятность = благоприятные / все исходы
- [ ] Для 3 монет — 8 равновероятных исходов ($2^3$), перечислить все вручную (ООО, ООР, ОРО, РОО, ОРР, РОР, РРО, РРР)
- [ ] Посчитать, в скольких из них есть хотя бы 1 орёл И хотя бы 1 решка

### Комбинаторика (N)

- [ ] Формула сочетаний: $C_n^k = \dfrac{n!}{k!(n-k)!}$
- [ ] Метод "дополнения": все команды минус команды без математиков минус команды без программистов плюс пересечение (или прямой перебор случаев 1+3, 2+2, 3+1)
- [ ] Разобрать задачу N: 8 программистов, 7 математиков, команда из 4, нужен хотя бы 1 из каждой группы
    - Всего команд: $C_{15}^4$
    - Минус команды без математиков (только программисты): $C_8^4$
    - Минус команды без программистов (только математики): $C_7^4$
    - Ответ: $C_{15}^4 - C_8^4 - C_7^4$

### Графы (I, J)

- [ ] Сумма степеней всех вершин графа = $2 \times$ (число рёбер) — лемма о рукопожатиях
    
- [ ] Задача I: рукопожатия = рёбра графа. Дано: 2024 рёбер, степень каждой вершины от 1 до 4. Минимизировать число вершин → максимизировать среднюю степень (использовать степень 4 у всех вершин, где возможно)
    
    - Сумма степеней = $2 \times 2024 = 4048$
    - Минимум вершин при максимальной степени 4: $\lceil 4048/4 \rceil$
- [ ] Компоненты связности графа — определение
    
- [ ] Задача J: минимальная степень вершины ≥ 3 → минимальный размер одной компоненты связности (граф, где у каждой вершины степень ≥3, не может быть компонентой из менее чем 4 вершин) → максимальное число комнат = число компонент = $\lfloor 1919 / \text{мин.размер компоненты} \rfloor$
    
- [ ] Дополнительно: условная вероятность, схема Бернулли (вероятность ровно k успехов из n испытаний) — вариация задачи M
    
- [ ] Дополнительно: включение-исключение для 3+ групп — вариация задачи N
    

**Практика:** реши 2-3 вариации задач на сумму степеней и 2-3 на сочетания с ограничениями, меняя числа и условия (другое число программистов/математиков, другой размер команды).

**Чек в конце дня:** решить самостоятельно изменённые версии I, J, M, N (другие числа, другие ограничения), а не только вариант из пробника.

## День 5 — Алгоритмы (A, B)

Самые трудозатратные задачи — тут легко потерять время на реализацию, а не на понимание идеи. **На реальном экзамене может быть не insertion sort и не сортировка пар** — важно понимать сами алгоритмы сортировки/поиска в целом, а не только конкретные A и B.

### Дополнительно (шире, чем в пробнике)

- [ ] Знать хотя бы поверхностно: bubble sort, selection sort, merge sort, quick sort — как работают, сколько операций делают в худшем/среднем случае
- [ ] Уметь писать компаратор на 2-3 ключа для любого языка, который используешь на экзамене (не только для пар чисел, но и для структур/объектов)
- [ ] Уметь считать количество операций (сравнений, перестановок) вручную для разных алгоритмов, не только insertion sort

### Задача A — сортировка по составному ключу

- [ ] Идея: создать массив структур/кортежей `(a, b, index)`, а не сортировать индексы отдельно от значений
- [ ] Компаратор: сначала сравнить `a`, при равенстве — `b`, при равенстве обоих — `index`
- [ ] На псевдокоде/языке по выбору:
    
    ```
    pairs = [(a[i], b[i], i+1) for i in range(n)]sort pairs by (a, b, index)print index for each pair in pairs
    ```
    
- [ ] Проверить на примере из условия (9 пар) — сверить результат с ожидаемым выводом

### Задача B — insertion sort с подсчётом сравнений

- [ ] Реализовать сортировку вставками **вручную**, не библиотечной функцией
- [ ] Ключевой момент: посчитать **каждое сравнение** внутри внутреннего цикла (не путать со сравнениями, которые "могли бы быть", а считать реально выполненные операции сравнения)
- [ ] Аккуратно с условием выхода из цикла вставки: либо дошли до начала массива, либо нашли элемент, который не больше вставляемого — в обоих случаях последнее "неудачное" сравнение тоже нужно засчитать (или не нужно — сверить по примеру)
- [ ] Прогнать вручную пример 1 из условия: `[2, 2, 1, 1, 2]` → 7 сравнений, сверить свою реализацию по шагам, которые расписаны в примечании к задаче
- [ ] Написать код, протестировать на обоих примерах (5 элементов → 7, 1 элемент → 0)

**Практика:** это единственный день, где стоит реально писать и запускать код (не только на бумаге) — тут баги в деталях реализации решают исход задачи. Помимо A и B, попробуй реализовать 1-2 другие сортировки (например, bubble sort с подсчётом операций) — это подготовит к вариации задачи B на экзамене.
